# Phase 08 Plan 07: A Manager can read a deleted order Summary

*Created: 2026-10-29T20:45:00-05:00 · Updated: 2026-10-29T20:45:00-05:00*

**`GET /api/v1/orders/deleted/{id}` lets a Manager read a soft-deleted order with every child row, totals, deletedAt and deletedBy; Admin gets 403, anonymous 401, and a live, unknown or restored id gets 404. The reader lifts the soft-delete filter on the order and on each child query, and the snapshot and web types are regenerated.**

## Performance

- **Duration:** about 60 min (one connection error mid-run; resumed from the working tree)
- **Completed:** 2026-10-29
- **Tasks:** 2 (3 commits)
- **Files modified:** 14 (3 created, 11 modified)

## Accomplishments

- `OrderReader.GetDeletedDetailAsync` reuses the live detail read in a "deleted" mode. The order query and the six child queries (items, discounts, payments, refunds, expenses, status history) each use `IgnoreQueryFilters([SoftDelete])`, and the row-version re-check does too. The live read is unchanged, and its 8-command count test still passes.
- The deleter and `deletedAt` come from one extra small query. If the order was restored after the child reads, that query finds nothing and the read answers 404.
- Controller action `GetDeleted` (`[HttpGet("deleted/{id:guid}")]`, `Policies.Manager`, `EndpointName("GetDeletedOrder")`) calls `GetDeletedOrderHandler` and sends `Cache-Control: no-store` like the rest of the controller.
- The matrix row, the Admin/anonymous test and `docs/api/orders.md` (route table, who-may-do-what table, a read-one section) are in place.
