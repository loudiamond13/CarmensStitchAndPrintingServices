# Phase 8: UI Design Contract (Order Screens)

*Created: 2026-10-29T14:27:45-05:00 · Updated: 2026-10-29T14:27:45-05:00*

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Owner conventions apply to everything below** (`.claude/CLAUDE.md` → Conventions): components from `@/components`; module code in `web/src/modules/admin/` (`pages/`, `components/`, `hooks/`, `services/`, module-wide copy and schema files); no em dash or en dash in any client string, `aria-label`, `title` or `alt` (OR-4); a missing value renders `EmptyValue`, never a dash; every form has a zod schema that mirrors its API validator and shows inline errors before any request is sent (OR-3); API calls live in per-module services (OR-5); the owner layout tree (OR-6). Money and every total come from the server. The client computes only labelled previews inside open forms (success criterion 3).

**What this file is.** The phase-scoped contract for the Orders list (grid and table), the New Order form, the Edit Details form, the Order page (header, status menu, locked banner, totals panel, customer card, status history, the five tabs and their add, edit and delete windows), the delete and cancel dialogs, the Manager-only Deleted Orders page and read-only deleted order view, and the Settings page turned into four list tabs. It creates **no new design token, color, font, font size or weight**. `CSPS-UI-SPEC.md` ("the spec") stays the visual source of truth with its precedence (Appendix, then tables, then prose). `02-UI-SPEC.md` ("P2") stays binding for the Tailwind contract, recipes, SPEC-GAP primitives and the interaction contract; `04-UI-SPEC.md` ("P4") for the Note primitive and the error mapper; `05-UI-SPEC.md` ("P5") for the shell, ConflictBanner, ActorName, RecordMeta, DateInput, RadioGroup, the row-action spacing (05 D-51) and motion (05 D-37 to D-39); `06-UI-SPEC.md` ("P6") for the list slice pattern, CategoryBadge, PaidBySelect, the Deleted page pattern and the Settings card. This file only adds what Phase 8 needs.

References: "§8.7" and "App. E.10" point into `CSPS-UI-SPEC.md`; "D-01" into `08-CONTEXT.md`; "07 D-26" into `07-CONTEXT.md`; "06 D-18" into `06-CONTEXT.md`; "P2", "P4", "P5", "P6" into the earlier UI-SPECs; "API" into `docs/api/orders.md` and `docs/api/order-lists.md`.

**URL params (WEB-10, allow-list parsers; defaults stay out of the URL):**
- `q`: trimmed, capped at 100 (`searchParser`). Sent as the API `q`.
- `status`: `active` (default) · `all` · `pending` · `mockup` · `production` · `ready` · `delivered` · `completed` · `cancelled`.
- `dates`: `30d` · `90d` · `month` · `custom`; none means **Any date** (OQ-3 default). `30d`, `90d` and `month` resolve against the client business date on every visit and are never stored as dates. `custom` reads `from` and `to` (`parseAsBusinessDate`) as a pair; either missing or invalid, or `from` after `to`, drops `dates`, `from` and `to` with one `replace`.
- `productType`: one id by shape; an id the list does not hold falls back to all with one `replace`.
- `hasBalance`: `true` or absent.
- `sort`: `due` (default) · `newest` · `balance` · `total`.
- `page` ≥ 1 (past the last is replaced by the last); `size` ∈ {10, 20, 50, 100}, default 20, sent as `pageSize`.
- `view`: `grid` · `table`, **no default** (ORD-10: URL, else `localStorage['csps-orders-view']`, else grid; only the toggle writes both).
- Order page and deleted view `tab`: `items` (default) · `payments` · `discounts` · `expenses` · `refunds`. `refunds` when the Refunds tab is not shown is replaced by the default with one `replace`.
- Settings `tab`: `product-types` (default) · `payment-methods` · `order-expense-categories` · `expense-categories`.
- A filter, search, sort or page-size change replaces the entry and resets the page to 1; a page change pushes; a tab change replaces. Search writes the URL with `debounce(300)`.
