# Plan 08-26: The payment window checks its cap against current figures (D-95, WR-02)

*Created: 2026-10-30T18:30:00-05:00 · Updated: 2026-10-30T18:30:00-05:00*

<objective>
Close the payment part of WR-02 in gap G-08-5 as the owner ruled in D-95. The payment window keeps the instant cap check, but it reads the order's figures again when the browser tab regains focus and when a cap check fails, then checks again with the current figures. The payment delete check gets the same refresh-then-check-again rule.

Purpose: today the window holds the order it opened with for its whole life, so if another staff member removes a payment or a refund, a valid amount is refused from old figures. No request is sent, so the 409 and Load Latest never come (08-REVIEW.md WR-02). The version a save sends stays the opened one (05 D-20, RESEARCH Pitfall 10), so a concurrent change is still caught by the server.
Output: a shared hook file (`useOrderWindowFigures`, `useReadOrderNow`, `freshCapResolver`) that 08-28 reuses for the refund and discount windows, `isOverPaymentCap`, the payment window wired to it, and the Payments tab delete check that reads once more before refusing.

Note for the owner, recorded in the SUMMARY: WR-02 listed the "would leave payments below refunds" delete check with the caps, so this plan applies D-95's refresh-then-check-again rule to it too (Task 3).

Phase goal (ROADMAP, verbatim): "Staff can run every order day to day in the portal. They can find an order, create one, work its detail page (items, payments, discounts, expenses, totals and estimated profit) and delete it safely."
</objective>

## Interface this plan creates (08-28 reuses it unchanged)

In `web/src/modules/admin/hooks/useOrderWindowFigures.ts`:

```ts
/** Reads one order now and puts it in the page cache; a read under a second old counts as current. Null when the read fails. */
export function useReadOrderNow(): (orderId: string) => Promise<OrderDetailResponse | null>;

export interface OrderWindowFigures {
  /** The order the window shows and checks: the newest answer held for this order, else the opened one. */
  readonly current: OrderDetailResponse;
  /** The newest held answer at the moment of the call, for a check that runs outside render. */
  latest(): OrderDetailResponse;
  /** Reads the order now (see useReadOrderNow). */
  refresh(): Promise<OrderDetailResponse | null>;
}

export function useOrderWindowFigures(opened: OrderDetailResponse): OrderWindowFigures;

/** A form resolver that checks against the latest figures, and on a cap failure reads once and checks again. */
export function freshCapResolver<TInput extends FieldValues, TOutput>(options: {
  figures: OrderWindowFigures;
  resolverFor: (order: OrderDetailResponse) => Resolver<TInput, unknown, TOutput>;
  overCap: (values: TInput, order: OrderDetailResponse) => boolean;
}): Resolver<TInput, unknown, TOutput>;
```
