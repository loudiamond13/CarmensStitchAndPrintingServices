# Plan 13-27: Queued quote and content photos are really removed from the storage (gap G-13-11)

*Created: 2026-11-25T00:58:00-06:00 · Updated: 2026-11-25T00:58:00-06:00*

> Gap closure for UAT test 11 (G-13-11) and the critical review finding 13-REVIEW G2A-CR-01. The ROADMAP Goal line for Phase 13 is not in user-story form, so no story was invented.

## What is wrong

`ImageRemovalJob` builds one allowed folder from the storage root and `orders`, and fails every other queued row with the code `outside-folder` without calling the storage (`ImageRemovalJob.cs:91` and `:197-202`). Quote photos live under `{root}/quotes/{requestId}/` (`PublicIds.QuoteFolder`) and content photos under `{root}/content/` (`PublicIds.ContentFolder`). So Spam (D-04), Manager delete, permanent order delete (D-22), the 6-month purge (INQ-07) and the stray sweep all queue rows that can never leave. The owner saw it in UAT test 11: "image are still in cloudinary after marking request spam". The queueing is already correct and tested (13-16 D3, 13-18 D2, 13-20 D5, 13-08 D2). Only the removal job's folder check is wrong.

## Decisions this plan follows

- **D-04** (Phase 13): marking a request Spam deletes its photos within a day, through the maintenance job.
- **D-22** (Phase 13): a permanent order delete takes the converted request and its photos with it.
- **D-34** (Phase 13): the maintenance run is daily (already built; no change here).
- **Phase 9 D-07** (`.planning/phases/09-order-images-maintenance-jobs/09-CONTEXT.md`): each environment touches only its own folders, and automated tests never call Cloudinary. This is the "D-07" the job's comments name. It is not Phase 13 D-07, which is the Quote alerts address.
- Scope from the orchestrator (2026-11-25): accept exactly the three own folders, each with its trailing slash; keep refusing everything else as `outside-folder`; one shared source for the prefixes in `PublicIds`; correct the runbook. The other 60 review findings, the D-45 Privacy Policy flip and the D-48 test email wording are out of scope (they belong to `/gsd-code-review 13 --fix` and later work).
