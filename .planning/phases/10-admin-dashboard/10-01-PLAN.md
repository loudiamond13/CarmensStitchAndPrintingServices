# Plan 10-01: The staff ledger union query runs on SQL Server (Wave 0 spike)

*Created: 2026-11-05T15:30:00-06:00 · Updated: 2026-11-05T15:30:00-06:00*

> MVP note: the ROADMAP Goal line for Phase 10 is not in user-story form ("Staff land on a dashboard that shows how the business stands today ..."). No story was invented. Run `/gsd-mvp-phase 10` if a user-story frame is wanted.

<objective>
The Wave 0 spike the research asks for first (RESEARCH Pattern 3, Pitfall 3, assumptions A1 and A2). It proves, against a real LocalDB database, that one LINQ `Concat` of narrow same-typed projections pages one person's money rows newest first, and that the sum of the rows newer than a page can be read. The query is written for keeps: plan 10-14 adds the transfer rows (the MoneyTransfers table arrives in plan 10-08) and the row details on top of it, without changing its shape.

Purpose: decide the ledger query shape before any screen depends on it (D-41 running balance, MONEY-02 server paging). If Concat will not translate, the fallback in RESEARCH "Alternatives Considered" (per-source reads merged in memory) is used and recorded; plan 10-14 consumes `StaffLedgerQuery` either way.
Output: `LedgerEntryKind`, `StaffLedgerRow`, `StaffLedgerQuery` and `StaffLedgerQueryTests`.

Phase goal (ROADMAP, verbatim): "Staff land on a dashboard that shows how the business stands today: active work, money owed, money collected and money spent. Each staff member also sees the money they hold and can hand it to a coworker (owner addition, 2026-10-07)."

Serial contract rule for this phase: the plans that rewrite `tools/openapi-gen/openapi.v1.json`, `web/src/types/api.generated.ts` and `tests/Csps.Server.IntegrationTests/Authorization/AuthorizationMatrix.cs` are 10-05, 10-06, 10-08, 10-10, 10-12, 10-14, 10-16 and 10-18, each in its own wave. This plan touches none of them.
</objective>
