# Phase 2 — UI Design Contract

*Created: 2026-10-07T19:42:42-05:00 · Updated: 2026-10-07T19:56:40-05:00*

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**What this file is.** This is the phase-scoped contract for Phase 2. It does **not** create a new design system. The approved design system is `CSPS-UI-SPEC.md` (spec v1.1, "the spec"), and its precedence still applies: Appendix › tables › prose. This file does three things:

1. It locks which parts of the spec Phase 2 delivers.
2. It records how the owner rulings in `02-CONTEXT.md` (D-01..D-24) change the visuals.
3. It defines the `// SPEC-GAP` items Phase 2 must build that the spec does not draw: the skip link, Pagination, OtpInput, MoneyInput, LazyImage, ErrorState, the Skeleton family, the mobile nav drawer, the user menu, the placeholder pages and the showcase.

Section references such as "§6.5" and "App. B" point into `CSPS-UI-SPEC.md`.

**Sources used:** 02-CONTEXT.md (D-01..D-24, all locked), CSPS-UI-SPEC.md §0–§13 and App. A–F, CSPS-PRD.md §7.1, §9, §12 and §17.2, REQUIREMENTS.md (WEB-01..10, ORD-09, A11Y-01/02/04, PERF-01/02/03/05), research/STACK.md, and the local-only `.planning/design/*.html` exports. The exports were unpacked to a scratch folder outside the repo and never copied into git. They contain no Pagination, OTP, LazyImage or skip-link designs, so those stay SPEC-GAP.

**Questions asked of the user in this session:** none while drafting, because every contract question was already answered by 02-CONTEXT.md or the spec. After verification, the UI-consideration probe raised three state gaps, and the owner answered them on 2026-10-07 (see § UI Considerations, rows marked "(owner, probe)"). Items that change markup and are not yet ruled are collected in **§ Owner Confirmations (D-08)**. The planner sends them to the owner as **one** plain-words before/after checkpoint. They are not decided here.

### CSS file contract (load order is part of the visual contract)

| Order | File | Rule |
|---|---|---|
| 1 | `globals.css` (App. A.2) → `tokens.css` (A), `compat.css` (A.3), `components.css` (B), `screens.css` (C) | **Byte-for-byte** copies of the spec (D-07). `globals.css` is not edited. |
| 2 | `spec-gaps.css` | New styles for the SPEC-GAP primitives only, written inside `@layer components { … }` so Tailwind utilities still come after them. It may use only `var(--…)` tokens and introduces no hex values. Every block starts with `/* SPEC-GAP: <primitive> */`. |
| 3 | `overrides.css` | The owner-approved reconciliations (D-01..D-05 and the PERF-05 font fallback). It is unlayered, so it wins over the verbatim CSS. Every rule carries a comment naming its decision ID, e.g. `/* D-02 (C-35) */`. |

`main.tsx` (App. D.6) imports them in that order after the font CSS. The two extra imports are marked `// SPEC-DEVIATION: D-07 overrides/spec-gaps load order`. React `style={{…}}` props, such as `Skeleton` and `Avatar` sizes, are applied through the CSSOM and are allowed under the strict CSP. **No `style="…"` strings may appear in `index.html` or any server-rendered HTML.**

## Spacing Scale

Declared values. All are multiples of 4 and are the spec's own `--space-*` tokens (spec §3.4). Tailwind's default 4px step equals this scale (`p-4` = 16px).

| Token | Value | Usage |
|-------|-------|-------|
| xs (`--space-1`) | 4px | Icon gaps, `.s-ph-title` gap, OtpInput gap at page width ≤ 420px |
| sm (`--space-2`) | 8px | Compact spacing, badge padding, OtpInput gap above 420px, toolbar end gap |
| (`--space-3`) | 12px | Toolbar gap, table cell vertical padding, phone card margin |
| md (`--space-4`) | 16px | Default element spacing, table cell horizontal padding, phone body side padding |
| (`--space-5`) | 20px | Card header horizontal padding, phone body top padding |
| lg (`--space-6`) | 24px | `.s-body` gap, `.s-wrap` side padding, tablet body padding |
| xl (`--space-8`) | 32px | Desktop `.s-body` padding, footer grid gap |
| 2xl (`--space-12`) | 48px | `.s-body` bottom padding, EmptyState vertical padding, phone `.s-sec` |
| 3xl (`--space-16`) | 64px | Page-head top padding, footer top padding |
| 4xl (`--space-24`) | 96px | Public `.s-sec` vertical padding, phone footer bottom padding (clears the sticky bar) |

**Control heights (touch targets):** inputs and md buttons 44px, lg buttons 52px, sm buttons and icon buttons 36px (existing design, see O-8), OtpInput boxes 44px tall (`.csp-input`) and ≥ 44px wide, skip link 44px (`.csp-btn-md`).

## Typography

The **full approved scale is spec §3.3 and is binding unchanged**. It is not reduced for this phase, and its 650 button weight and 800-italic display weight are approved decisions, not new ones. The four roles below are the ones Phase 2 surfaces (layouts, placeholders, showcase).

**Rule for new SPEC-GAP elements (binding):** a new element never sets its own `font-size`, `font-weight` or `line-height`. Its type comes from one of two places:
1. **An existing spec class it reuses.** The type is whatever that class already defines in App. B/C, and nothing in `spec-gaps.css` overrides it.
2. **Otherwise, Body (16/400) or Label (14/600)** from the table below.

Every SPEC-GAP element in this file is mapped:

| SPEC-GAP element | Type source |
|---|---|
| SkipLink | `.csp-btn.csp-btn-primary.csp-btn-md` |
| OtpInput digits | `.csp-input` |
| OtpInput legend | `.csp-label` |
| Showcase group heading | `.s-card-h h2` |
| Showcase variant labels | `.csp-overline` |
| UserMenu items | `.csp-nav` |
| Checkbox label | `.s-check` |
| ErrorState | `.s-banner` |
| ErrorBoundary and AdminPreviewPage empty state | `EmptyState` (`.csp-empty-*`) |
| Page titles and sublines | `.s-ph-title` |
| Public placeholder | `.s-eyebrow`, `.s-h1`, `.s-lead` |
| FilterBar and SearchBox | App. E.7 classes |
| Pagination buttons | `.csp-btn-secondary.csp-btn-md` |
| Pagination status text | Body weight 400 and Label weight 600, at the 14px Label size |
| Loading announcements | Visually hidden, no type |

So new work introduces **0 new sizes and 0 new weights**. It uses at most the 4 declared role sizes and the weights 400 and 600, and everything else is inherited from a reused class.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (Archivo) | 16px | 400 | 24px (1.5) |
| Label (Archivo, `.csp-label`, also the D-01 phone input size) | 14px | 600 | 20px (1.43) |
| Heading (Barlow, admin page title `.s-ph-title h1`) | 34px (30px tablet and phone) | 700 | 1.05 |
| Display (Barlow, inner-page H1 `.s-pagehead .s-h1`, public placeholder) | 80px (52px phone) | 800 italic, UPPERCASE | 0.88 |

**Weights for new SPEC-GAP elements:** 400 (body) and 600 (labels, emphasis). Any other weight they show, such as 650 on buttons or 700 on `.s-card-h h2`, belongs to a reused class and is not declared by the element. The only weight change this phase makes to existing elements is the **D-03 second cue: 700 on current or selected items** (see Color → D-03).

**Fonts (PERF-05):**
- Load only: Barlow Condensed latin + latin-ext at 600, 700, 800 and 800-italic, and Archivo Variable latin + latin-ext.
- Preload the Archivo Variable latin woff2.
- Add metric-matched fallback faces in overrides.css (`/* PERF-05 */`):
  - `"Archivo Fallback"` (`src: local("Arial")`)
  - `"Barlow Condensed Fallback"` (`src: local("Arial Narrow"), local("Arial")`)

  Each has computed `size-adjust` / `ascent-override` / `descent-override`, inserted into `--font-sans` / `--font-display` right after the brand family.
- Verify `document.fonts.check('16px "Archivo Variable"', '₱')` is `true`, and that `₱` in KPI or display text renders in Barlow Condensed or Archivo Variable, never a system font.

**Casing (spec §3.3):** public headlines and eyebrows are UPPERCASE. Buttons, nav, tabs and admin titles are Title Case. Body, labels, helper text and toasts are sentence case.
