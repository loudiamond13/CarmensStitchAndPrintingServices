# Phase 2 — UI Design Contract

*Created: 2026-10-07T19:42:42-05:00 · Updated: 2026-10-08T07:10:23-05:00*

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**What this file is.** This is the phase-scoped contract for Phase 2. It does **not** create a new design system. The approved design is `CSPS-UI-SPEC.md` (spec v1.1, "the spec"), and it stays the **visual source of truth** for look and copy, with its precedence: Appendix › tables › prose.

**Owner ruling D-33 (2026-10-08) changes how the look is built.** All UI styling is Tailwind v4 utilities in the markup. Spec §0 rule 2 and §2.3 ("copy Appendix A–C unchanged; utilities are layout glue only") and the CSS part of D-07 yield for UI styles. What they protected is still binding: every token value, size, spacing, radius, shadow, breakpoint, state and theme must render exactly as the approved CSS renders it today, plus the owner rulings. This file does four things:

1. It locks which parts of the spec Phase 2 delivers.
2. It records how the owner rulings in `02-CONTEXT.md` (D-01..D-38) change the visuals or the way they are built.
3. It defines the **Tailwind contract** and the **look-equality proof** that replace the verbatim-CSS and DOM-equality rules.
4. It defines the `// SPEC-GAP` items Phase 2 must build that the spec does not draw: the skip link, Pagination, OtpInput, MoneyInput, LazyImage, ErrorState, the Skeleton family, the mobile nav drawer, the user menu, the placeholder pages and the showcase.

Section references such as "§6.5" and "App. B" point into `CSPS-UI-SPEC.md`.

**Reading convention (D-33).** A spec class name in this file, such as `.csp-btn-primary`, `.s-banner` or `.s-rt`, means **"the look App. B/C defines for that class"**: its exact declarations, states and responsive rules, reproduced with utilities. It is **not** a class to put in markup (see § Tailwind Contract → Class-name hooks).

## Tailwind Contract (D-33)

This section replaces the old "CSS file contract". The *mechanism* rules here are binding. The *outcome* is fixed by the spec and the owner rulings, and § Look-Equality Proof checks it.

### What stays in CSS (and nothing else)

There is one stylesheet entry, `web/src/styles/app.css`, which `@import`s `web/src/styles/base.css` into `layer(base)`. `main.tsx` imports the fontsource weight CSS files and then `@/styles/app.css`, and nothing else; that import list is marked `// SPEC-DEVIATION: D-33`. A node-environment **stylesheet-contract test** parses both files and fails on any construct not in this table. The budget plugin asserts that every build emits **exactly one CSS asset**.

| Allowed construct | File | Content |
|---|---|---|
| `@import "tailwindcss" source("../src");` + `@source not "../src/**/*.test.{ts,tsx}"; @source not "../src/test";` | app.css | Tailwind entry and scan scope. Tests, `e2e/`, `visual/` and build output are never scanned (Pitfall 19). |
| `@custom-variant …` | app.css | The exact variant set below |
| `@theme { --*: initial; … }` and `@theme inline { … }`, with `@keyframes` inside `@theme` | app.css | The token theme below |
| Token custom properties per theme: `:root, [data-theme="light"] {…}`, `[data-theme="dark"] {…}`, `:root {layout tokens}` | base.css | The App. A token blocks with their values unchanged (Blush and Espresso, shadows, `--space-*`, radii, layout and z-index tokens, the status aliases). This is the **theme switch**: `data-theme` changes the tokens, and the `@theme inline` utilities read them live. The dark Mark tokens (`--csp-mark-ring: #1a100f; --csp-mark-stitch: #ff6a1a`) move into the dark block. The App. A **type utility classes are retired**, since App. D/E never use them. |
| `@font-face` for the PERF-05 metric fallbacks, plus the font-stack tokens | base.css | `'Archivo Fallback'` and `'Barlow Condensed Fallback'` (values in § Typography → Fonts) |
| Global element rules | base.css | `body {…}` (App. B line 1 look), the global `:focus-visible { outline: 2px solid var(--focus); outline-offset: 2px }`, the reduced-motion `* { transition-duration: 0s !important }`, and `main[tabindex="-1"]:focus { outline: none }` |
| **Nothing else** | — | No class selector (`.x {}`), no `@utility`, no `@apply`. No `overrides.css`, `spec-gaps.css`, `components.css`, `screens.css`, `tokens.css` or `compat.css`. App. A.3's two compat restores become utilities on their own elements: `my-[1em]` on the two `<dl>`s (later phases) and `px-[2px] py-px` on the two search inputs. |

### Token theme (binding values)

```css
@theme {
  --*: initial;                       /* no Tailwind default palette, radius, shadow, size, font or weight (spec §0 rule 1) */
  --spacing: 4px;                     /* the CSPS 4px step in px, like the spec: p-4 = 16px at any root font size */
  --breakpoint-sm: 640px; --breakpoint-md: 768px; --breakpoint-lg: 1024px; --breakpoint-xl: 1280px;
  --font-weight-normal: 400; --font-weight-medium: 500; --font-weight-semibold: 600;
  --font-weight-button: 650; --font-weight-bold: 700; --font-weight-heavy: 800;
  --radius-xs: 4px; --radius-sm: 8px; --radius-md: 12px; --radius-lg: 18px; --radius-pill: 999px;
  --animate-csp-spin: csp-spin .8s linear infinite;   --animate-csp-fade: csp-fade .15s ease;
  --animate-csp-rise: csp-rise .2s ease;              --animate-csp-slide: csp-slide .2s ease;
  --animate-csp-shimmer: csp-shimmer 1.4s ease-in-out infinite;
  /* @keyframes csp-spin / csp-fade / csp-rise / csp-slide / csp-shimmer: copied from App. B unchanged */
}
@theme inline {
  /* Every App. A.2 colour with the same name: --color-bg: var(--bg); … --color-link: var(--link);
     plus --color-transparent: transparent; --color-current: currentColor; */
  --font-display: var(--font-display);   /* reads the token, so the PERF-05 fallbacks apply */
  --font-sans: var(--font-sans);
  --shadow-level-1: var(--shadow-1); --shadow-level-2: var(--shadow-2); --shadow-level-3: var(--shadow-3);
}
```

- **Colour utilities** are exactly the 37 App. A.2 names (`bg`, `surface`, `surface-2`, `surface-3`, `nav-bg`, `nav-ink`, `sand`, `line`, `line-strong`, `ink`, `ink-muted`, `ink-subtle`, `primary`, `primary-hover`, `on-primary`, `accent`, `accent-hover`, `on-accent`, `accent-ink`, `accent-soft`, `accent-line`, `focus`, `danger`, `danger-soft`, `on-danger`, `success`, `success-soft`, `warning`, `warning-soft`, `info`, `info-soft`, `mockup`, `mockup-soft`, `neutral-soft`, `chart-income`, `chart-expense`, `scrim`, `link`), plus `transparent` and `current`. There are no others.
- **Px spacing** (research Q-7, inside planning discretion) reproduces the approved px CSS exactly. It changes nothing visible at the default 16px root, and it stays identical to the approved CSS for visitors who change the browser font size.
- **Layout and z-index tokens** are read with the v4 var shorthand, never copied as numbers: `w-(--sidebar-width)`, `h-(--header-height)`, `z-(--z-overlay)`, `max-w-(--container-max)`.
- **Font sizes and line heights** have no theme scale. They are transcribed as the spec literal: `text-[15px]`, `leading-5` (20px, from the 4px step), `leading-[.88]`.

### Custom variants (exact set; verified to emit the spec's query text)

```css
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));   /* App. A.2, unchanged */
@custom-variant hover (&:hover);       /* spec :hover applies on every device (Pitfall 21) */
@custom-variant pg-phone  (@container pg (max-width: 767px));
@custom-variant pg-tablet (@container pg (min-width: 768px) and (max-width: 1023px));
@custom-variant pg-md-up  (@container pg (min-width: 768px));
@custom-variant pg-lt-lg  (@container pg (max-width: 1023px));
@custom-variant pg-lt-xl  (@container pg (max-width: 1279px));
@custom-variant pg-xs     (@container pg (max-width: 420px));
@custom-variant vp-lt-sm  (@media (max-width: 639px));
@custom-variant vp-lt-md  (@media (max-width: 767px));
@custom-variant vp-xs     (@media (max-width: 420px));
@custom-variant no-hover  (@media (hover: none));
```

- **Allowed built-ins:** `sm:`/`md:`/`lg:`/`xl:` (exact `min-width` queries), `motion-reduce:`, `focus-visible:`, `focus-within:`, `active:`, `disabled:`, `not-disabled:`, `aria-*:`, `data-*:`, `group-*/<name>:`, `peer-*:`, `in-data-[…]:`, `before:`/`after:`, `placeholder:`, `first:`/`last:`/`nth-*:`, `checked:`.
- **Banned:** the built-in `max-*:`, `@max-*`, `@min-*` and `@md`-style container variants (they are off by one or nest differently; Pitfall 22), `enabled:` (it doesn't match `<a>`, so ButtonLink would lose its hover; Pitfall 27), and `prefers-color-scheme` dark mode.
- **Breakpoints stay container queries.** Every `@container pg (…)` rule in App. C becomes a `pg-*` variant on a descendant of the page root, which carries `@container/pg` (spec §2.10 #2). Every App. B/C `@media` rule becomes `md:`, `vp-*` or `no-hover`, with the same query text. The two are never swapped.

### Transcription rules (utilities in markup)

1. **Copy the spec value; never pick the "nearest" Tailwind value.** `font-size: 15px` → `text-[15px]`; `letter-spacing: .01em` → `tracking-[.01em]`; `min-height: 480px` → `min-h-[480px]`. A default-palette or default-scale class (`bg-blue-500`, `rounded-xl`, `shadow-lg`, `text-sm`) emits **no CSS at all, silently**, under the cleared theme (Pitfall 23). The gates below catch it.
2. **No hex, `rgb(` or `oklch(` inside a class token.** A literal colour the spec uses outside the tokens (lightbox chrome and hero overlay in App. C, all later phases) becomes a named theme token with the same value first.
3. **Exact shorthands.** A multi-layer shadow is an arbitrary **property**, `[box-shadow:0_6px_20px_-10px_var(--primary)]`, never `shadow-[…]`. `color-mix` is copied as written, `bg-[color-mix(in_srgb,var(--bg)_82%,transparent)]`, never an opacity modifier, which mixes in oklab (Pitfall 26). An order-sensitive or multi-function transform is `[transform:…]`, never the individual `scale-*`/`translate-*` utilities (Pitfall 25). Gradients take the `image:` hint, `bg-[image:repeating-linear-gradient(…)]`.
4. **Never put an arbitrary shorthand next to its longhands** (`[font:…]`, `[border:…]`, `[background:…]`, `[transition:…]`, `[animation:…]`; Pitfall 24). Drop App. B's `font: inherit`, because preflight already gives it.
5. **Transitions always carry duration and easing:** `transition-[background-color,border-color,color,transform,box-shadow] duration-150 ease-[ease]`. A bare `transition` has zero duration under the cleared theme (Pitfall 28).
6. **State comes from the attribute that already states it.** Selected and current use `aria-selected:` and `aria-[current=page]:`, invalid uses `aria-invalid:`, pending uses `aria-disabled:`, and other states use `data-*`. The spec's `.is-on`, `.is-invalid`, `.is-collapsed`, `.is-over` and `.tone-*` classes become ARIA/data attributes, or TSX class maps where no attribute exists.
7. **Parent state to child** uses a named group on the parent and a group variant on the child (`group/nav` + `group-aria-[current=page]/nav:hidden`). **Context ("this component inside that region")** uses (a) a prop when the parent component renders the child itself (`<Field density="toolbar">`, `<Icon>` colour passed by `Sidebar`), or (b) a `data-ui` marker on the region with `in-data-[ui=s-toolbar]:…` on the child, which matches the spec's descendant selector at any depth with no extra specificity.
8. **Reproduce the computed result, not the CSS's intent.** Cascade accidents in App. B/C are part of the approved look. The known case is the phone list-card title separator (OQ-1, ruled **A** by the owner on 2026-10-08, D-38). Any newly found accident that looks like a bug is a D-08 stop for the owner, and it is never silently "fixed" (Pitfall 29).
9. **Preflight differences are restated where they show.** v4 preflight gives `<button>` no `cursor: pointer`. Wherever the spec's look sets or inherits a pointer, the utility list says `cursor-pointer` (Pitfall 30).
10. **Don't restate preflight** (`m-0` on headings, `box-border`). The spec's `.s-page *` resets and `:where(.s-page) a { color: inherit }` are already preflight.

### Where class strings live

- **One typed recipe per component** (`*.recipe.ts`): module-level `as const satisfies Record<…>` maps of **complete, literal class tokens**, joined with `clsx`. There is no class-variance or merge package (R-5 not adopted). Base, variant, size and state axes set **disjoint properties**. The one intended overlap (icon-only padding) is resolved by one mechanism that the plan picks and proves in parity.
- **Shared looks share a recipe.** `buttonClasses()` serves `Button`, `ButtonLink` and `SkipLink`. One field-control recipe serves `Field`, `PasswordField`, `Select`, `MoneyInput` and `OtpInput`. One nav-item recipe serves the sidebar link and the D-27 Logout button.
- **`className` passthrough:** feature code may pass only **layout glue** (margin, width, grid or flex placement) that the component never sets itself, and never restyles a primitive (spec rule 3: extend by adding props). Inside `src/ui`, a component may pass context or state utilities to a child primitive **it renders itself** (for example `Sidebar` gives its `Icon` the current-item colour).
- **No constructed tokens.** `'bg-' + tone`, template literals and `+` inside `className`/`clsx` produce no CSS (Pitfall 31), so lint bans them. Concatenating *complete* tokens at module level is fine.
- **Tooling (D-36, dev only, exact versions):**
  - `prettier-plugin-tailwindcss` **0.8.1** sorts class strings in `className`, in `clsx` and in the recipe helper functions (configured by name).
  - `eslint-plugin-better-tailwindcss` **4.7.0** reports unknown classes (which catches every cleared-theme default), conflicting classes and restricted patterns (hex, `rgb(`, `oklch(`, default-palette names, the banned variants above, and text-bearing `opacity-*` outside the D-02 allow-list). Its class-order rule stays off, because Prettier owns the order.
  - The in-house `compile()` class gate from the research stays if the planner finds it covers something the plugin does not, such as recipe maps the plugin isn't configured to read. The planner decides.

### Inline style rule (strict CSP)

- **No `style="…"` attribute** anywhere in `index.html`, server-rendered HTML or `setAttribute('style', …)`. CSP blocks them in all three engines.
- **React `style` may set only CSS custom properties**, for genuinely continuous values, and a utility reads them:

  | Component | Custom properties | Consumed by |
  |---|---|---|
  | Skeleton | `--sk-w`, `--sk-h`, `--sk-r` | `w-(--sk-w) h-(--sk-h) rounded-(--sk-r)` |
  | MediaPlaceholder, LazyImage | `--ratio` | `aspect-(--ratio)` |
  | Avatar (numeric `size` prop) | `--avatar-size`, `--avatar-fs` (= `max(10, round(size × .38))`px, the App. D.3 formula) | `size-(--avatar-size) text-(length:--avatar-fs)` |
  | DataTable column | `--col-w` | `w-(--col-w)` |
  | IncomeExpenseChart tooltip | `--tip-x` | `left-(--tip-x)` |

- **Finite sets become class maps.** Column `align` becomes `text-left` or `text-right`.
- `cssText` and `setAttribute('style')` are lint-banned.
- **Body scroll lock** (modals, the drawer) toggles the literal `overflow-hidden` class on `<body>` through `classList`. It doesn't write `style.overflow`.
- CSP is verified only on the built app (E2E host and parity suite), never on the Vite dev server.

### Class-name hooks policy

- **No `.csp-*` or `.s-*` class names in markup.** They would be unknown classes to the gates, and they invite hand-written CSS back.
- **`data-ui="<spec class name>"`** appears only where a context variant needs a region marker, named after the spec class it stands for so reviewers can trace it to App. B/C. The markers Phase 2 needs are `data-ui="s-toolbar"`, `data-ui="s-item"`, `data-ui="s-admin-side"` and `data-ui="s-overlay"`. A new marker follows the same naming.
- **Tests find elements by role, label or text** (Testing Library and Playwright), never by class. The parity harness pairs elements by DOM order inside `[data-case="<id>"]` wrappers.
- **Visually hidden text** uses one shared constant that transcribes the `.csp-sr` look (`absolute h-px w-px overflow-hidden [clip:rect(0_0_0_0)] whitespace-nowrap`), not Tailwind's `sr-only`, so computed styles match the reference.
- The only non-utility classes in the DOM are the `lucide lucide-<name>` classes that lucide-react adds itself (D-28).

## Look-Equality Proof (D-33; replaces the DOM-differential test)

The rendered look is **proven equal** to the approved design by a same-run A/B comparison in the same browser. There are no stored baselines, so Windows and ubuntu font rasterization never matters.

### Reference and implementation

| Side | What renders | Where |
|---|---|---|
| **Reference** (test-only, never shipped) | The App. A–C CSS compiled exactly as App. A.2 wires it, applied to the frozen App. D.3/D.4/D.5 markup and App. E.1/E.6 shell fragments. On top sits a **test-only rulings layer** with the owner's look decisions: D-01, D-02 (+ FYI-01), D-03, D-05, D-27, D-31 O-3, O-6, D-BL-02, WEB-09, D-39 (the zero KpiCard value) and the PERF-05 font stacks. | **Implementation** | The real converted components, rendered by the dev showcase from **one** scenario list (`web/src/dev/scenarios.ts`: id, component, props, §12 seed data, themes, widths, states) inside fixed-width `[data-case]` frames (L-29) | `/dev/components` in the e2e build |

Both sides are served through `page.route` with the project's exact `StrictCsp` header (no port, no host, no DB), after `document.fonts.ready`.

### What is compared (exact, after normalization)

1. **Computed styles.** About 80 visual properties per element, walked in DOM order, including `::before`/`::after` when `content` is set. Boxes from `getBoundingClientRect` relative to the case root, exact to 0.01 px.
2. **Pixels.** A locator screenshot per case with `animations: 'disabled'` and `maxDiffPixels: 0`.
3. **Zero axe violations** and **zero CSP violations** on both sides.

**The only normalizations allowed** are:
- repeated entries in transition lists collapse to one;
- `border-*-style`/`-color` on 0-width sides and `outline-style`/`-color` at 0 width are ignored;
- `display: none` subtrees are skipped;
- for the icon `<svg>`, the wrapper is compared (size, colour, stroke, `display`, `vertical-align`) and the drawing is masked (D-32);
- transforms are compared by box and pixels, not by property string;
- attributes are not compared.

A per-case tolerance override needs a recorded reason, and the owner must be able to see it. The suite's self-test proves that a deliberate 1px change fails.

## Typography

**Fonts (PERF-05):**
- Load only Barlow Condensed latin + latin-ext at 600, 700, 800 and 800-italic, and Archivo Variable latin + latin-ext. Use the fontsource **weight** files, which carry `unicode-range` (Pitfall 18).
- Preload the Archivo Variable latin woff2 (a build plugin that fails unless it finds exactly one match).
