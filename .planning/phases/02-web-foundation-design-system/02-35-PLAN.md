## Executor Rules (every task)

- **Timestamps (owner rule):** every `.md` you create or edit (docs/web/release-gates.md included) carries ISO 8601 timestamps with offset; on an edit change only `updated`.
- **Packages:** lighthouse 13.5.0 is installed (D-25, replaces @lhci/cli); nothing else. Any install stops for a blocking-human `checkpoint:decision`.
- **Checkout:** if `web/node_modules` (or `tools/openapi-gen/node_modules`) is missing in this checkout, for example in a fresh worktree, run `npm --prefix web ci` (and `npm --prefix tools/openapi-gen ci`) first; it installs only what the committed lockfile pins and is not a package change. Parity, E2E, Lighthouse and review runs take run locks under `web/.locks/`; if one is held by another executor, wait and retry, never delete it.
- **Shared machine:** preflight before every Lighthouse, E2E and parity run; ports 5199 only for the host; never kill another project's process; environment variables per child process only. Reports go to git-ignored `artifacts/`, never uploaded.
- **Failures:** a gate that fails is fixed in the code, never by loosening a threshold; a fix that would change the look is a D-08 `checkpoint:decision` stop. If Lighthouse or axe fails on the footer's `href="#"` placeholders, that is a D-08 stop (UI-SPEC Owner Rulings).
- **Windows (L-22):** spawn `process.execPath` with JS entries (lighthouse's `cli/index.js`).
- Stay on `gsd/phase-2-web-foundation-design-system`. Zero warnings.
