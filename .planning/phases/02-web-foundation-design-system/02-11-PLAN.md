  truths:
    - "`?size=9999`, `?page=0`, `?page=-3`, `?status=bogus` and `?from=2026-02-30` each fall back to their default, and the URL is rewritten exactly once with `replace`; re-applying an already-canonical URL changes nothing (WEB-10 boundary and idempotency edges)."
    - "A page past the last page is replaced by the last page through `clampPage(page, totalPages)` (totalPages 0 → page 1), and an empty result is left to EmptyState (WEB-10 boundary/empty edges)."
    - "A page change adds a history entry (`push`); a filter, search, sort, page-size, tab or view change replaces the current entry and resets the page to 1 in the same single URL update (WEB-10 adjacency edge)."
    - "Defaults never appear in the URL (`clearOnDefault`); an empty or whitespace-only search removes `q` (WEB-10 empty edge)."
    - "Search text is trimmed and capped at 100 UTF-16 code units (the same unit as the input's maxLength and .NET string.Length) and truncation never leaves a lone surrogate (WEB-10 encoding edge)."
    - "Query-string keys are written in the order page, size, q, then the remaining keys by code-unit order, through the adapter's `processUrlSearchParams` (L-17) (WEB-10 ordering edge)."
    - "Date filters stay plain `YYYY-MM-DD` business dates through `parseAsBusinessDate` (real calendar validation, no UTC round trip); preset ranges are stored by name and resolved against the business today on every visit; nothing is defaulted from `new Date()` (WEB-10 precision edge)."
    - "Two setters called in the same tick produce one URL update (nuqs batching); the nuqs `startTransition` option and `shallow: false` are never used (lint from 02-04) (WEB-10 concurrency edge)."
    - "`NuqsAdapter` from `nuqs/adapters/react-router/v8` renders inside the router around `<Outlet/>` in the lazily loaded `UrlStateLayout`, with `defaultOptions` `{ shallow: true, clearOnDefault: true, scroll: false }`; layout tests assert `window.location.search` through `createBrowserRouter`, because shallow writes bypass `useLocation` (L-16)."
    - "Creating a list hook with a personal-data or secret key name (email, phone, mobile, token, password, otp, code, secret) throws at definition time."
    - "TanStack Query defaults are staleTime 30 s, gcTime 5 min, retry false (the HTTP client owns retries), refetchOnWindowFocus true, mutation retry false; list queries use `placeholderData: keepPreviousData`, forward the query `signal`, and key on parsed, defaulted values with the search through `useDebouncedValue(q, 300)`; intent prefetch calls `queryClient.query(options).catch(() => undefined)` (prefetchQuery is deprecated in 5.103.2, L-15) (WEB-08)."
