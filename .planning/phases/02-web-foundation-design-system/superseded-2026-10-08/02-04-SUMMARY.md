# Phase 2 Plan 04: Shared Centavo-Exact Order Math Summary

**The browser's order-math preview and the server's `Csps.Domain.Orders.OrderMath` now agree to the centavo. This is proven by 220 shared golden vectors, which xUnit and Vitest both read from one committed file. An exact-rational BigInt oracle generates the file, and a `--check` mode catches drift. The client `round2`, `discountAmount` and `orderTotals` work in exact integer centavos with half-away-from-zero rounding (SPEC-DEVIATION D-09), so 7.5% of ₱17.00 previews ₱1.28. The web app also gets the en-PH/Manila money and date formatters and an exact string-to-centavo conversion for MoneyInput.**

## Accomplishments

- **One vector file, two implementations.** `tests/fixtures/order-math-golden-vectors.json` holds 220 cases, all amounts as strings, sorted by id, LF, with no timestamp.
  - The xUnit project links it as `Content` (`Fixtures\order-math-golden-vectors.json`).
  - Vitest reads it with `fs.readFileSync(new URL('../../../tests/fixtures/…', import.meta.url))`.
  - Both suites assert at least 200 cases, unique ids and all eight categories.
- **The oracle shares no code with either implementation.** `web/scripts/golden-math.mjs` parses plain decimal strings into BigInt fractions. It rejects exponents and grouping, and rounds half away from zero at the centavo in the pinned order. Eleven hand-checked figures test it, including the full ORD-2026-0148 and ORD-2026-0151 totals.
- **Red evidence for D-09 (Pitfall 13).** The verbatim App. D.1 math fails 53 of the 220 vectors: 37 midpoint, 13 multi-discount, 2 negative-balance and 1 seeded-random. ORD-2026-0148 passes even with the buggy code, which is why the midpoint category exists. Each midpoint total/percent pair was picked because `Math.round(n * 100) / 100` rounds it the wrong way.
- **Server math.** `OrderMath.Compute` uses decimal, `ArgumentNullException.ThrowIfNull` on each list, and `Math.Round(x, 2, MidpointRounding.AwayFromZero)` at each step. It is BCL only, and Csps.Domain stays at 100% line and branch coverage.
- **Client math.** `csps.ts` keeps D.1's names, signatures and number-returning shapes, so D.2's 7 tests pass unchanged. A file header marks the totals as previews that the server's figures replace (D-09).
- **Formatting (ORD-09).** `format.ts` adds `formatBusinessDate`, with one cached `Intl.DateTimeFormat` per zone and Asia/Manila as the default. It re-exports `formatPeso` and `formatDate`, so callers need one import. `toCentavos` and `centavosToAmount` give MoneyInput an exact string-to-bigint round trip.

**2. [Rule 1 - Lint] Lint-only fixes in the verbatim App. D.1 code, each marked `// SPEC-DEVIATION:`**
- **Found during:** Task 1
- **Issue:** strictTypeChecked reported five problems in D.1 outside the order math:
  - `no-redundant-type-constituents` on `OrderExpenseCategory | string`
  - `no-unnecessary-type-conversion` and `restrict-plus-operands`/`noUncheckedIndexedAccess` in `formatDate`
  - `array-type` on `CASCADE_LABELS`
  - `restrict-plus-operands` in `cascadeSentence`
  - `restrict-template-expressions` in `orderNumber`
- **Fix:** Made the smallest same-output edit for each, with the rule named in a SPEC-DEVIATION comment. Prettier reformatted D.1 and D.2, which `format:check` requires. The tokens and logic are unchanged. The D.1 `Number(x)` lint errors in the order math went away with the D-09 rewrite.
- **Verification:** The D.2 tests and new characterization tests (formatDate with a Date or an unparseable string, the cascade sentence, passwordStrength) pass.
- **Committed in:** `0f13ecd`

**3. [Rule 1 - Bug] Domain coverage: `private const decimal Hundred` left one line uncovered**
- **Found during:** Task 2, coverage gate (99.6%)
- **Issue:** A `const decimal` compiles to a static field with a static-constructor initializer that never runs, because uses are inlined.
- **Fix:** Used the literal `100m`. The gate now reports 320/320 lines and 140/140 branches.
- **Committed in:** `819edee`

**4. [Rule 1 - Bug] Converting centavos to a number lost precision for huge values**
- **Found during:** Task 3, the new `round2(1e21)` test
- **Issue:** `Number(centavos) / 100` gave 999999999999999900000 for 1e21.
- **Fix:** Previews now convert through the exact decimal text, `Number(centavosToAmount(c))`. Within the money range (at most 999,999,999.99) both forms give the same number, and all 220 vectors still pass.
- **Committed in:** `080166d`

**5. [Rule 2 - Correctness] Non-finite inputs count as 0 in `round2` and the order math**
- **Found during:** Task 1 (GREEN)
- **Issue:** Exact centavos cannot represent `Infinity`. D.1 returned `Infinity` from `round2(Infinity)`, so a bad value would have poisoned every figure.
- **Fix:** NaN and ±Infinity count as 0, which extends D.1's own `Number(n) || 0` rule. This is documented in the SPEC-DEVIATION D-09 comment and tested.
- **Committed in:** `42dcc69` (tests in `080166d`)
