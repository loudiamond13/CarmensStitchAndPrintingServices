    - POST with idempotencyKey 'k-1' and a 503 then 200 makes 2 calls, both with header Idempotency-Key 'k-1'; POST without a key and a 503 makes 1 call; a 500 is never retried.
    - GET never carries an Idempotency-Key header; httpClient never generates one.
    - Three concurrent requests receiving 401 cause exactly one `refresh()` call; each request is retried once with the same headers (including the same Idempotency-Key) after the refresh resolves, and request interceptors run again (so a new token header applies).
    - When refresh rejects, all three reject with HttpError status 401 and onUnauthorized is called exactly once; a second 401 after a successful refresh calls onUnauthorized and does not refresh again.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
