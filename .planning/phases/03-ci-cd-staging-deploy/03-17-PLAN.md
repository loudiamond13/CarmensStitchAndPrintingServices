## Phase Goal

ROADMAP goal for Phase 3 (verbatim): "Every pull request is gated by the full pipeline. Every merge to `main` deploys to a SmarterASP.NET staging site that passes a smoke test, and production deploys wait for manual approval."

As amended by 03-CONTEXT.md (owner, 2026-10-15): GitHub runs a workflow_dispatch workflow only when its file is on main, and the package is built by a push to main (D-11), so the first deploy needs the pipeline merged first; the switch follows as soon as the pipeline and runbook are verified (D-19).

## Executor Rules (every task)

- **Timestamps (owner rule):** every `.md` you create or edit carries ISO 8601 `created:`/`updated:` timestamps with the -05:00 offset.
- **Merging:** only through `tools/scripts/Merge-PullRequest.ps1`, only after the owner's own message says to merge (D-08, D-09); never `gh pr merge` directly; never force-push.
- **Git:** stay on `gsd/phase-03-ci-cd-staging-deploy`; never create, rename, switch or delete a branch (the merge keeps it with -KeepBranch).
- **Away mode:** if the owner is away, the checkpoint goes to the backlog and nothing is merged.
