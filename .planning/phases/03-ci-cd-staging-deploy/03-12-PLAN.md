## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository writer → deploy workflow | Anyone who can dispatch the workflow can deploy |
| workflow inputs → deploy script | Dispatch inputs reach a script that holds the Web Deploy password |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-47 | Elevation of Privilege | A deploy triggered by anything other than the owner | high | mitigate | workflow_dispatch only, main-only job condition (tested); solo writer repo; Claude dispatches only on the owner's own instruction |
| T-03-48 | Tampering | Injection through dispatch inputs (CWE-77) | high | mitigate | Inputs reach the script only through env (tested); the script validates the sha format |
| T-03-49 | Elevation of Privilege | contents write used beyond releases | medium | mitigate | Granted only to the deploy job; the script only creates releases with it |
| T-03-50 | Elevation of Privilege | Repository secrets readable by any workflow on any pushed branch | medium | accept | GitHub Free private repos have no environment secrets; the owner is the only writer and CODEOWNERS covers .github/; recorded as an accepted risk in deploy.md |
| T-03-51 | Denial of Service | Two deploys at once corrupting the site | medium | mitigate | Concurrency group deploy-production without cancel (tested) |
| T-03-SC | Tampering | GitHub Actions (supply chain) | high | mitigate | Only owner-approved, SHA-pinned actions; no npm install on the deploy runner |
</threat_model>
