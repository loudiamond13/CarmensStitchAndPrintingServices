# Phase 7.1: Code Review Report

*Created: 2026-10-29T12:33:14-05:00 · Updated: 2026-10-29T12:33:14-05:00*

## Summary

I reviewed the legacy fit check tool, its tests, and the CI, solution and doc changes that come with it. I read the source only. I did not open `_local/`, connect to a database, or run the tool or its tests. I ran one incremental `dotnet build` of the test project, which reported 0 warnings.

The three D-14 security points hold up:

1. **The restore is only read.** The context refuses every save. The command guard lets through only LINQ commands that start with SELECT. The read transaction is never committed. The write evidence compares before and after.
2. **Nothing is written outside the trial database and `_local`.** The trial name must match `^CSPS_Test_[0-9a-f-]{36}$` before it is created or dropped. The drop runs in `finally` with no cancellation. The findings writer refuses links and any path that leaves `_local/legacy-fit-check`.
3. **No personal data reaches the console.** Console and error output give only type names and fixed sentences.

The tool has no hand-written SQL. There is no em or en dash in any file in scope.

The one blocker is a test portability bug. The CI step this phase adds runs these tests on ubuntu, and five path-guard test cases build their escape paths with Windows backslashes, so they will fail there. The warnings are:

- The summary renderer prints rule keys that embed domain messages, which is a latent way for amounts to leak.
- The column drift finding can never fire in a real run.
- The no-raw-SQL source scan has gaps.
- The write evidence can quietly lose its index-update check.

One thing I checked and ruled out: I first suspected the trial compatibility check would fail on the SQL 2025 CI container. It will not, because `SqlCompatibility.Level` is 170, the same as that server's default.

## Critical Issues

### CR-01: Path-escape tests use Windows backslashes and will fail on the ubuntu CI runner

**File:** `tests/Csps.LegacyFitCheck.Tests/FindingsTests.cs:66-71, 94`
**Issue:** This phase adds `dotnet test --project tests/Csps.LegacyFitCheck.Tests` to the "3 integration tests" step (`.github/workflows/ci.yml:140`). That job runs on `ubuntu-24.04`. On Linux, `\` is an ordinary file name character, not a separator. So `Path.Combine(folder, "..\\x.md")` stays inside the folder as a file literally named `..\x.md`. `FindingsWriter.ResolveTarget` then correctly accepts it, and `Should.Throw` fails. Five cases are affected:
- `("legacy-fit-check", "..\\x.md")`
- `("legacy-fit-check", "..\\..\\evil.md")`
- `("..\\..\\_localx", "x.md")`
- `("legacy-fit-check", "sub\\..\\..\\x.md")`
- the `"..\\_localx"` call in `ASiblingFolderWithTheSamePrefixIsRefused`

The CI gate will go red when the joint PR opens (D-15). The guard itself is fine on both systems. Only the tests are not portable.
**Fix:** Build the escape paths with the platform separator, or use `/`, which both systems treat as a separator:
```csharp
[Theory]
[InlineData("legacy-fit-check", "../x.md")]
[InlineData("legacy-fit-check", "../../evil.md")]
[InlineData("legacy-fit-check", "../../../evil.md")]
[InlineData("../../_localx", "x.md")]
[InlineData("..", "x.md")]
[InlineData("legacy-fit-check", "sub/../../x.md")]
public void ATargetThatLeavesTheFolderIsRefused(string subFolder, string fileName) { ... }

// and in ASiblingFolderWithTheSamePrefixIsRefused
Should.Throw<InvalidOperationException>(() => FindingsWriter.ResolveTarget(root, "../_localx", "x.md"));
```
If you want to keep the backslash forms as Windows-only proof, put them in a separate test that skips unless `OperatingSystem.IsWindows()`.

## Warnings

### WR-01: The summary prints raw rule keys that embed domain messages, some of which carry per-order amounts

**File:** `tools/Csps.LegacyFitCheck/Checks/OrderRuleProbe.cs:150`, `tools/Csps.LegacyFitCheck/Checks/CompanyExpenseCheck.cs:61`, `tools/Csps.LegacyFitCheck/Findings/SummaryRenderer.cs:27-30, 218`
**Issue:**
- **The keys embed messages.** The rule key of a probe break is `"{path}: {message}"`. The rule key of a company expense failure is `"{Field}: {Message}"`.
- **The summary prints them as-is.** A key with no label is printed verbatim as the summary line (`SummaryRenderer.cs:218`). The class comment says the renderer "never reads a path, a message or a detail", but through the rule key it does read both.
- **Some messages carry amounts.** Several domain messages hold per-order peso amounts: `OrderRules.PaymentAboveBalance` (`OrderRules.cs:570`), `RefundAboveCredit` (988), `RefundAboveKept` (994), and `OrderStatusRules.cs:40`.
- **Why it does not leak today.** These messages are not reached now. `OrderImportRules.Default` relaxes every flag, a relaxation finding uses the flag name as its key, and the draft mapping builds no refunds.
- **Why it could leak later.** If a relaxation is narrowed later, or Phase 15 maps refunds, a per-order amount lands in the committed summary. D-08 says amounts stay in `_local/` only, and the privacy self-check would not catch it, because amounts are not in `readValues`. Lines would also split per amount instead of grouping.

**Fix:** Keep messages out of rule keys. For example, key on the index-free path plus a stable message id. Or have the renderer print any unlabeled key as a fixed line ("Other rule break: see the local list"). Add a test that a finding whose message holds `₱1,234.00` never puts that text in the rendered summary.

### WR-02: The "mapped column missing" drift finding can never appear in a real run

**File:** `tools/Csps.LegacyFitCheck/FitCheckRunner.cs:200-228`, `tools/Csps.LegacyFitCheck/Mapping/ColumnInventory.cs:50-53`
**Issue:** Every column `DraftColumnMap` marks as mapped is also a property in `LegacyModel`. The runner reads Orders, OrderItems, Payments, Discounts, Expenses and the people tables (lines 201-221) before it reads `source.Columns` (line 228). If a mapped column is missing, the first EF query throws `SqlException`. The run then ends with only `Failed: SqlException`, and the D-05 "cannot map (drift)" finding that `ColumnInventory` was built to report never appears. The `column.missing` path is reachable only in unit tests.
**Fix:** Read the column list right after the first write evidence capture. Run `ColumnInventory.Check` on it. If `Missing > 0`, stop with a fixed message, or write the inventory findings, before any table query runs:
```csharp
var before = await WriteEvidence.CaptureAsync(source, cancellationToken).ConfigureAwait(false);
var columns = await source.Columns.Where(static c => c.TableSchema == "dbo").ToListAsync(cancellationToken).ConfigureAwait(false);
if (ColumnInventory.Check(columns).Missing > 0) { /* return a drift result, no table reads */ }
```

### WR-03: The no-raw-SQL source scan has gaps

**File:** `tests/Csps.LegacyFitCheck.Tests/ToolSourceRulesTests.cs:14-25, 88-101`
**Issue:** This test is what enforces the owner rule against hand-written SQL in the tool, but it bans only a few literal tokens. All of these pass the scan:
- `SqlCommand command = new(sql, connection);` (a target-typed `new`, so `new SqlCommand` never appears)
- `new Microsoft.Data.SqlClient.SqlCommand(...)`
- `connection.CreateCommand()` followed by `ExecuteReaderAsync`, with the text set through a constructor argument

At run time, the read-only guard would still refuse such a command on the legacy context. But a raw command on a separate `SqlConnection`, or on the trial `CspsDbContext`, has no guard. The comment-skip rule also skips any code line that starts with `*`.
**Fix:** Add `SqlCommand`, `DbCommand`, `CreateCommand(`, `ExecuteReader` and `SqlConnection(` to the banned tokens. Allow-list `ReadOnlyCommandGuard.cs` for its `DbCommand` parameter type. Then add matching `InlineData` cases.

### WR-04: The write evidence silently drops its index-update check if the database lookup misses

**File:** `tools/Csps.LegacyFitCheck/Source/WriteEvidence.cs:36-43`
**Issue:** `FirstOrDefaultAsync` returns 0 when no `sys.databases` row matches `GetDbConnection().Database`. The code then casts that 0 to `short`, and the usage sum for "database 0" is 0 both before and after. In that case the D-14 proof quietly rests on row counts alone, while the summary still says "0 index updates before and after". The `(short)` cast also narrows an `int` id without any check.
**Fix:** Use `SingleAsync` and throw if it is missing (the runner already reports a fixed failure text). Keep the id as an `int` and compare with `usage.DatabaseId == databaseId` after widening:
```csharp
var databaseId = await context.CatalogDatabases.Where(d => d.Name == databaseName).Select(d => d.DatabaseId).SingleAsync(cancellationToken).ConfigureAwait(false);
var updates = await context.CatalogIndexUsage.Where(u => (int)u.DatabaseId == databaseId).SumAsync(u => (long?)u.UserUpdates, cancellationToken).ConfigureAwait(false);
```

## Info

### IN-01: "The trial database could not be removed" shows even when it was never created

**File:** `tools/Csps.LegacyFitCheck/FitCheckRunner.cs:89-107, 142-159`
**Issue:** If `TrialDatabase.CreateAsync` fails before the database exists (for example, the server cannot be reached), the `finally` still drops and checks. When that also throws, the user sees "could not be removed. Run Remove-StaleTestDatabases.ps1" plus `Failed: SqlException`, which points them the wrong way.
**Fix:** Set a `created` flag once `CreateAsync` gets past `IRelationalDatabaseCreator.CreateAsync`, or ask `ExistsAsync` first. Report a failed removal only when the database exists.

### IN-02: Splitting the trial staff name assumes the pseudonym has a space

**File:** `tools/Csps.LegacyFitCheck/Trial/TrialSeeder.cs:65-70`
**Issue:** `member.Pseudonym[..space]` throws `ArgumentOutOfRangeException` when `IndexOf` returns -1. Today the pseudonym is always "Legacy staff N", so this is latent.
**Fix:** Carry `FirstName` and `LastName` on `TrialStaff` instead of parsing the display name.

### IN-03: Description null handling is not consistent across the mapping

**File:** `tools/Csps.LegacyFitCheck/Mapping/DraftMapping.cs:148, 195, 223`
**Issue:** `MapCompanyExpense` uses `expense.Description?.Trim()`, while items and discounts call `.Trim()` directly on the same kind of non-nullable `string` property. The columns are NOT NULL today (RESEARCH line 129-132), so nothing breaks. The mixed style hides which fields really can be null.
**Fix:** Pick one rule. Either declare the properties as nullable where the column allows NULL, or drop the `?.`.

### IN-04: The tool's pure tests run only in CI full mode

**File:** `.github/workflows/ci.yml:140`, `docs/operations/ci.md:182`
**Issue:** The whole test project sits in the "3 integration tests" step, which runs in Full mode only. The privacy self-check, summary renderer, read-only guard theories and the no-raw-SQL source scan need no database, but they also skip every non-full run.
**Fix:** Optional. Split the database-free tests into a unit test project, or filter them into the "3 unit tests" step, so the D-14 guards run on every PR.
