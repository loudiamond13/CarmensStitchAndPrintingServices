# Phase 7.1 Plan 09: Counts-only summary, privacy self-check, hardened _local guard and runbook Summary

**Every run now writes a private full list and a counts-only summary in plain words beside it. The summary is built from counts and allow-listed list words only, is searched for every personal-looking value the run read before it is written, and the full list can only land inside the repo's `_local/legacy-fit-check` folder. Owner ruling D-87 is built in: legacy expenses with no order that are not company expenses are counted by one new finding, `expense.unplaced`.**

## Notes and open questions for the owner and later plans

- **Risk for the real run (plan 10): the self-check may refuse a real summary on a false hit.** The plan's rule is "every read value of 3 or more characters that appears anywhere in the summary refuses it". The match is a plain substring, so a short real value such as a 3-letter name or an item word like "tag" or "set" can sit inside an ordinary summary word and refuse it. The refusal text cannot say which value matched (that would leak it). The full list is still written, so nothing is lost, but the owner may then get no summary. Options: (1) keep as is and see on the real run (recommended: it is the safe direction, and the real run is the cheapest way to learn how often it happens); (2) match whole words only; (3) raise the minimum length to 4. I did not change the rule, because it changes the security posture.
- **Open question (D-87 follow-up):** an expense whose `OrderId` points at an order that does not exist in the restore is also read into no order, and `expense.unplaced` does not count it (D-87 names only rows with no `OrderId`). The owner can rule whether to count those too.
- **Open question:** expenses (and payments, items) of a soft-deleted order are dropped with the order, which is reported once as `order.deleted`. They are not counted separately. Not changed.
- **Not covered here:** the file-level link refusal (`File.CreateSymbolicLink`) is skipped on this machine because the account may not create file symbolic links. The folder, root and existing-file refusals run. The code path for a linked file is the same `RefuseLink` check as for folders.
- **Plan 10:** the real run needs the owner's go-ahead. The summary must be reviewed and gitleaks-scanned before it is copied into `07.1-FINDINGS.md` (plan 11).
- **Plan 11:** the run output folder `_local/legacy-fit-check/` is git-ignored (`.gitignore` line 2).
