# Phase 7.1 Plan 07: Trial database safety and import outcomes Summary

**The throwaway trial database is checked before it is created, always dropped (even when a step throws) with removal confirmed by name, and each import result (400, 422, 409, exception) and each lifted year counter is now a finding.**

## Accomplishments

- Tracer (D-07): a hook that throws `InvalidOperationException("SENTINEL-NAME-7Q")` right after the trial database exists ends the run with exit 1 and exactly `Failed: InvalidOperationException`, no findings file, and `TrialDatabase.ExistsAsync` for that name is false. The tracer `<verify>` was re-run end to end before expanding: `FitCheckRunnerTests` 11 of 11 and `TrialTargetTests` 24 of 24.
- `TrialTarget.Check`: allows only `(localdb)\MSSQLLocalDB`, `127.0.0.1,<port>` and `localhost,<port>`. It refuses `(localdb)\CSPS`, `np:` and `tcp:` addresses, named instances, hosted servers, `AttachDBFilename`, `Failover Partner`, null, empty and unreadable text. Reasons are fixed sentences; a theory test checks none repeats the host, instance or port.
- `TrialTarget.For(template, name, sourceName)`: refuses a server that fails `Check`, a name that is not `CSPS_Test_{guid}`, and a name equal to the source database (any case). It sets only `InitialCatalog`.
- `FitCheckRunner`: checks the trial target right after the source check and builds the trial connection string from a generated name, all before any connection (exit 2, `Refused: ...`). The drop sits in `finally`, never cancelled. `RemoveTrialAsync` then asks the server by name; if the database is still there (or the drop threw), the run returns 1 with `Failed: the trial database could not be removed. Run tools/scripts/Remove-StaleTestDatabases.ps1.` On success the findings hold `Trial database removed: yes` (rule key `trial.removed`).
- `TrialDatabase.CheckCompatibilityAsync`: reads `compatibility_level` for the trial name through the keyless `sys.databases` view (LINQ) and throws unless it equals `SqlCompatibility.Level`. `CreateAsync` calls it right after the migration, so a mismatch fails the run and the database is dropped. No ALTER text exists in the tool. On this machine the level is 170, so no owner question arose.
- `TrialImport`: success gives Info `trial.imported`. `orders.number-taken` gives `trial.number-taken`. `orders.busy` is retried once in a fresh scope, then `trial.busy`. Any other failure gives one `trial.invalid` per field path and message (or one for the error, with its code in Detail). An exception in one order gives `trial.exception` (type name only) and the next order still imports. After the imports, `OrderNumberCounters` is read with LINQ and each year with a value above zero gets one Info `trial.counter-lifted`.

## Notes and open questions for the owner and later plans

- **Counters:** `trial.counter-lifted` is emitted for every year whose counter is above zero after the import. A fresh trial database starts empty, so every such year was lifted by an import. If the owner wants only years where the imported number was above the next free value, that is the same set here.
- **Plan 09:** count lifted years by counting `trial.counter-lifted`; group `TrialImport` findings by rule key (`trial.invalid` by its path, `trial.number-taken`, `trial.busy`, `trial.exception`). Counter values are only in `Detail`.
- **Hard kill:** if the tool is killed by force while the trial database exists, only `tools/scripts/Remove-StaleTestDatabases.ps1` cleans it up. The drop in `finally` cannot run after a hard kill. This is the residual risk of T-07.1-20 and is named in the failure text.
- **Order of the guard:** the trial server is checked after the source check. A bad source and a bad trial server both exit 2; the source reason wins when both are bad.
