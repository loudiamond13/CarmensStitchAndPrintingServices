# Phase 7.1: Draft legacy mapping (provisional)

*Created: 2026-10-29T08:41:00-05:00 · Updated: 2026-10-29T09:10:00-05:00*

> **Provisional (D-04).** Good enough to run the fit check only. Phase 15 writes the real LEGACY-MAPPING.md and the owner signs it off there. Phase 16 may reuse the code but is not bound by it.

This page names legacy tables, columns and list words only (D-02). It holds no names, phones, emails, notes, order numbers, row ids or amounts. The same map lives in code as `DraftColumnMap` in `tools/Csps.LegacyFitCheck/Mapping/`, and a test keeps the two in step with what the tool reads.

## How to read the tables

- **Mapped:** the check reads the column and puts it in the place named.
- **Not mapped, cannot map:** the column has no clear place in CSPS (D-05). Each one becomes a "cannot map" finding and a question for Phase 15.
- **Not mapped, not checked:** the column is left for Phase 15 (who created or changed a row, and edit date stamps). The tool does not read these columns at all. A run only notes that they exist.
- **Unknown column:** a column of an in-scope table that is in none of the lists below. The run reports it as "cannot map: unknown column" (`column.unknown`).
- **Missing column:** a mapped column the restore does not have. The run reports it as drift (`column.missing`).

## Scope

- **In scope (seven tables):** Orders, OrderItems, Payments, Discounts, Expenses, OrderTypes, Statuses. Every column of these is listed below.
- **People tables, read only to match people (D-09):** AspNetUsers (id, user name, email), AspNetRoles (id, name) and AspNetUserRoles (user id, role id). They are left out of the column inventory. No person-name or login column is read.
- **Out of scope (D-09):** OrderImages, MoneyTransfers, the Identity claim, login and token tables, and `__EFMigrationsHistory`. Users, site content, images and the other tables wait for Phases 15 and 16.

## Value rules

How a legacy order and its parts become a CSPS import snapshot (plan 07.1-04). Each row matches the code in `DraftMapping`, `LegacyDates` and `ListMatching`, and a test covers it. Values are passed through trimmed and the CSPS rules judge them. A finding of type "cannot map" is raised only where a value has no place or no meaning (D-05).

### Orders

| CSPS target | Legacy source | Draft rule | Finding raised |
|---|---|---|---|
| Order number | OrderId, order year | `ORD-{Manila year}-{OrderId, 4 digits}` | CannotMap `order.no-number` for every mapped order |
| Order status | Statuses.StatusName | "Open" is Pending, "In Progress" is InProduction, "Completed" is Completed (trimmed, any case) | CannotMap `order.status-unknown` for any other word; the order is not imported |
| Order date | Orders.OrderDate | read as UTC, moved to Asia/Manila, date taken | CannotMap `order.no-date` when empty; the order is not imported |
| Deleted order | Orders.IsDeleted | an order marked deleted is not imported | CannotMap `order.deleted` |
| Customer name | OrderName | trimmed; a blank name is passed on for the rules to judge | none |
| Notes | Note | trimmed; empty means none | none |
| Team, contact number, email, address, due date | none in the legacy data | left empty | none |
| Status history | none in the legacy data | left empty; the import writes one row | CannotMap `order.no-status-history` for every mapped order |

### Dates

The stored datetime is read two ways: as UTC moved to Asia/Manila (used for the import, provisional guess, RESEARCH A3), and as stored with no zone change. A record whose two readings give different dates gets an Info finding `dates.reading-differs`. The owner rules on which reading is right when the counts are known.

### People

Plan 07.1-05 (D-06, 07 D-37). The text in `Payments.PaidTo` (the receiver) and `Expenses.PaidBy` on an order expense (the payer) is matched to a legacy user by user name (trimmed, any case). The code is `PeopleMatching`, and tests cover each row. No name, user name or email reaches the trial database, the console or an exception text.

| Case | Draft rule | Finding raised |
|---|---|---|
| A legacy user with the role Admin | becomes one trial staff member named "Legacy staff N" with the email `legacy-staff-N@example.invalid` (N counts up in legacy id order). The account is an active CSPS Admin with a placeholder password and a confirmed email, so the CSPS payer rule accepts it. It cannot sign in | none |
| Any other role (Company, Employee, Manager, or a role CSPS does not have) | the Legacy / unassigned holder (`LegacyHolder`) is used | UnmatchedPerson `person.role-no-match` naming the role, plus LegacyHolderUsed `person.legacy-holder` |
| A user with no role | the Legacy / unassigned holder is used | UnmatchedPerson `person.role-no-match`, plus LegacyHolderUsed |
| A name that matches no legacy user | the Legacy / unassigned holder is used | UnmatchedPerson `person.unknown-name` naming the text, plus LegacyHolderUsed |
| Empty text | the Legacy / unassigned holder is used | UnmatchedPerson `person.blank`, plus LegacyHolderUsed |

Each holder use is two findings on the payment or order expense, so the counts show how often the holder would be used per record kind. The text and role names appear only in the full findings file under `_local`. A user with more than one role maps when one of the roles is Admin. The legacy Manager role is not mapped to the CSPS Manager role because the plan rules it out; the owner can rule on that when the counts are known.

Plan 07.1-08 adds the rules for company expenses here.
