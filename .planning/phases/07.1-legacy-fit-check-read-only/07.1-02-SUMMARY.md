# Phase 7.1 Plan 02: Read-only proof Summary

**The restore is only read, and the tool proves it: a fixed source refused before connect, a SELECT-only EF interceptor, saves that always throw, one never-committed transaction, and per-run write evidence (tables, rows, index updates) compared before success.**

## Accomplishments

- Tracer (D-14): every run captures write evidence before the first read and after the last, compares, and records "Write evidence: unchanged (4 tables, 5 rows, N index updates before and after)" as an Info finding in the findings file only. A change fails the run (exit 1, fixed line, no findings file, no trial database created). The console never prints the counts.
- Source guard (D-07): `LegacySource.Check` refuses null, blank and unreadable text, `CSPS_Dev`, `CSPS_E2E`, `BetsLLC_*`, `master`, no catalog, the restore on a container address, `(localdb)\CSPS`, `np:` and `tcp:` addresses, named instances, hosted servers, `AttachDBFilename`, `Failover Partner` and uppercase or over-long test names. The runner calls it first and returns 2 with `Refused: <fixed sentence>` before any connection. `Prepare` forces `Pooling=false` and the application name. `FitCheckTargets.Real` is built from `LegacySource` constants.
- Command guard (D-14): `ReadOnlyCommandGuard` passes a reader only when `CommandSource` is `LinqQuery` and the text starts with SELECT. Every other source, every non-query and every scalar command throws `InvalidOperationException("The legacy restore is read-only. Only LINQ reads are allowed.")`. `LegacyDbContext.Open` adds it to every context. Proven against a fake restore: LINQ reads work; `SaveChanges`, `ExecuteDelete`, `ExecuteUpdate`, raw non-query, `FromSql` and `SqlQuery` are all refused and the fake's rows and names are unchanged.
- Source rules: `ToolSourceRulesTests` scans every `.cs` under `tools/Csps.LegacyFitCheck` (bin and obj skipped, comment lines skipped) for the raw SQL entry points, any `CommandText` assignment (reading it is allowed), `EnableSensitiveDataLogging`, `LogTo(` and `LoggerFactory`. It also checks the runner begins a transaction and never commits.

## Deviations from Plan

**1. [Rule 1 - Bug] Write evidence flaked under parallel load because a closed connection resets index usage counters**
- **Found during:** Task 2 (full test project run after the source guard was added; the Task 1 tracer re-run had passed by luck).
- **Issue:** `OneLegacyOrderRunsEndToEnd...` failed intermittently with "the restore changed during the run". Diagnosed with a temporary debug line (removed before commit): before `UserUpdates = 4`, after `UserUpdates = 0`. LocalDB test databases auto-close; with `Pooling=false` and EF opening a connection per query, the database closed between the two captures and SQL Server reset its index usage counters.
- **Fix:** The runner now opens one `BeginTransactionAsync(ReadCommitted)` around the whole read window (evidence included), never committed. This is the Task 3 transaction, pulled forward because Task 1's evidence needs it to be stable. The `WriteEvidenceTests` open the connection explicitly for the same reason. Five full runs, then three more after Task 3, all 0 failures.
- **Files modified:** `FitCheckRunner.cs`, `WriteEvidenceTests.cs`.
- **Commit:** fe8956e8 (shared with the source guard change, because both touch `FitCheckRunner.cs`).
- **Not covered by a deterministic test:** forcing auto-close would need hand-written SQL, so the regression evidence is the repeated clean runs. A real restore that is idle is unaffected, because the window holds one connection from before the first capture to after the last.

**2. [Test wording] "a line starting 'Write evidence: unchanged'"**
- The findings file is a Markdown table, so the text sits in the Message cell and no line starts with it. The test asserts the file contains `Write evidence: unchanged (4 tables, 5 rows,`, and that the console output does not contain it.

**Total deviations:** 1 auto-fixed (Rule 1), 1 wording note. **Impact:** none on scope. Task 3's "transaction" criterion was met earlier than planned.
