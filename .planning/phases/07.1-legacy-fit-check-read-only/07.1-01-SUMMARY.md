# Phase 7.1 Plan 01: Fit check tracer Summary

**A no-argument console tool reads a fake legacy restore, maps one order, imports it through ImportOrderHandler with OrderImportRules.Default into a throwaway CSPS_Test database it then drops, and writes the findings under _local only; CI runs its tests and a publish test keeps it out of the deploy package.**

## Accomplishments

- Tracer: one made-up legacy order (sentinel name, two items) goes read, map, trial import, drop, findings file. The recorded trial database no longer exists afterwards, the fake restore still holds 1 order and 2 items, and neither output nor error contains the sentinel.
- `Program` takes no arguments: any argument returns exit 64 with a "Usage:" line before anything connects. A failure prints `Failed: <ExceptionTypeName>` and exits 1.
- `FitCheckTargets.Real` is built from constants only (default LocalDB instance, `CSPS_Legacy_Restore`, pooling off). There is no argument or environment input for it.
- `LegacyDbContext` maps only the columns the check reads, tracks nothing and throws `InvalidOperationException("The legacy restore is read-only.")` on every save overload. No logging is attached.
- `FindingsWriter` writes `_local/legacy-fit-check/findings-{stamp}.md` with a Created/Updated line on line 2 and the never-commit warning. It refuses a root not named `_local`, a target outside it, and link folders.
- Gates: both projects are in `Csps.slnx` and `SolutionLayoutTests.ExpectedProjects`; the CI step "3 integration tests" runs the new test project; `PublishOutputTests` asserts no `Csps.LegacyFitCheck*` file in the publish output; `docs/operations/ci.md` names the new tests.
