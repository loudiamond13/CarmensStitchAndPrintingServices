# Phase 7.1 Plan 03: Column inventory and draft mapping Summary

**Every column of the seven in-scope legacy tables is now accounted for: a run reads INFORMATION_SCHEMA.COLUMNS inside the read window and lists each column as mapped, not mapped with a reason, unknown (cannot map) or missing (drift), and the provisional column map is written down in 07.1-DRAFT-MAPPING.md.**

## Accomplishments

- Tracer (D-05, D-09): the run reads the column list for schema `dbo` through a keyless LINQ view, passes it to `ColumnInventory.Check`, adds the findings and the line "Column inventory: 43 columns read, 0 unknown, 0 missing" (counts for the standard fake). Console output is unchanged: counts and a relative path only.
- `DraftColumnMap` holds 58 entries over Orders, OrderItems, Payments, Discounts, Expenses, OrderTypes and Statuses. The people tables sit in their own list with the reason "read only to match people (D-09)" and are left out of the inventory.
- `ColumnInventory.Check` is pure and case-insensitive. An unknown column gives CannotMap `column.unknown`, a mapped column the restore lacks gives CannotMap `column.missing`, and each present not-mapped column gives its own finding (`column.not-mapped`) with its reason and type. Findings carry table and column names and the data type, never a value. Tables outside the seven are ignored.
- The read model grew to payments, discounts, expenses, `IsDone`, and the three people tables. Money is read as SQL `money` and dates as `datetime`, and a test proves 12345.6700, 0.0100, 0.0001 and 99999.9999 and times of day come back equal.
- 07.1-DRAFT-MAPPING.md (D-04) carries the provisional banner, the scope, one column table per in-scope table that matches `DraftColumnMap`, and an empty "Value rules" section for plans 04, 05 and 08. Tables, columns and list words only.
