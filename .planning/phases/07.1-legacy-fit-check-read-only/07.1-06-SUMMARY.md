# Phase 7.1 Plan 06: Every-rule probe and totals comparison Summary

**Each legacy order now lists every rule it breaks (not just the first) by running the public Order.Import on isolated parts, with every relaxation it relies on and every stored total that differs from the CSPS math by even one centavo.**

## Accomplishments

- Tracer (D-03): a made-up order whose first item has a price with four decimals and whose payment is 0.0000 reports a RuleBreak on `items[0].unitPrice`, a RuleBreak on `payments[0].amount` and a ReliesOnRelaxation `ContactNumberOptional`, while the trial import of the same order reports only its own first failure (`items[0].unitPrice`). The tracer `<verify>` was re-run end to end before expanding: 7 of 7.
- `NeutralOrder`: made-up customer, contact number, one 1.00 item, people set to the Legacy holder, every date equal to the order date (or the business today when the order date is later). A test proves it passes `OrderImportRules.Strict` for four order dates.
- `ProbeFlags`: 14 rows (Details 4, Child 2, Figures 5, Handler 3). A reflection test fails if a bool is added to `OrderImportRules` and left out, or if a row changes more than its own property.
- `OrderRuleProbe`: the details part is split into nine groups (customer name, team, contact number, email, address, notes, number, the two dates together, status with history), then one part per item, discount, payment, refund and order expense (the path is moved back to the child's real index), then a figures part (real amounts, quantities, kinds, counts and status; neutral text, dates and people). A structural break in the figures part gives one `figures.not-judged` and no figure-flag findings. A child-scope flag is never probed on the figures part, so one cause is counted once (a test counts exactly one `IgnoreAmountCaps`).
- `TotalsComparer`: `Compare` pairs Total with TotalAmount, Discount with TotalDiscount, Paid with PaidAmount, Balance with TotalBalance and Expenses with TotalExpenses by decimal equality (12.3400 equals 12.34). Each difference is a `TotalMismatch` with the rule key `totals.total`, `totals.discount`, `totals.paid`, `totals.balance` or `totals.expenses`, a message with no digits, and both amounts only in Detail. A null stored total is `CannotMap totals.no-stored-total` and the other four are still compared. `Check` runs `Order.Import(Default)` in memory and gives `NotJudged totals.not-compared` when it fails.
- `FitCheckRunner` probes and compares every mapped order with the `ToolCalendar` clock after the read window and before the trial import. The console is unchanged (counts and the relative path only).

## Notes and open questions for the owner and later plans

- **Limit, as planned:** within one field only the first message shows (a contact number that is too long and has a bad character gives one RuleBreak). Figure rules of an order with a structural break are NotJudged.
- **Open question (not decided here):** a discount above the subtotal makes the total, and so the balance, negative. With only the overpaid relaxation off, that order also fails, so it shows both `AllowDiscountAboveSubtotal` and `AllowOverpaid`. This is what the import does, and a test records it. The owner may want the summary to say so in the D-10 session.
- **Open question:** `AllowRetiredListEntries` and `AllowInactivePeople` have no count yet. Only the Legacy holder is counted (plan 05). The trial import uses active entries and active trial staff, so neither relaxation is exercised by the draft mapping. This is a real gap for plan 09 or 10 to state or close.
- **Counts:** probe findings carry `RecordKind.Order` and the order's key, so "distinct records per group" counts orders, not children. `Path` shows which child. `DueDateOptional` and `ContactNumberOptional` will appear for every order, because the draft mapping leaves both empty (legacy has neither). That is expected, not a fault.
- **Totals:** orders where the draft mapping leaves a row out (a deleted payment, an order expense with no date) can show a totals mismatch for that reason. The finding for the left-out row is on the same order.
- **Plan 09** can group RuleBreaks by RuleKey (a code word plus a domain message, never data) and ReliesOnRelaxation by flag name.
