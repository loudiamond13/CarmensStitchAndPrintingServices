# Phase 7.1 Plan 04: Order parts, lists and dates mapping Summary

**Every legacy order now maps with all its parts into an import snapshot and imports into the trial database; each value with no CSPS place is a finding, unmatched order types become trial-only product types, and dates are read as UTC moved to Asia/Manila with a count of records where the as-stored reading differs.**

## Accomplishments

- Tracer (D-04, D-06): a made-up order with an unmatched order type, two items, a discount, one live and one deleted payment, and one order expense (plus a company expense) imports into the trial database. A test reads the trial database before it is dropped and finds 2 items, 1 discount, 1 payment and 1 expense, with the items on the trial-only product type "Fixture Garments".
- `ListMatching.ForProductTypes` matches order type words by name (trimmed, case-insensitive) to the six CSPS product types. A miss gives one trial-only entry per distinct word. Payments always get the one trial-only "Unknown (legacy)" method; order expenses use Others.
- `TrialSeeder.SeedListsAsync` writes the trial-only entries through the domain factories on the trial `CspsDbContext` only, keeping the id the snapshots point at.
- `DraftMapping.MapOrder` reads the status names (Open, In Progress, Completed, any case), builds the number `ORD-{Manila year}-{id}`, and reports: `order.no-number`, `order.no-status-history`, `order.status-unknown`, `order.no-date`, `order.deleted`, `item.done-flag`, `discount.giver`, `payment.no-method`, `payment.deleted-dropped`, `payment.payer-text-in-notes`, `order-expense.no-category`, `order-expense.no-date`, `list.product-type`, `list.name-too-long`, `list.name-blank` and `dates.reading-differs`.
- `LegacyDates` reads a stored datetime as UTC and gives the Manila date, the as-stored date, and whether they differ. Stored 2025-12-31 16:30 reads as 2026-01-01 in Manila.
- The "Value rules" section of 07.1-DRAFT-MAPPING.md now has one row per rule, matching the code.
