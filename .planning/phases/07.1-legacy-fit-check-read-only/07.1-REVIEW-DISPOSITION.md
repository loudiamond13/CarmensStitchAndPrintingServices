# Phase 7.1: Code review disposition

*Created: 2026-10-29T12:55:00-05:00 · Updated: 2026-10-29T12:55:00-05:00*

Every finding in `07.1-REVIEW.md` has a recorded outcome. Per the owner's ruling D-43, CR-01 and WR-01 to WR-04 were fixed test first. IN-01 to IN-04 are deferred to Phase 15.

| Finding | Outcome | Commits | Note |
|---------|---------|---------|------|
| CR-01: path-escape tests use Windows backslashes | fixed | `0c5aba18` | The escape cases now use `/`, which both Windows and Linux treat as a separator. The backslash forms are kept in a separate test that runs on Windows only. This is a test-only fix, so there is no separate RED commit: the old cases already passed on Windows. |
| WR-01: summary prints rule keys that embed domain messages | fixed | `f494c9ee` (RED), `c9ef6307` | A rule key with no label now shows only its field name ("Rule break on X (message in the local list)"), or the fixed line "Other rule break (message in the local list)". The message never reaches the summary. The privacy self-check also refuses any peso sign. Proven with real domain messages that hold peso amounts. |
| WR-02: "mapped column missing" finding can never appear | fixed | `569452d1` (RED), `ba34e83f` | The column list is read right after the first write evidence. If a mapped column is missing, no table is read and no trial database is created. The `column.missing` findings go to the `_local` list, and the run prints "Failed: mapped columns missing from the restore: N. No table was read." The fake restore can now leave a mapped column out. |
| WR-03: no-raw-SQL source scan has gaps | fixed | `700cdba2` (RED), `cd382f62` | The scan now bans `SqlCommand` in any form (target-typed `new(...)` and fully qualified), `CreateCommand(`, `ExecuteReader` and a raw `SqlConnection`. Only `ReadOnlyCommandGuard.cs` may name `DbCommand`. Block comments are now tracked, so a code line that starts with `*` is scanned. Each new pattern has a planted sample in the test. |
| WR-04: write evidence silently drops its index-update check | fixed | `d4d3da96` (RED), `c03719bd` | The database id lookup throws unless the server lists exactly one match. The id stays an `int`, and the index usage id is widened for the compare, so nothing is narrowed and no range check is needed. A test also checks that an insert raises the index update count. |
| IN-01: "could not be removed" shows when the trial was never created | deferred | none | Deferred to Phase 15 by owner ruling 07.1 D-43. Only the wording of a rare failure is affected (the server cannot be reached before the trial database exists). It causes no data or safety risk. |
| IN-02: trial staff name split assumes a space | deferred | none | Deferred to Phase 15 by owner ruling 07.1 D-43. This is latent: the pseudonym is always "Legacy staff N" today. Phase 15 reshapes the staff mapping (D-33). |
| IN-03: description null handling is not consistent | deferred | none | Deferred to Phase 15 by owner ruling 07.1 D-43. This is a style issue only: the columns are NOT NULL today. Phase 15's schema document settles which fields can be null. |
| IN-04: the tool's pure tests run only in CI full mode | deferred | none | Deferred to Phase 15 by owner ruling 07.1 D-43. Changing the CI test layout is optional. The guards still run in Full mode and in every local test run. |
