<domain>
## Phase Boundary

A read-only check, run by hand, that tests the legacy data in `CSPS_Legacy_Restore` (17 tables, 988 rows, restored in 03-18) against the rules built so far:

- **Legacy orders** (with their items, payments, refunds, discounts, expenses and status history) go through `Order.Import` and `ImportOrderHandler` in a trial import.
- **Legacy company expenses** go through the Phase 6 expense rules, report only (D-11, D-12).

It lists every record that breaks a rule, every value it cannot map, every unmatched list entry or person, and every legacy total or balance that differs from the CSPS math. Then the owner rules on each group of findings, and the approved import relaxations are built test first in this phase.

It never derives the schema, never writes to the restore and never restores over `CSPS_Dev` (07 D-33). It adds no requirement, no screen and no deployed code. Phase 7 and Phase 7.1 ship together as one PR (D-13).

</domain>

<decisions>
## Implementation Decisions

### Where the findings go
- **D-01:** **The full findings list stays only in git-ignored `_local/`**, beside the restore receipt. It holds real customer names, phones, order numbers and notes, so it must never be committed, uploaded or deployed. (owner, 2026-10-29) — **Reversibility:** one-way — anything committed to this public repo cannot be recalled.
- **D-02:** **The committed summary in this phase folder (`07.1-FINDINGS.md`) shows counts per rule and no data:** no customer or staff names, phones, emails, notes, order numbers or legacy row ids. Legacy **list values** (product type, payment method and category names) may be named, because they are shop words and not personal data. People's names never appear (D-08). (owner, 2026-10-29)
- **D-03:** **Each record reports every rule it breaks**, not just the first. This matches how `Order.Import` already returns all failures together in one 400. (owner, 2026-10-29)

### How far to map legacy data
- **D-04:** **This phase builds a best-guess draft mapping, clearly marked provisional.** It only has to be good enough to run the check. Phase 15 still writes the real `LEGACY-MAPPING.md` and the owner signs it off there. Phase 16 may reuse the code but is not bound by it. (owner, 2026-10-29)
- **D-05:** **A legacy column or value with no clear meaning or place is reported as "cannot map"**, its own finding type beside the rule breaks. The check never guesses in a way that hides a problem. These findings become Phase 15's questions for the owner. (owner, 2026-10-29)
- **D-06:** **The lists and people are checked too.** Legacy product types, payment methods, order expense and company expense categories, and the staff named as receivers, refunders or payers, are matched against the new lists and staff. Unmatched ones are reported. People who cannot be matched use the "Legacy / unassigned" holder (07 D-37) in the trial import, and how often that happens is counted. (owner, 2026-10-29)

### How the check runs
- **D-07:** **Orders go through a trial import into a temporary test database.** The check creates a fresh, migrated `CSPS_Test_<guid>`, seeds the lists and staff the draft mapping needs, imports every legacy order with `ImportOrderHandler`, and drops the database at the end, even on failure. This catches what the real import would hit: missing lists, unknown people, duplicate order numbers and the counter lift. `CSPS_Dev`, `CSPS_E2E` and the restore are never written. The restore is only read. (owner, 2026-10-29)
- **D-08:** **Legacy totals and balances are compared with the CSPS math.** Any order whose stored legacy total, paid amount or balance differs from what CSPS computes, even by ₱0.01, is listed (amounts in `_local/` only, a count in the summary). Phase 16 still owns the full 100% reconciliation. (owner, 2026-10-29)
- **D-09:** **Coverage is orders with all their parts, plus company expenses** (D-11). Users, site content, images and the remaining tables wait for Phases 15 and 16. (owner, 2026-10-29)

### What happens after the findings
- **D-10:** **The owner rules on each group of findings in this phase.** Each group is brought to the owner in plain words with 2 or 3 options, for example: relax the import rule, clean it up in Phase 16, or accept as is. Each answer becomes a dated ruling in this file. This settles the open items before Phase 8: 07 D-40 (a database check on the discount cap) and 07 D-47 (relaxations for contact-number characters, email shape and a due date before the order date). (owner, 2026-10-29)
- **D-11:** **An approved new import relaxation is built in this phase, test first.** It is a named flag on `OrderImportRules` with a failing test first. The check is then re-run to show its count dropping. No relaxation is added without an owner ruling. (owner, 2026-10-29)
- **D-12:** **Legacy company expenses are checked against the existing Phase 6 rules (amount, date, category, payer), report only.** No company expense import path is built. Phase 16 decides whether expenses need one with relaxations, like orders. (owner, 2026-10-29)

### Shipping
- **D-13:** **Phase 7 and Phase 7.1 ship together as one PR** from `gsd/phase-07-order-domain-api`. Phase 7's security and UI reviews are already done (07-SECURITY.md verified, 07-UI-REVIEW.md). (owner, 2026-10-29)
- **D-14:** **Phase 7.1 gets a code review and a security review before the joint ship. It gets no UI review because it has no screens.** The security review checks that the restore is only read, that nothing writes outside the temporary test database, and that no personal data reaches git or the logs. (owner, 2026-10-29)
- **D-15:** **The joint PR opens only after the D-10 rulings and the D-11 relaxations are in**, so Phase 8 starts on a settled base. Merging still goes only through `tools/scripts/Merge-PullRequest.ps1` on the owner's word (D-08 merges). (owner, 2026-10-29)
- **D-16:** **The roadmap goal is reworded to add company expenses** (approved wording): "...a read-only check runs the legacy orders in CSPS_Legacy_Restore through Order.Import's rules and the legacy company expenses through the Phase 6 expense rules, and lists every record that breaks them..." The rest of the goal stays the same. (owner, 2026-10-29)

### Execution rulings
- **D-17:** **Go-ahead for the real fit-check run and its re-runs: yes, Claude runs it now (option-a)** after the preflight, and shows the owner only the counts file. The same go-ahead covers the re-runs after each relaxation approved in plan 07.1-12. (owner, 2026-10-29)
- **D-18:** **The summary privacy self-check stays strict as built**: a plain substring match on read values of 3 or more characters. If it refuses the summary on the real run, the owner rules on loosening it then (whole words only, or a 4-character minimum). (owner, 2026-10-29)
- **D-19:** **Legacy expense rows whose `OrderId` points at an order missing from the restore are counted too**, as their own counts-only finding, separate from D-87's rows with no `OrderId`. Built before the real run. (owner, 2026-10-29)
- **D-20:** **D-13 stands with one change of branch**: the joint Phase 7 and 7.1 PR opens from `gsd/phase-07.1-legacy-fit-check-read-only`, which is stacked on the Phase 7 branch and so holds both phases (see STATE D-85). (owner, 2026-10-29)
- **D-21:** **The summary privacy self-check matches whole words only** (replaces the substring rule kept in D-18): a read value of 3 or more characters refuses the summary only when it appears as a whole word, not inside another word. Ruled after the first real run (plan 07.1-10) refused the summary. Built test-first, then the check runs once more under D-17. (owner, 2026-10-29)

### Claude's Discretion
- **The tool's form:** a `tools/` console project, like `Csps.DevSeed`, or a manual-only test that CI never runs. It must not be part of the deployed package.
- **How the restore is opened read-only:** for example `ApplicationIntent=ReadOnly`, a login or connection with read rights only, and a fixed database name (no parameter), like `Restore-LegacyReceipt.ps1`.
- **How the draft mapping is written up:** a `07.1-DRAFT-MAPPING.md` in this folder that names legacy tables and columns but no data.
- **The finding types and the summary layout**, as long as D-02 and D-03 hold.
- **The order of the findings groups** shown to the owner for D-10.

## Existing Code Insights

### Reusable Assets
- `src/Csps.Application/Orders/ImportOrderHandler.cs`: already documented as the entry point for the 7.1 check. It checks the order, then the lists and people, then the number, and returns every failure together.
- `src/Csps.Domain/Orders/OrderImportSnapshot.cs` and `OrderImportRules.cs`: the input shape and 14 named relaxations (`KeepLegacyNumber`, `DueDateOptional`, `ContactNumberOptional`, `AllowOverpaid`, `AllowCompletedWithBalance`, `AllowDiscountAboveSubtotal`, `IgnoreAmountCaps`, `AllowFutureDates`, `AllowRetiredListEntries`, `AllowLegacyHolder`, `AllowInactivePeople`, `AllowAnyStatusHistory`, `IgnoreChildCaps`, `AllowNoItems`). D-11 relaxations are added here.
- `src/Csps.Domain/Identity/LegacyHolder.cs`: the fixed-id "Legacy / unassigned" holder.
- `tests/Csps.Testing/CspsDatabase.cs` and `TestDatabaseName.cs`: create, migrate and drop `CSPS_Test_<guid>`, with the only allowed drop pattern `^CSPS_Test_[0-9a-f-]{36}$`. A natural fit for D-07.
- `src/Csps.Application/Expenses/CreateCompanyExpenseRequestValidator.cs` and `CreateCompanyExpenseHandler.cs`: the Phase 6 rules for D-12.
- `src/Csps.Infrastructure/Seeding/DevSeedTargetGuard.cs` and `tools/scripts/Restore-LegacyReceipt.ps1`: patterns for fixed database names and refusing any other target.

### Established Patterns
- Tools that touch databases use fixed names, not parameters, and refuse every other target before a connection opens.
- The receipt-style output goes to `_local/` with a timestamp line and never echoes connection strings.
- Every phase's code is TDD with zero warnings. The trial import's drop must run in a finally path.

### Integration Points
- It reads `CSPS_Legacy_Restore` on `(localdb)\MSSQLLocalDB` only. Run the preflight script before using LocalDB.
- It writes only the temporary `CSPS_Test_<guid>`, `_local/`, and the committed counts-only summary.

</code_context>
