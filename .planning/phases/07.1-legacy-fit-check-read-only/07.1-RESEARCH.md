# Phase 7.1: Legacy Fit Check (read-only) - Research

*Created: 2026-10-29T06:58:00-05:00 · Updated: 2026-10-29T06:58:00-05:00*

**Researched:** 2026-10-29
**Domain:** Read-only legacy data check: EF Core read model over a restored SQL Server database, a throwaway migrated test database, the Phase 7 import path and the Phase 6 expense rules
**Confidence:** HIGH for the codebase and the legacy schema (read this session); MEDIUM for the draft mapping (it is provisional by design, D-04)

## Summary

The legacy database `CSPS_Legacy_Restore` is reachable on `(localdb)\MSSQLLocalDB`, and its schema was read this session from catalog views only. It is **much thinner than the CSPS order shape**. It has no order number, no customer contact, email, address or due date, no payment method, no expense category, no refunds and no status history. Orders carry stored totals (`TotalAmount`, `PaidAmount`, `TotalDiscount`, `TotalBalance`, `TotalExpenses`), and a raw SQL recount this session says every one of the 91 orders agrees with its own children. So the expected findings are mostly **"cannot map" findings** (D-05), such as missing payment methods, missing categories and no order number. Few or no **rule breaks** are expected. Phase 7's open items look settled by the data: 07 D-47's contact, email and due-date relaxations have no legacy field to act on, and no legacy order has discounts above its items total (07 D-40).

One premise in CONTEXT D-03 is **only half true**. `ImportOrderHandler` returns every **list and person** failure together. But `Order.Import` (and `OrderImportChecks.Check` under it) returns **only the first broken field**, and when it fails the handler stops before the reference checks. To meet D-03 ("every rule it breaks"), the tool must **probe**: it runs the public `Order.Import` on isolated parts of each order, under the default rules and under the default rules with one relaxation off at a time. This needs no Domain change.

**Primary recommendation:** Build a console tool `tools/Csps.LegacyFitCheck` (never deployed, like `Csps.DevSeed`) with a test project `tests/Csps.LegacyFitCheck.Tests`.

- **Reading the restore:** it reads through an EF Core LINQ-only read model, behind a layered read-only guard: a fixed connection string, a command interceptor that refuses anything but `SELECT`, `SaveChanges` that always throws, a transaction that is always rolled back, and a before and after write check.
- **Orders:** it builds `OrderImportSnapshot`s from a provisional draft mapping, probes every rule, then runs `ImportOrderHandler` with `OrderImportRules.Default` into a fresh migrated `CSPS_Test_<guid>`. That database is dropped in `finally`.
- **Company expenses:** it checks them with `CreateCompanyExpenseRequestValidator` plus the handler's two reference checks, and saves nothing.
- **Output:** full findings go to `_local/` only. A counts-only summary is written to `_local/` first, self-checked for personal data, then copied into `07.1-FINDINGS.md`.

#### How far to map legacy data
- **D-04:** **This phase builds a best-guess draft mapping, clearly marked provisional.** It only has to be good enough to run the check. Phase 15 still writes the real `LEGACY-MAPPING.md` and the owner signs it off there. Phase 16 may reuse the code but is not bound by it. (owner, 2026-10-29)

#### How the check runs
- **D-07:** **Orders go through a trial import into a temporary test database.** The check creates a fresh, migrated `CSPS_Test_<guid>`, seeds the lists and staff the draft mapping needs, imports every legacy order with `ImportOrderHandler`, and drops the database at the end, even on failure. The restore is only read. (owner, 2026-10-29)
- **D-08:** **Legacy totals and balances are compared with the CSPS math.** Any order whose stored legacy total, paid amount or balance differs from what CSPS computes, even by ₱0.01, is listed (amounts in `_local/` only, a count in the summary). Phase 16 still owns the full 100% reconciliation. (owner, 2026-10-29)
- **D-09:** **Coverage is orders with all their parts, plus company expenses** (D-11). Users, site content, images and the remaining tables wait for Phases 15 and 16. (owner, 2026-10-29)

- **D-10:** **The owner rules on each group of findings in this phase.** Each group is brought to the owner in plain words with 2 or 3 options, for example: relax the import rule, clean it up in Phase 16, or accept as is. Each answer becomes a dated ruling in this file. ## The legacy database (read this session, metadata and counts only)

How it was read: `sys.*` catalog views and `INFORMATION_SCHEMA` for the shape, plus aggregate `COUNT`/`SUM` queries inside a transaction that was rolled back. No row value except **list-table names** (D-02 shop words) was printed. [VERIFIED: catalog query, 2026-10-29]

- **Database state:** `READ_WRITE`, `MULTI_USER`, compatibility level 150, snapshot isolation off, collation `SQL_Latin1_General_CP1_CI_AS`. The session login is `sysadmin` and `db_owner`, as on any LocalDB. **Read-only is not enforced by the engine or by permissions**, so the tool must enforce it (Pattern 2).
- **Legacy app:** ASP.NET Core with EF Core 8 (5 migrations in `__EFMigrationsHistory`, product versions 8.0.11 and 8.0.16) and a React SPA. Two stored procedures (`OpenOrdersSummary`, `OverAllPrintExpenses`). No triggers or views.
- **Row counts** match the 03-18 receipt: 17 tables, 988 rows.

Hour-of-day spread (UTC reading): order, payment and expense times cluster at 23:00 to 02:59 and around 14:00. That fits **UTC storage** of Manila working hours (7 to 11 AM and about 10 PM in Manila). The legacy SPA also serializes dates with `toISOString()`. So treating legacy `datetime` as UTC and converting to `Asia/Manila` before taking the date is the better guess. It is still a guess [ASSUMED], so the tool should count records whose date differs between the two readings (Pitfall 4).

The legacy `OpenOrdersSummary` procedure computes profit as `TotalAmount - TotalDiscount - TotalExpenses`. Since `TotalAmount` is already net of discounts, that **subtracts discounts twice**. Legacy stores no profit, so nothing needs comparing, but the owner should know that legacy "profit" reports ran low (an FYI finding for Phase 15).

### Pattern 2: A read-only restore you can trust (recommended layering)
`ApplicationIntent=ReadOnly` only routes connections in an Availability Group, so on LocalDB it does nothing [ASSUMED, standard SqlClient behavior]. Do not rely on it, and leave it out so nobody thinks it guards anything. Engine-level options all **write to the restore**. `ALTER DATABASE ... SET READ_ONLY` changes its metadata. A `db_datareader` user would have to be created inside it. A database snapshot needs Enterprise or Developer edition, not LocalDB/Express [ASSUMED]. All of these clash with "never writes to the restore" (07 D-33), so use these layers instead:

1. **Fixed target, checked before any connection opens:** `Server=(localdb)\MSSQLLocalDB; Initial Catalog=CSPS_Legacy_Restore; Integrated Security=true; Pooling=false; Application Name=Csps.LegacyFitCheck`. These are constants, not parameters, like `Restore-LegacyReceipt.ps1` and `DevSeedTargetGuard` [VERIFIED: src/Csps.Infrastructure/Seeding/DevSeedTargetGuard.cs:16-22]. `Pooling=false` keeps no idle connection that would block a later `Restore-LegacyReceipt.ps1 -Replace`.
2. **EF command interceptor (`ReadOnlyCommandGuard : DbCommandInterceptor`):** `NonQueryExecuting`/`ScalarExecuting` (sync and async) always throw. `ReaderExecuting` throws unless the trimmed command text starts with `SELECT` (case-insensitive). EF LINQ queries always start with `SELECT`. Unit-test the classifier as a pure function, and integration-test that `SaveChanges`, `ExecuteDelete` and `ExecuteUpdate` are refused.
3. **`LegacyDbContext.SaveChanges`/`SaveChangesAsync` overrides throw**, and `QueryTrackingBehavior.NoTracking` is the default.
4. **One transaction, always rolled back:** `BeginTransactionAsync(IsolationLevel.ReadCommitted)` and never commit. Disposing it rolls back, so a write that slipped past layers 2 and 3 is undone.
5. **Write evidence:** before and after the run, read the restore's per-table row counts (`sys.partitions`) and the sum of `user_updates` (`sys.dm_db_index_usage_stats` for the restore's `database_id`) through keyless entities mapped with `ToView`. Refuse to report success unless both are unchanged. Record both values in the `_local` findings file. The session showed `user_updates = 0` since the 06:46 instance start, so a non-zero delta is meaningful.

Option for the owner (not recommended without a ruling): `ALTER DATABASE CSPS_Legacy_Restore SET READ_ONLY` would add a real engine guard. It is a one-time metadata write, and the database can still be dropped and restored. Raise it only if the security review asks for it.

### Pattern 4: Isolate and probe (makes D-03 true for orders)
**Why:** `OrderImportChecks.Check` "returns the first broken rule" and `Order.Import` returns "a validation error naming the first broken field" [VERIFIED: src/Csps.Domain/Orders/OrderImportChecks.cs:46-57; src/Csps.Domain/Orders/Order.cs:324-345]. `ImportOrderHandler` runs the reference checks only after `Order.Import` passed [VERIFIED: src/Csps.Application/Orders/ImportOrderHandler.cs:43-54].
**How (pure, no DB):**
1. Split each order into **parts**: the details part (real details, status and history, plus one neutral item), then one part per child (neutral details, the one child, plus a neutral item when the child is not an item). Neutral values are made-up and valid: a fixed customer name such as "Neutral Customer", the order date, a product type id from `OrderListSeed`, and `LegacyHolder.Id` for people.
2. Add a **figures part** that keeps every amount, quantity, kind, count and the status but uses neutral text, dates and ids. It judges discount above subtotal, overpaid, Completed with a balance, oversized figures, child caps and no items.
3. For each part, run `Order.Import(part, OrderImportRules.Default, now, today)`. A failure is a **blocking break**: the migration rules refuse it, so it is a candidate for a D-11 relaxation or Phase 16 clean-up.
4. If the default run passes, run once per **domain-read flag** with that one flag off (`OrderImportRules.Default with { DueDateOptional = false }`, and so on). A failure means the record **relies on that relaxation**. Count it per flag (for example "orders with no due date: 91").
5. Do not probe the three **handler-read** flags (`AllowRetiredListEntries`, `AllowLegacyHolder`, `AllowInactivePeople`) through `Order.Import`, because it ignores them. Derive their counts from the mapping output instead, such as "payments using the Legacy holder: N".
6. Unit test with reflection: the probe's flag table covers every `bool` property of `OrderImportRules` (domain-read or handler-read). Then a D-11 flag cannot be forgotten.

**Limits to document in the summary:** within one field, only the first message shows (for example a too-long contact number hides a bad character). If a part's amounts break a structural rule, its figure rules are reported as "not judged". The 14 flags today [VERIFIED: src/Csps.Domain/Orders/OrderImportRules.cs:14-27]: `KeepLegacyNumber`, `DueDateOptional`, `ContactNumberOptional`, `AllowOverpaid`, `AllowCompletedWithBalance`, `AllowDiscountAboveSubtotal`, `IgnoreAmountCaps`, `AllowFutureDates`, `AllowRetiredListEntries`, `AllowLegacyHolder`, `AllowInactivePeople`, `AllowAnyStatusHistory`, `IgnoreChildCaps`, `AllowNoItems`.

### Pattern 7: Findings model and privacy
- `Finding(RecordKind, LegacyKey, Type, RuleKey, Path, Message, Detail)`. `Type` ∈ {`RuleBreak` (blocks Default), `ReliesOnRelaxation` (flag name), `CannotMap`, `UnmatchedList`, `UnmatchedPerson`/`LegacyHolderUsed`, `TotalMismatch`, `TrialImport` (400/422/409), `ExpenseRule`}.

### Anti-Patterns to Avoid
- **Printing `error.Message` of a database exception** (DevSeed does this). A unique-key violation message carries the duplicate value, such as an order number. Print the exception type only, and write details to `_local`.
- **One `DbContext` for all 91 imports.** Tracking piles up, and `CspsUnitOfWork` clears the tracker on failures. Use a scope per order.
- **Turning on `EnableSensitiveDataLogging` or adding a logger factory** to either context. Parameters would reach the console.
- **Seeding real staff names** into the trial DB. Use pseudonyms (see Pattern 5).
- **Writing the summary straight into `.planning/`.** Write it to `_local/`, self-check it, review it, run gitleaks, then copy.
- **Changing `OrderImportChecks` to collect all failures.** That is Phase 7 domain behavior with 100% branch coverage. The probe gives D-03 without it.

## Common Pitfalls

### Pitfall 1: Believing `Order.Import` returns every failure
**What goes wrong:** the summary under-counts. An order with a structural break never reaches the list, person or number checks.
**Why:** `OrderImportChecks.Check` returns the first broken rule, and the handler stops there (see Pattern 4 citations). CONTEXT D-03's "all failures together" is true only for the handler's reference checks.
**How to avoid:** isolate and probe (Pattern 4). Tell the owner about the premise in the D-10 session, in plain words.
**Warning signs:** an order with two known faults in a fixture reports one.

### Pitfall 2: A "read-only" flag that guards nothing
**What goes wrong:** `ApplicationIntent=ReadOnly` gives a false sense of safety on LocalDB. The session is `sysadmin`.
**How to avoid:** the five layers in Pattern 2, each with its own test. The write-evidence check is the proof the security review reads.

### Pitfall 3: The trial database survives a crash or holds the restore open
**What goes wrong:** a leftover `CSPS_Test_*`, or a pooled connection keeps `CSPS_Legacy_Restore` busy.
**How to avoid:** drop in `finally` after a name re-check. Use `Pooling=false` on the source and `SqlConnection.ClearAllPools()` before the drop (as `CspsDatabase.DisposeAsync` does). Test with an injected failure. For a hard kill, use `Remove-StaleTestDatabases.ps1`.

### Pitfall 4: Date shifts from `datetime` to `DateOnly`
**What goes wrong:** a legacy time like 16:00 to 23:59 UTC is the next day in Manila. Taking `.Date` of the stored value can move orders, payments and expenses by a day, including across a month or year boundary, which would also change a derived `ORD-YYYY` number.
**How to avoid:** one mapping function with both readings. Use the UTC → Manila reading for the trial, and count records whose date differs. The owner rules in D-10 (group 6) or Phase 15.

### Pitfall 5: Domain coverage gate breaks on a new relaxation
**What goes wrong:** a D-11 flag adds a branch that only `Default` exercises, and `Invoke-CoverageGate.ps1` fails (Domain 100% branch).
**How to avoid:** for each flag, write tests on both sides: Strict refuses with the create-path words, and Default accepts. Copy the shape of `tests/Csps.Domain.UnitTests/Orders/OrderImportTests.cs`. Update the XML docs on `OrderImportRules`, and set the flag `true` in `Default` and `false` in `Strict`.

### Pitfall 6: Personal data leaking through side doors
**What goes wrong:** names, order numbers or amounts reach the console (and so the AI transcript), exception text, EF logs, test output or a committed file.
**How to avoid:**
- Console prints counts and paths only.
- Catch blocks print the exception type only.
- No EF logging on either context.
- Pseudonymous trial staff.
- Summary self-check (Pattern 7).
- Test fixtures use made-up names only (`example.com`/`example.invalid`, no real people), because the repo is public.
- Run gitleaks plus a manual look before committing `07.1-FINDINGS.md`.

### Pitfall 7: New projects trip existing gates
**What goes wrong:** `SolutionLayoutTests.SlnxListsExactlyTheExpectedProjects` and `EveryProjectOnDiskIsListedInTheSolution` fail. The CI step lists test projects one by one, so a new test project silently never runs. The `.csproj` gets a `Version=` (central management forbids it).
**How to avoid:**
- Wave 0 adds both projects to `Csps.slnx` and `ExpectedProjects`.
- It adds the test project to the CI step `3 integration tests`.
- It keeps the `.csproj` files free of versions.
- It adds a `PublishOutputTests` assertion that no `Csps.LegacyFitCheck*.dll` is in the package.

### Pitfall 8: Committing the hosting database id or other infra names
**What goes wrong:** the original `.bak` file name in `_local` carries the hosting database id. 03-18 renamed the copy for exactly this reason.
**How to avoid:** the tool never reads or prints `.bak` names. Committed docs name only tables, columns, list values and counts.

```csharp
        {
            findings.AddReliesOn(key, flag, probe.Error);
        }
    }
}
```
