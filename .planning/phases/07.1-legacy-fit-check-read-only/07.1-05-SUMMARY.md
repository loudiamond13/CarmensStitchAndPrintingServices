# Phase 7.1 Plan 05: People matching Summary

**Receivers and order expense payers named in legacy rows now resolve by user name: a legacy Admin becomes a pseudonymous "Legacy staff N" trial Admin that passes the CSPS payer rule, and any other name uses the Legacy / unassigned holder with a counted reason.**

## Accomplishments

- Tracer (D-06): a made-up restore with one Admin user, one order, two payments (receivers: that user and an unknown name) and one expense (payer: that user) imports. The trial database holds exactly one staff account, "Legacy staff 1" with `legacy-staff-1@example.invalid`, and none of its fields hold the made-up user text. The first payment and the expense point at that account and the second payment points at the Legacy holder. The findings file has one `UnmatchedPerson person.unknown-name` and one `LegacyHolderUsed`.
- `PeopleMatching.Build` reads the legacy users, roles and role links. `Resolve` trims the text and matches the user name in any case. The outcomes are a trial staff id, or the holder id with `person.unknown-name`, `person.blank` or `person.role-no-match`.
- `DraftMapping` resolves `PaidTo` and the order expense `PaidBy` through `PeopleMatching`. It replaces the interim `person.legacy-holder` finding from plan 04 with the pair UnmatchedPerson plus LegacyHolderUsed, only when the holder is used.
- `TrialSeeder.SeedStaffAsync` writes one active Admin per trial staff member (password hash set, email confirmed, role link by LINQ on the role name). `TrialImport` runs it with the list seeding before the first import. `FitCheckRunner` builds `PeopleMatching` inside the read window.
- The People section of 07.1-DRAFT-MAPPING.md records each rule and finding, with no names.

## Deviations from Plan

**1. [Rule 1 - Bug] Placeholder password hash threw on verification**
- **Found during:** Task 2 RED.
- **Issue:** the Task 1 placeholder `legacy-fit-check-not-a-hash` is not valid base64, so `PasswordHasher.VerifyHashedPassword` throws `FormatException` instead of returning Failed. A sign-in attempt on a trial account would throw (T-07.1-15 says the hash "cannot verify").
- **Fix:** the placeholder is now `AAAA` (valid base64, too short to be a hash), with a one-line comment. The test pins that verification returns Failed.
- **Files modified:** `tools/Csps.LegacyFitCheck/Trial/TrialSeeder.cs`. **Commit:** a662f315.

**2. [Plan wording] Tracer reads the trial staff through `BeforeTrialDropped`**
- The plan names the `AfterTrialCreated` hook "after seeding". Seeding happens inside `TrialImport`, and `AfterTrialCreated` is used by the first test to capture the name. The test reads through `BeforeTrialDropped` instead, which sees the same staff and also the payment and expense ids the import wrote. No hook was moved.

**3. [Plan wording] `MapOrder` takes `PeopleMatching? people = null`**
- The parameter is optional and defaults to `PeopleMatching.Empty` (no one known, so every name uses the holder). The 25 existing mapping and list tests did not need to change. The runner always passes the real matching, and the tracer test covers that.
