    `OrderStatusRules.Check(OrderStatus from, OrderStatus to, decimal balance)` returns `Result<OrderStatusMove>` (NoChange, Move, Reopen):
    - every pair of active statuses (25 pairs) -> Move, or NoChange when equal;
    - any active -> Cancelled -> Move;
    - any active -> Completed with balance 0.00 -> Move; 0.01 -> orders.complete-balance-owed naming ₱0.01; -0.01 -> orders.complete-credit naming ₱0.01;
    - Completed or Cancelled -> any active -> Reopen (no balance check);
    - Completed -> Cancelled and Cancelled -> Completed -> orders.reopen-first with the two messages;
    - Completed -> Completed and Cancelled -> Cancelled -> NoChange;
    - an undefined value (0 or 8) on either side -> ArgumentOutOfRangeException.
    `OrderStatusRules.IsActive`, `IsLocked` for all seven. `Pesos.Format(9327.5m)` -> "₱9,327.50"; `Pesos.Format(1000000m)` -> "₱1,000,000.00" (invariant grouping, two decimals).
  </behavior>
  <implementation>`OrderStatus : byte` with the explicit values in the truths (research A1; never renumbered). `OrderStatusMove` enum. `OrderStatusRules` static class with the error codes and messages as public constants (the endpoint and docs reuse them) and a static `ActiveStatuses` list. `Pesos.Format(decimal)` uses "N2" with the invariant culture and a leading peso sign, for every domain message that names an amount.</implementation>
</feature>
