# Plan 09-24: A permanent order delete, or a failed upload save, queues the storage removal reliably

*Created: 2026-10-31T18:00:00-05:00 · Updated: 2026-10-31T11:52:00-05:00*

> MVP note: the ROADMAP Goal line for Phase 9 is not in user-story form. No story was invented.

<objective>
The removal queue that makes storage cleanup reliable: a permanent order delete writes one queue row per photo in the same transaction as the delete, and an upload whose save fails queues its own file for removal on a separate short context. The monthly job (plan 09-28) works the queue; deleting one photo (plan 09-26) uses the same queue.

Purpose: JOB-02 "image deletions are queued in the same transaction as the business change", D-20, and IMG-01 (no file left in Cloudinary without a record).
Output: the queue port, row, configuration, migration and adapter, the permanent-delete enqueue loop, the upload compensation and tests.

Split note (revision 2026-10-31, plan budget): this was Tasks 2 and 3 (queue half) of the original plan 09-19; the photo delete endpoint is plan 09-26.

Phase goal (ROADMAP, verbatim): "Staff can attach, arrange and view order photos, including straight from a phone camera. The photos load fast and stay private per the OD-9 ruling. Storage cleanup and token purges run as short, reliable, scheduled jobs."
</objective>
