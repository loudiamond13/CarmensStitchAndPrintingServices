# Phase 9: UI Design Contract (Order Images and Maintenance Jobs)

*Created: 2026-10-31T09:15:00-05:00 · Updated: 2026-11-06T07:41:04-06:00*

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Owner conventions apply to everything below** (`.claude/CLAUDE.md` → Conventions): components from `@/components`; module code in `web/src/modules/admin/` (`pages/`, `components/`, `hooks/`, `services/`, module-wide copy and schema files); no em dash or en dash in any client string, `aria-label`, `title` or `alt` (OR-4); a missing value renders `EmptyValue`, never a dash; every form and every file pick runs a zod schema that mirrors the API validator and shows its message before any request is sent (OR-3); API calls live in per-module services and only `core/api/http` touches `fetch` (OR-5); the owner layout tree (OR-6). Strict CSP: no inline `style` attribute or inline script, and **`img-src` stays `'self' data: https://res.cloudinary.com`** (no `blob:`; previews are `data:` URLs, as the Phase 2 UI-CR-01 fix already does).

**What this file is.** The phase-scoped contract for order photos: the Images card on the New Order form (F1) and on the order page (O1), its read-only form on Completed and Cancelled orders and on the Manager's deleted order view (X2), the photo viewer, the photo description window, the delete-photo dialog, the upload queue and its failures, the phone camera buttons, the cover thumbnail on the Orders list (L1 grid card and table), and the image delivery sizes. The maintenance jobs (JOB-01, JOB-02) have **no screen** (D-22); this file only fixes the plain-English wording of the GitHub run summary the owner reads. It creates **no new design token, color, font, font size or weight**. `CSPS-UI-SPEC.md` ("the spec") stays the visual source of truth with its precedence (Appendix, then tables, then prose). `02-UI-SPEC.md` ("P2") stays binding for the Tailwind contract, recipes and the interaction contract; `05-UI-SPEC.md` ("P5") for ConflictBanner, the row-action spacing (05 D-51) and motion (05 D-37 to D-39); `08-UI-SPEC.md` ("P8") for every order screen this file does not change. This file only adds what Phase 9 needs.

References: "§6.3" and "App. D.3" point into `CSPS-UI-SPEC.md`; "D-01" into `09-CONTEXT.md`; "08 D-27" into `08-CONTEXT.md`; "07 D-26" into `07-CONTEXT.md`; "P2", "P5", "P8" into the earlier UI-SPECs.

**Control sizes:**
- Every photo action is a 44 × 44 icon button (`Button size="md"` icon, `w-11 h-11`) or a 44px-tall text button. No 28px overlay button remains (App. B `.csp-thumb-btn` is retired here; SPEC-DEVIATION OD-14, D-13, CLAUDE.md "touch targets ≥ 44 px").
- "Make Cover", "Try Again" and "Remove" inside a tile are `size="sm"` (36px drawn) with the existing invisible 44px tap area (`button.recipe.ts`, WR-20 pattern); nothing else sits within 4px above or below them, so tap areas never overlap.

- Viewer: Close 44 × 44 (App. C `.s-lb-close`); Previous and Next 56 × 56 above 639px (App. C `.s-lb-nav`) and 44 × 44 on phones (below the image, D-16); "Open Full Size" 44px tall.

### Client preparation of each file (D-18, IMG-05, OR-3)

`prepareImage` runs per file, in pick order, before a file becomes a tile:
1. Read the first bytes and **sniff the type** (JPEG, PNG, WebP, HEIC/HEIF signatures); anything else, SVG included, is refused with the type message. The file name and the browser's MIME type are not trusted.
2. Decode with `createImageBitmap` (EXIF orientation applied, so the photo is upright).
3. **Downscale** to a 2000px long side when larger, keeping the format family (JPEG stays JPEG, PNG stays PNG, WebP stays WebP; the encoder settings are the planner's). A file already within 2000px is sent as it is (D-18).
4. Check the size (≤ 10 MB after preparation) and the pixels (≤ the server's max).
5. Make the 176px `data:` preview.
- **HEIC the browser cannot decode** (most desktop browsers): steps 2, 3 and the pixel check are skipped; the file is sent as it is if it is within 10 MB (the server checks pixels; § Validation marks it server-only). The tile shows `MediaPlaceholder` and the Small line "No preview. It shows after upload." *(SPEC-GAP)*.
- **Upright photos:** the server must also apply EXIF orientation before stripping metadata, so a phone photo that skipped downscaling never arrives sideways (UI truth; a rotated fixture proves it).
