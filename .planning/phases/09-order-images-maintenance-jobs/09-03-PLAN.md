# Plan 09-03: Prepare a photo in the browser before upload

*Created: 2026-10-31T18:00:00-05:00 · Updated: 2026-10-31T11:52:00-05:00*

> MVP note: the ROADMAP Goal line for Phase 9 is not in user-story form. No story was invented.

<objective>
A pure, fully tested `prepareImage` that checks a picked or captured file by its bytes, turns it upright, downscales it to a 2000 px long side when it is larger, and makes a small `data:` preview, all before any request is sent.

Purpose: IMG-05 (phone camera photos are downscaled client-side) and D-18 (every upload, camera or gallery, is downscaled; a file within the size is left as it is), plus the OR-3 mirror of the server's type and size rules so a refused file never becomes a tile. Plan 09-16 calls it from the upload queue; plan 09-21 from the new-order form.
Output: `web/src/utils/images.ts` and its tests. No new package.

Phase goal (ROADMAP, verbatim): "Staff can attach, arrange and view order photos, including straight from a phone camera. The photos load fast and stay private per the OD-9 ruling. Storage cleanup and token purges run as short, reliable, scheduled jobs."
</objective>

<feature>
  <name>prepareImage: sniff, upright, downscale, preview</name>
  <files>web/src/utils/images.ts, web/src/utils/images.test.ts</files>
  <behavior>
    - sniff: each of the four signatures is accepted; `<svg`, `GIF89a`, an ftyp with brand avif, BM and 32 zero bytes are null; a HEIC header in a file named photo.png is heic.
    - A 4000 x 3000 JPEG (fake decode) gives a 2000 x 1500 image/jpeg from encode at 0.85 and a preview; a 1800 x 1200 JPEG returns the same File object and a preview.
    - A 3000 x 4000 PNG gives 1500 x 2000 image/png; a WebP whose encode yields image/png falls back to JPEG.
    - A HEIC whose decode rejects: returned unchanged when within maxBytes with preview null and previewUnavailable true; over maxBytes gives reason size.
    - A JPEG whose decode rejects gives reason unreadable; a decoded 6000 x 5000 photo with maxPixels 25,000,000 gives reason pixels; an encoded result over maxBytes gives reason size.
    - The fake bitmap's close is called on success and on every failure after decode.
  </behavior>
  <implementation>Pure core over the injectable `BrowserImageParts`; the default parts use `file.slice(0, 32).arrayBuffer()`, `createImageBitmap(file, { imageOrientation: 'from-image' })`, an offscreen `canvas` with `imageSmoothingQuality = 'high'` and `toBlob`, and a second small canvas `toDataURL` for the preview.</implementation>
</feature>
