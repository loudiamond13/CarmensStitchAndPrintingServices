# Plan 09-15: Location and camera data never reach Cloudinary

*Created: 2026-10-31T18:00:00-05:00 · Updated: 2026-10-31T11:52:00-05:00*

> MVP note: the ROADMAP Goal line for Phase 9 is not in user-story form. No story was invented.

<objective>
A hand-written, byte-level metadata stripper for JPEG, PNG, WebP and HEIC (no decoding, no package), wired into the upload so the stored copy is clean even if an address leaks.

Purpose: D-02 (GPS and camera data stripped before the file reaches Cloudinary) and IMG-03 (EXIF/GPS stripped; Cloudinary's delivery strip is the second layer). RESEARCH calls this the riskiest code in the phase, so it gets its own TDD plan with synthetic fixtures. Plan 09-19 (real Cloudinary uploads) depends on this plan.
Output: `ImageMetadataStripper`, the handler step, fixtures and tests.

Phase goal (ROADMAP, verbatim): "Staff can attach, arrange and view order photos, including straight from a phone camera. The photos load fast and stay private per the OD-9 ruling. Storage cleanup and token purges run as short, reliable, scheduled jobs."
</objective>

  <behavior>
    - JPEG with every metadata block and orientation 6: output starts FF D8, has no 'Exif' block except a minimal one with Orientation 6 and no GPS tag, no 'http://ns.adobe.com/xap' text, no APP13, no COM, ends at the first EOI, keeps the ICC APP2 and the scan bytes identical; re-sniffing gives the same size and orientation 6.
    - JPEG with orientation 1: no APP1 at all in the output.
    - PNG: none of the dropped chunk types remain; kept chunks identical including CRC; re-sniff gives the same size.
    - WebP: no EXIF or 'XMP ' chunk, VP8X flags cleared, RIFF size equals file length minus 8, re-sniff gives the same size.
    - HEIC: the Exif and XMP item payload regions are all zero bytes, file length unchanged, every other byte unchanged, re-sniff gives the same size; an iloc with construction method 2 is refused.
    - Strip of each stripped output is byte-identical (idempotent).
  </behavior>
  <implementation>One static class with a private method per kind over a bounded reader shared with the sniffer's approach (caps on segments, chunks and boxes); output built in one pre-sized buffer. The minimal Exif block is a fixed TIFF header (big or little endian) with one IFD0 entry (tag 0x0112, SHORT, count 1).</implementation>
</feature>
