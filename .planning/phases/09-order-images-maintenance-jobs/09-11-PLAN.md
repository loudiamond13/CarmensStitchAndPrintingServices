# Plan 09-11: One run at a time, failures isolated, long work split across calls

*Created: 2026-10-31T11:52:00-05:00 · Updated: 2026-10-31T11:52:00-05:00*

> MVP note: the ROADMAP Goal line for Phase 9 is not in user-story form. No story was invented.

<objective>
Expansion of the maintenance tracer (plan 09-06): a database lease so two runs never overlap, a per-job try and catch so one bad job never hides the others, and a time budget so long work continues on the next call.

Purpose: JOB-01 "short, leased, idempotent jobs ... nothing relies on long-running in-memory state" on a 256 MB app pool that can recycle at any time.
Output: `IMaintenanceRunLock` and its database adapter, `MaintenanceErrors`, the runner's lease, isolation and budget, batched purges and their tests.

Split note (revision 2026-10-31, plan budget): this was Task 2 of the original plan 09-06.

Phase goal (ROADMAP, verbatim): "Staff can attach, arrange and view order photos, including straight from a phone camera. The photos load fast and stay private per the OD-9 ruling. Storage cleanup and token purges run as short, reliable, scheduled jobs."
</objective>
