# Plan 09-02: Named sizes and delivery addresses

*Created: 2026-10-31T18:00:00-05:00 · Updated: 2026-10-31T11:52:00-05:00*

> MVP note: the ROADMAP Goal line for Phase 9 is not in user-story form. No story was invented.

<objective>
Build the pure code that turns a stored photo (public id, width, height) into ready addresses for each display slot, using only the 13 named sizes that strict transformations will allow, and the Cloudinary settings with the guard that keeps development and live photos in their own folders.

Purpose: IMG-04 "nothing larger than its display size" and D-03 "only the named sizes" are decided here once; the client never assembles a Cloudinary address (UI-SPEC server work 1). Plans 09-07 and 09-13 wire this into the order answers and the orders list; plan 09-25 creates the same 13 sizes in the account.
Output: `IImageDelivery`, `ImageSource`/`PhotoUrls`/`CoverUrls`, `ImageNamedSizes`, `CloudinaryImageDelivery`, `CloudinarySettings` and their tests. No DI registration in this plan.

Phase goal (ROADMAP, verbatim): "Staff can attach, arrange and view order photos, including straight from a phone camera. The photos load fast and stay private per the OD-9 ruling. Storage cleanup and token purges run as short, reliable, scheduled jobs."
</objective>
