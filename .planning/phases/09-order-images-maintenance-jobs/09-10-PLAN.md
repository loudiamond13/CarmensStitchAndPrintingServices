# Plan 09-10: Every photo type the shop uses is recognized; everything else is refused

*Created: 2026-10-31T18:00:00-05:00 · Updated: 2026-10-31T11:52:00-05:00*

> MVP note: the ROADMAP Goal line for Phase 9 is not in user-story form. No story was invented.

<objective>
Extend the server's byte-level sniffer from JPEG to PNG, WebP and HEIC with exact size reading, and make it refuse look-alikes (AVIF, animated WebP, SVG, GIF) and hostile bytes safely.

Purpose: IMG-02 "validated by magic bytes (JPEG/PNG/WebP/HEIC) ... SVG is rejected" (CWE-434) for every type staff upload from phones and computers; the upright HEIC size feeds IMG-03's stored dimensions.
Output: `ImageSniffer` for four kinds, more synthetic fixtures, unit and endpoint tests. The handler is unchanged: it already calls `ImageInspection`.

Phase goal (ROADMAP, verbatim): "Staff can attach, arrange and view order photos, including straight from a phone camera. The photos load fast and stay private per the OD-9 ruling. Storage cleanup and token purges run as short, reliable, scheduled jobs."
</objective>

<feature>
  <name>Byte-level type and size detection for JPEG, PNG, WebP and HEIC</name>
  <files>src/Csps.Application/Images/ImageSniffer.cs, src/Csps.Application/Images/ImageFacts.cs, tests/Csps.Testing/Images/SyntheticImages.cs, tests/Csps.Application.UnitTests/Images/ImageSnifferTests.cs, tests/Csps.Server.IntegrationTests/Orders/OrderImageTypesTests.cs</files>
  <behavior>
    - PNG 800 x 600 -> Png 800 x 600; WebP VP8 1024 x 768, VP8L 300 x 200 and VP8X 4000 x 3000 -> WebP with those sizes; HEIC ispe 4032 x 3024 -> Heic 4032 x 3024; with irot 1 (90 degrees) -> 3024 x 4032.
    - ftyp brands [mif1, heic] -> Heic; [mif1, avif] -> refused; [avif] -> refused; [msf1, hevc] -> Heic.
    - VP8X with the animation bit, or an ANIM chunk -> refused.
    - SVG text, GIF89a, BM, II*\0 (TIFF), empty input, 7 bytes of PNG signature -> refused.
    - A HEIC box with size 0 or a size past the end, a meta box nesting deeper than the cap, more boxes than the cap, a PNG chunk length past the end -> refused, no exception, in under 50 ms each.
    - 2,000 seeded pseudo-random inputs of 0 to 4,096 bytes never throw.
  </behavior>
  <implementation>One static class with a bounded reader over `ReadOnlySpan<byte>`; each format in its own private method; an explicit iteration cap for segments, chunks and boxes; ISOBMFF parsing reads ftyp, meta (full box), pitm, iinf only as far as needed, iprp/ipco/ipma to find the primary item's ispe and irot. Never allocate per box; never recurse without a depth cap.</implementation>
</feature>
