<feature>
  <name>Expired-record purges with safe margins</name>
  <files>src/Csps.Infrastructure/Maintenance/PurgeExpiredRecordsJob.cs, tests/Csps.Infrastructure.IntegrationTests/Maintenance/PurgeExpiredRecordsJobTests.cs</files>
  <behavior>
    - Each rule: one row exactly at its cut-off stays, one row one second older is removed, a fresh row stays; the line counts only removed rows.
    - A removed session takes its refresh tokens; a live session keeps its consumed refresh tokens.
    - A removed challenge takes its codes.
    - An unsent outbox row created 90 days ago stays; a row sent 31 days ago goes; a row failed 29 days ago stays.
    - 1,100 expired sessions are removed in three batches; with the budget spent after the first batch the job reports More.
    - A purge that throws a database failure gives a failed line for that rule and the next rule still runs.
  </behavior>
  <implementation>One private batched-delete helper reused by every rule (Where cut-off, OrderBy the cut-off column, Take 500, ExecuteDeleteAsync, loop while full and not spent); rule order: request keys, locks, sessions, challenges, account links, outbox.</implementation>
</feature>
