# Plan 09-05: The photo limit, the closed-order lock and the size rules hold at the endpoint

*Created: 2026-10-31T11:52:00-05:00 · Updated: 2026-10-31T11:52:00-05:00*

> MVP note: the ROADMAP Goal line for Phase 9 is not in user-story form. No story was invented.

<objective>
Expansion of the upload tracer (plan 09-01): every refusal the server owes is proven at the endpoint, before anything reaches storage. The size rules arrive through `ImageInspection`, the database guard is checked row by row, two racing uploads never make a sixth photo, and an architecture test pins that uploads never touch disk.

Purpose: D-08 (5 photos, domain plus database), D-11 (closed orders), D-34 (25 megapixels, 10,000 px), IMG-02 (magic bytes, 10 MB, never on local disk) and IMG-01 (nothing sent to Cloudinary for a refused upload).
Output: `ImageInspection`, the size messages, the handler step, `MultipartBodies`, `ImageInspectionTests`, `OrderImageSchemaTests`, `UploadNoDiskTests` and the endpoint refusal tests.

Split note (revision 2026-10-31, plan budget): this was Task 2 of the original plan 09-01.

Phase goal (ROADMAP, verbatim): "Staff can attach, arrange and view order photos, including straight from a phone camera. The photos load fast and stay private per the OD-9 ruling. Storage cleanup and token purges run as short, reliable, scheduled jobs."
</objective>
