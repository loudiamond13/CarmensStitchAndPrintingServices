# Plan 11-15: Visitors' Products data comes from six database product lines, ready on day one

*Created: 2026-11-11T18:30:00-06:00 · Updated: 2026-11-11T18:30:00-06:00*

> MVP note: the ROADMAP Goal line for Phase 11 is not in user-story form. No story was invented.

<objective>
The product line model on the server (D-01, CONT-02) and its public read (PUB-02): the `ProductLines` and `ProductLinePhotos` tables, the `ProductTypes.ProductLineId` link column (D-09), the six seeded lines shown with no prices (D-06, D-40), and `GET /api/v1/public/product-lines` with the /products boot block. Plan 11-17 adds the Manager's writes, 11-19 the photos, 11-21 the Home card data, 11-26 the gallery flag.

**D-06 mechanism (stated as CONTEXT asks):** a hand-written `migrationBuilder.InsertData` in the `AddProductLines` migration's Up, with fixed literal Guids and the UI-SPEC §7 text. Production gets the six rows exactly once through the reviewed idempotent script (`dotnet ef migrations script --idempotent`); nothing seeds or migrates at startup, the dev seed's `CSPS_Dev`/`CSPS_E2E` guard is untouched, and because the rows are not model HasData, no later deploy can overwrite a Manager's edits (RESEARCH Pattern 8, A9). The owner reviews the script before applying it, as for every deploy.

Purpose: the Products and Home pages have real lines from the first deploy, and a Manager adds prices before cutover.
Output: entities, configurations, migration with seed, public read, boot data, tests, matrix row, contract and docs.
</objective>
