## Spacing Scale

Declared values. All are multiples of 4 and are the spec `--space-*` tokens (spec §3.4). With `--spacing: 4px`, `p-4` = 16px.

| Token | Value | Usage in Phase 4 |
|-------|-------|------------------|
| xs (`--space-1`) | 4px | `.s-back` icon gap; OtpInput gap at page width ≤ 420px |
| sm (`--space-2`) | 8px | Header block gap (eyebrow / h1 / subline); `.s-note` gap; `.s-check` gap; OtpInput gap above 420px |
| (`--space-3`) | 12px | `.s-banner` gap and vertical padding; `.s-note` padding; `.s-login-row` gap |
| md (`--space-4`) | 16px | `.s-banner` horizontal padding; phone form-column and brand-panel side padding |
| (`--space-5`) | 20px | **Card gap** between every block of an auth card (`.s-login-card`: gap 20) |
| lg (`--space-6`) | 24px | Tablet form-column side padding; phone brand-panel top and bottom padding |
| xl (`--space-8`) | 32px | Phone form-column top and bottom padding |
| 2xl (`--space-12`) | 48px | Brand-panel padding and form-column vertical padding at ≥ 768px; the outlined "C" left offset |

**Control heights:** inputs and md buttons 44px, lg buttons 52px, OtpInput boxes 44px tall and 44–56px wide (P2). With OQ-5 applied, every small link and the checkbox label on the auth screens has a 44px-tall target: an invisible `::before` box fixed at 44px tall (`before:h-11`, the control height, not a spacing step), vertically centred on the element (`before:top-1/2 before:-translate-y-1/2`) and as wide as the element. Being a fixed height, it reaches 44px for the 20px links and the ~18px `.s-back` links alike, and it draws nothing.

**Standard set** for anything Phase 4 lays out itself: 4, 8, 16, 24, 32, 48 (and 64, unused here).

**Declared exceptions (inherited, justified):**

| Value | Token | Where | Why it is allowed |
|---|---|---|---|
| 12px | `--space-3` | `.s-banner` gap and vertical padding, `.s-note` padding, `.s-login-row` gap | These are the approved App. C / App. E.5 values. The look-equality proof (P2, D-33) checks S1 against App. E.5 to 0.01 px, so swapping to 8 or 16 would fail parity and change an owner-approved look. P2 already lists `--space-3` as a token step. |
| 20px | `--space-5` | The auth card gap (`.s-login-card` `gap: var(--space-5)`) | This is the approved App. C value, pinned by the S1 parity scenarios like the 12px row. P2 already lists `--space-5` as a token step. |

The 20px checkbox and the 13px `.s-back` text are element sizes from App. C (P2 O-8), not spacing. No other non-standard value may be introduced. A new SPEC-GAP block (Note slot, notice, banner slot) sits in the card's existing 20px gap and adds no spacing of its own. S7 adds no spacing of its own either: its page header, body and list table use the P2 `.s-ph`, `.s-body` and ResponsiveTable recipes unchanged (their values are the P2-approved token steps), and the only-this-device Note sits in the `.s-body` gap.

| `/admin/sessions` | S7 Signed-in devices (D-43) | SPEC-GAP, inside the admin shell (not AuthLayout) | Behind the admin guard like every admin page. Both roles; each user sees only their own sessions. Not a sidebar or tab-bar item: it is reached from the UserMenu, so no nav item is current on this page. |
| `/admin/*` (all other admin routes) | Admin shell | P2 | The layout `loader` calls `ensureSession()`. On failure it does `throw redirect('/admin/login?returnUrl=…')` (a loader redirect, never `<Navigate>`). While the first `ensureSession()` runs, the existing `ShellFallback` (an empty Blush page root) shows, so nothing shifts. |

**Return path (D-07).** `returnUrl` is accepted only when it is a same-origin relative path that starts with `/admin` and is not `/admin/login…`. Absolute URLs, `//`, backslashes and encoded forms of these are rejected. Anything else lands on `/admin`. The return path never carries a token or code.

### S7 Signed-in devices — `/admin/sessions` (SPEC-GAP, D-43, D-44)

An ordinary admin-shell page (`AdminLayout`, the user's D-13 theme, both Blush and Espresso), **not** AuthLayout. It is built only from P2 looks: the `.s-ph` page header, the `.s-body` body and ResponsiveTable. Document title "Signed-in Devices · CSPS Admin".

**Page header (`.s-ph` look, spec §8.1):**
- Left: `h1` "Signed-in devices" (`.s-ph-title h1` look) and the 14px muted subline.
- Right (`.s-ph-actions`): `Button` **secondary** md with `icon="log-out"` "Sign Out Other Devices". It opens SignOutOthersDialog and is always enabled (D-44). It is secondary because this page has no primary action; the one-primary rule (spec §3.1) is kept. On phones it takes the full width, as the spec's page-header actions do.

**Device list (`ResponsiveTable`, P2):**
- `caption` (visually hidden): "Signed-in devices". `things`: "signed-in devices". A real `<table>` with column headers, so screen readers get table semantics on every width; on phones the same rows render as stacked cards with each cell's `data-label` (spec §8.4).
- Columns, in order:

  | Column | Header | Cell |
  |---|---|---|
  | 1 (lead) | "Device" | The device label in the lead-cell look, e.g. "Chrome on Android". The current row also shows `Badge tone="info"` "This device" after the label. |
  | 2 | "Signed in" | Absolute business time, e.g. "Oct 12, 2026, 3:42 PM", in `<time dateTime="{UTC ISO}">`. |
  | 3 | "Last active" | Relative-or-absolute text (rules below) in `<time dateTime="{UTC ISO}">`. The current row reads "Active now". |
  | 4 | "Session" | `Badge tone="neutral"` "Keep me signed in" for a 90-day session; the plain muted text "Until browser closes" for a browser-close session. |
  | 5 (actions) | visually hidden "Actions" | Other rows: `RowActions` > `RowAction icon="log-out"` with `title="Sign out"` and the accessible name "Sign out {device}, signed in {Signed in}". The current row's actions cell is empty: no button, because Logout covers this device. |

- **Order:** the current session first, then the others by Last active, newest first. The server returns only the caller's active (unrevoked, unexpired) families, capped at 100 (SEC-03). There is no pagination, search or filter.
- **Device label:** the server's D-32 coarse summary ("{Browser} on {Device}"), at most 60 characters. An unknown agent reads "Unknown browser". The label wraps inside its cell (`wrap-anywhere`), and a long label never widens the page. Two rows with the same label tell themselves apart by their "Signed in" time, which is also in each button's accessible name.
- **"Last active" rules** (business zone Asia/Manila, en-PH; computed when the data is rendered, refetched on window focus):
  - the current row: "Active now"
  - under 1 minute: "Just now"
  - under 60 minutes: "{n} min ago"
  - under 24 hours: "{n} hr ago"
  - otherwise the absolute "Oct 12, 2026, 3:42 PM"

  "Last active" moves on each token refresh, so it can lag by up to the 15-minute access-token life. The subline says activity is approximate.

**States:**
- **Loading** (first load): ResponsiveTable `pending` → SkeletonTable inside the LoadingRegion, announcing "Loading signed-in devices…" → "Signed-in devices loaded." The page header and its button render at once.
- **Error:** ResponsiveTable `failed` with `onRetry` → ErrorState "Couldn't load signed-in devices." / the P2 reassurance line + "Try Again". The traceId reference shows when present. A non-load failure (5xx, network) uses the shared mapper copy.
- **Only this device:** the table shows the single current row, and below it a `Note icon="shield-check"` with the "only this device" copy. The header button stays enabled (D-44).
- **Populated:** current row first, then the others.
- **Refetching** (after a sign-out, or on window focus): the P2 rule — previous rows stay, dimmed by colour only after 200 ms, with no layout shift.

**Per-row sign-out (with a confirm):**
- Pressing a row's `log-out` action opens **SignOutDeviceDialog**, focused on the dismiss button "Keep Signed In". **Why a confirm:** the row icons are 36px and sit close together on phones; a mistaken tap would sign out the wrong device (for example the shop's shared tablet) and force a password-and-code sign-in there. That matches §8.9, where row actions with consequences confirm.
- Primary `log-out` "Sign Out Device", pending "Signing out" (WEB-09). While pending, Esc, the scrim and "Keep Signed In" are ignored.
- **Success:** the dialog closes, the row is removed (the list refetches), a success toast appears, and focus moves to (1) the sign-out button of the row that took the removed row's place, else (2) the previous row's sign-out button, else (3) the page `h1` (`tabIndex={-1}`), which happens when only this device is left. The toast (`role="status"`) announces the result.
- **Already gone** (the server says the session no longer exists, e.g. it expired or was signed out elsewhere): the same as success, but the toast is the "already signed out" info toast.
- **Failure:** the dialog stays open with the mapper line above the buttons (`role="alert"`). "Sign Out Device" becomes clickable again and takes focus (the P2 ConfirmDialog failure rule).
- The current session can't be signed out from this page. The UI never offers it, and the server refuses it (D-43).

**Responsive:** desktop is a table; tablet is the table with its in-wrapper scroll (min-width 680); phones show stacked cards with the device label as the card title, the badges under it, the three data rows labelled "Signed in", "Last active" and "Session", and the row action in the card's top-right corner (spec §8.4). No horizontal page scroll from 320 to 1920px.
