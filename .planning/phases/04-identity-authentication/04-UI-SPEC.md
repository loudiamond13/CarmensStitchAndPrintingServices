# Phase 4 — UI Design Contract

*Created: 2026-10-14T08:10:00-05:00 · Updated: 2026-10-14T08:10:00-05:00*

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**What this file is.** This is the phase-scoped contract for the Phase 4 sign-in, code, password and session screens, the user-menu session items, and the auth emails. It creates **no new design system, token, colour, font size or weight**. `CSPS-UI-SPEC.md` (spec v1.1, "the spec") stays the visual source of truth, with its precedence (Appendix › tables › prose). `02-UI-SPEC.md` (approved 2026-10-08) stays binding for everything it defines: the Tailwind contract (D-33), the look-equality proof, the recipes, the SPEC-GAP primitives and the interaction contract. This file only adds what Phase 4 needs on top.

Section references such as "§8.2" and "App. E.5" point into `CSPS-UI-SPEC.md`. References such as "D-01" point into `04-CONTEXT.md`. "P2 …" points into `02-UI-SPEC.md`.

## Typography

The spec §3.3 scale stays binding and unchanged. Under the P2 rule, **a new SPEC-GAP element never sets its own size, weight or line height.** Its type comes from the recipe of the spec look it reuses, or else from Body or Label below.

| Role | Size | Weight | Line Height | Where in Phase 4 |
|------|------|--------|-------------|------------------|
| Body | 16px | 400 | 24px (1.5) | Page root text; email field and OtpInput digits (field recipe, also prevents iOS zoom) |
| Label | 14px | 600 | 20px (1.43) | Field labels, the OtpInput legend, the strength label (12px/600 from the recipe) |
| Heading | 44px (36px on phones ≤ 767) | 800, UPPERCASE | 1.0 | Every auth `h1`, `.s-login-card h1` look (App. C) |
| Display | 40px | 800, UPPERCASE | 1.0 | The brand-panel quote (App. E.5; hidden on phones) |

**Weights.** New Phase 4 elements declare only **400 and 600**. Every other weight shown comes from a reused recipe and is not declared by the element: 650 (buttons, `.s-link`), 700 (eyebrow, `.s-banner strong`), 800 (`h1`, quote, outlined "C" 800 italic).

**Reused type looks (not new values):** body-sm `.s-small` 14/20/400 for sublines; `.s-note` 13/18; `.s-back` 13px/600; `.s-link` 14px/650; eyebrow 14/1.15/700 with .16em tracking.

**Casing (spec §3.3):** `h1` and eyebrow render UPPERCASE through the recipe; the source text is sentence case ("Check your email"). Buttons and menu items are Title Case ("Verify Code", "Sign Out Other Devices"). Sublines, labels, hints, errors, notices and toasts are sentence case.

### Routes

The route paths below are proposed. CONTEXT leaves route names to the planner, except `/admin/login` and `/admin/login/verify` (D-01). The token links are built from configuration, never from `Request.Host` (RESEARCH Pattern 8).

| Route | Screen | Look source | Guard behaviour |
|-------|--------|-------------|-----------------|
| `/admin/login` | S1 Sign in | **App. E.5** (approved) | With a live session, it redirects to `/admin` |
| `/admin/login/verify` | S2 Check your email (code step) | SPEC-GAP (D-01) | With a live session, it redirects to `/admin`. It renders without an in-memory step, so refresh works (D-01). |
| `/admin/login/new-password` | S3 Set a new password (must-change gate, D-13/D-18) | SPEC-GAP | Reached only from S2. Opened directly with no pending gate, the first save fails and redirects to S1 with the "timed out" notice. |
| `/admin/forgot-password` | S4 Reset your password (request) | SPEC-GAP | Anonymous |
| `/admin/reset-password#token=…` | S5 Set a new password (from the email link) | SPEC-GAP | Anonymous. The token is read from `location.hash` and removed at once with `history.replaceState` (RESEARCH Pattern 8). |
| `/admin/accept-invite#token=…` | S6 Set your password (invite, D-29) | SPEC-GAP | Anonymous. Same fragment handling as S5. |
| `/admin/*` (all other admin routes) | Admin shell | P2 | The layout `loader` calls `ensureSession()`. On failure it does `throw redirect('/admin/login?returnUrl=…')` (a loader redirect, never `<Navigate>`). While the first `ensureSession()` runs, the existing `ShellFallback` (an empty Blush page root) shows, so nothing shifts. |

**Return path (D-07).** `returnUrl` is accepted only when it is a same-origin relative path that starts with `/admin` and is not `/admin/login…`. Absolute URLs, `//`, backslashes and encoded forms of these are rejected. Anything else lands on `/admin`. The return path never carries a token or code.

## Screen Contracts

Every screen is an `AuthLayout` card. The blocks are listed top to bottom with the card's 20px gap between them. Copy keys refer to § Copywriting.

### S1 Sign in — `/admin/login` (App. E.5, with the deviations listed)

1. AuthHeader: eyebrow, `h1` "Sign in", subline (verbatim).
2. **Notice slot** (SPEC-GAP): at most one `Note live` from a one-shot notice (below). It is removed on the next submit.
3. **Error slot:** `ErrorState align="start"` with `role="alert"`: the generic credential error (verbatim App. E.5) or the shared-mapper copy for 429, network and 5xx. **It is never the "This account is deactivated." banner** (D-02, SPEC-DEVIATION).
4. `Field` "Email": `type="email"`, `autoComplete="username"`, `inputMode="email"`, `autoCapitalize="none"`, `spellCheck={false}`, required. **Never pre-filled or remembered** (D-09): no default value, no storage.
5. `PasswordField` "Password": `autoComplete="current-password"`, required, **no strength meter and no password-rule check** (legacy and temporary passwords must still be accepted).
6. Row (`.s-login-row` look): `Checkbox` "Keep me signed in", **unchecked by default** (D-03, SPEC-DEVIATION), and the `UiLink` "Forgot password?" (`.s-link.s-small` look) → `/admin/forgot-password` (D-16; SPEC-DEVIATION from the App. E.5 info toast).
7. `Button` primary lg block, `iconRight="arrow-right"`, "Sign In". Pending: "Signing in" (verbatim), with the spinner and `aria-disabled` per WEB-09.
8. `Note icon="shield-check"`: the staff-only line (verbatim).
9. `.s-back` link with `chevron-left` "Back to the CSPS website" → `/`.

**Outcomes:**
- correct password → S2
- generic failure (unknown email, wrong password, locked or deactivated, all the same, D-02) → the error banner, values kept, focus per OQ-1
- validation error → field errors and `focusFirstInvalid` (P2)

### S2 Check your email — `/admin/login/verify` (SPEC-GAP, D-01)

1. AuthHeader: `h1` "Check your email", subline with `{email}`. `{email}` is the address typed on S1, held **only in the session module's memory** (no URL, storage or history state). After a refresh, the subline uses the "your email" fallback.
2. Notice slot: the "new code sent" note after a resend (`Note live icon="circle-check"`).
3. Error slot: `ErrorState align="start"` for the resend cap (D-10), the cross-ticket lock and the shared mapper (429, network, 5xx).
4. `OtpInput`: legend "Sign-in code", the S2 hint, required. The first box has `autocomplete="one-time-code"`. Paste works. **Never auto-submits** (D-01): `onComplete` doesn't submit. Code errors show under the group and mark every box invalid.
5. `Button` primary lg block, `iconRight="arrow-right"`, "Verify Code". Pending: "Verifying".
6. `Button` secondary md block, "Resend Code". During the 60s cooldown it is `aria-disabled="true"` and its label reads "Resend code in 0:42" (`m:ss`, ticking each second). After the cap (D-10) it stays `aria-disabled`, reads "Resend Code" and gives no wait time.
7. `Note icon="shield-check"`: the "never share" line.
8. `.s-back` link (`chevron-left`) "Use a different account" → `/admin/login`. The next sign-in replaces the pending ticket.

**Outcomes:**
- correct code → `returnUrl` or `/admin`, or S3 when the must-change flag is set (D-13, D-22)
- wrong code → all six boxes cleared, the error under the group, focus on box 1
- dead or expired code → the matching error, Resend still available
- ticket gone (expired or missing) → S1 with the "timed out" notice

**Countdown announcements (W-4):** one visually hidden `role="status" aria-live="polite"` node. It speaks only when a send starts the cooldown ("We sent a new code. You can ask for another in 60 seconds.") and when the cooldown ends ("You can ask for a new code now."). The ticking button label is not in a live region. After a page refresh the cooldown isn't known, so Resend starts enabled. A send the server refuses within the 60s window gets the shared 429 copy.

### S3 Set a new password — `/admin/login/new-password` (SPEC-GAP, D-13, D-18, D-22)

1. AuthHeader: `h1` "Set a new password". The subline has two variants, chosen by the reason the server returns: **temporary** (D-21/D-22) or **breach** (D-18, verbatim).
2. Error slot: `ErrorState align="start"` for the shared mapper.
3. A hidden username input for password managers: `<input type="email" autoComplete="username" value={email} hidden readOnly>`, only when `{email}` is in memory.
4. `PasswordField` "New password": `autoComplete="new-password"`, `showStrength`, `hint` = the password rule hint, required.
5. `PasswordField` "Confirm new password": `autoComplete="new-password"`, required.
6. `Button` primary lg block, `iconRight="arrow-right"`, "Save Password". Pending: "Saving".
7. `.s-back` link "Use a different account" → `/admin/login`, which abandons the gate. **No session exists until a valid password is saved** (D-13).

**Outcome:** the save issues the session → `returnUrl` or `/admin`, with the success toast "Password saved". Server field errors go under their fields, and focus moves to the first one.

### S4 Reset your password — `/admin/forgot-password` (SPEC-GAP, D-16, AUTH-08)

**Form state:**
1. AuthHeader: `h1` "Reset your password", subline.
2. Error slot (shared mapper only: 429, network, 5xx).
3. `Field` "Email": `type="email"`, `autoComplete="username"`, required.
4. `Button` primary lg block, `iconRight="arrow-right"`, "Send Reset Link". Pending: "Sending". The `Idempotency-Key` is reused on retry (SEC-06, D-40).
5. `.s-back` link "Back to sign in" → `/admin/login`.

**Sent state** (same route, the card content swaps; shown **for every outcome**, so nothing reveals whether the account exists, AUTH-08):
1. AuthHeader: `h1` "Check your email" (focus moves to it), subline with `{email}`.
2. `Note icon="info"` with the spam hint.
3. `Button` secondary md block "Use a Different Email" → back to the form state with the email cleared and focus on the Email field.
4. `.s-back` link "Back to sign in".

### S5 Set a new password from the email link — `/admin/reset-password#token=…` (SPEC-GAP, AUTH-08/09)

- **Checking state:** the card shows the AuthHeader `h1` "Set a new password" and a `LoadingRegion` with `SkeletonText`, announcing "Checking your link…". The token check returns the account email or "invalid".
- **Form state:**
  - subline with `{email}`
  - the hidden username input with `{email}`
  - "New password" (meter and rule hint) and "Confirm new password", as S3
  - primary lg block "Save Password", pending "Saving"
  - `.s-back` "Back to sign in"
- **Invalid state** (expired, used, revoked, missing or malformed token; one state for all, with no detail):
  - `h1` "This link has expired" (focus moves to it), body copy
  - `ButtonLink` primary lg block "Request a New Link" → `/admin/forgot-password`
  - `.s-back` "Back to sign in"
- **Outcome:** save → `/admin/login` with the "password changed" notice (D-17; no auto sign-in). All sessions are revoked server-side (D-19).

### S6 Set your password from an invite — `/admin/accept-invite#token=…` (SPEC-GAP, D-29)
