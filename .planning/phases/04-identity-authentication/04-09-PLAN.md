## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → SMTP server | Credentials and messages cross the network |
| outbox table → anyone with database access | Codes and links at rest |
| user data → email HTML | Names and emails are inserted into HTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-26 | Information Disclosure | Outbox content at rest (codes in subjects, links in bodies) | high | mitigate | Subject, text and HTML each Data-Protection-encrypted (certificate-protected key ring); wiped after send, failure or expiry |
| T-04-27 | Information Disclosure | SMTP without TLS or with a bypassed certificate check (CWE-319/295) | high | mitigate | Only StartTls or SslOnConnect are representable; no certificate callback; options validated at start |
| T-04-28 | Tampering | HTML injection in the code email (CWE-79 in mail) and Host-header link poisoning (CWE-644, IN-06) | medium | mitigate | Every value HTML-encoded; links only from App:PublicBaseUrl, tokens in the fragment; the other six kinds are T-04-108 in plan 04-33 |
| T-04-29 | Information Disclosure | Real mail from tests (D-27) | medium | mitigate | The Testing transport is the Debug-only sink and Release refuses the Testing environment; log hygiene for the outbox path is T-04-109 in plan 04-33 |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No installs in this plan |
