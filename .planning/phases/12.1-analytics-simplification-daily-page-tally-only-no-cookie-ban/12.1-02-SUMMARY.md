# Phase 12.1 Plan 02: Site-wide page view limit Summary

**One site-wide sliding-window limit (600 a minute, `RateLimits:AnalyticsCeiling`) on the page view route only, chained before the per-address limit through the built-in global limiter, plus shared analytics test helpers moved out of the consent tests.**

## Performance

- **Duration:** about 25 min
- **Started:** 2026-11-18T18:50:00-06:00
- **Completed:** 2026-11-18T19:20:00-06:00
- **Tasks:** 3 (1 tracer, 2 auto, all TDD)
- **Files modified:** 11 (1 created, 10 modified)

## Accomplishments

- A script that rotates addresses can no longer flood the page view route: past 600 calls a minute across all callers, the next call answers 429 with the shared problem body (`code: rate-limited`) and a Retry-After. The per-address limit of 120 a minute is unchanged.
- The ceiling touches only the route named `RecordPageView`. A public read from another address still answers 200 after the ceiling is hit.
- The setting is validated at start-up. A bad limit or window stops the host with a message that names the key and never the value.
- Test hosts are never throttled by it: `CspsApiFactory` 100000, `RealLimitsFactory` the real 600, Playwright and the owner review host their no-throttle value.
- `AnalyticsHttp` holds the shared helpers, so plan 12.1-09 can delete `ConsentEndpointTests.cs` without breaking the rate limit or clear tests.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Wrong metadata type for the endpoint name**
- **Found during:** Task 1 GREEN
- **Issue:** The first version read `EndpointNameMetadata`. A controller `[EndpointName]` attribute adds the attribute itself, which implements `IEndpointNameMetadata`, so no endpoint matched and the fourth page view still answered 204.
- **Fix:** Read `IEndpointNameMetadata`.
- **Files modified:** `src/Csps.Server/Security/RateLimitingRegistration.cs`
- **Verification:** the target test went green.
- **Committed in:** `6873cfba`

**2. [Rule 1 - Bug] The no-limit partition reused the sliding-window key**
- **Found during:** Task 1 GREEN, caught by `TheCeilingLeavesOtherRoutesAlone`
- **Issue:** `PartitionedRateLimiter.Create` keeps the first limiter built for a key. Once a page view created the sliding window under `analytics-site`, every other request that asked for a no-limit partition under the same key got that sliding window, so the public read answered 429.
- **Fix:** The no-limit partition has its own key (`no-site-wide-limit`).
- **Files modified:** `src/Csps.Server/Security/RateLimitingRegistration.cs`
- **Verification:** all 65 rate limit tests passed.
- **Committed in:** `6873cfba`

**3. [Rule 3 - Blocking] No web dependencies in the worktree**
- **Found during:** Task 2
- **Issue:** The fresh worktree had no `web/node_modules`, and installing is not allowed here.
- **Fix:** Linked the main checkout's `web/node_modules` into the worktree as a directory junction (git ignores it, nothing is committed). No package was installed, added or bumped. The junction stays in the worktree and is removed with it.
- **Verification:** vitest and eslint ran.

**4. [Plan wording] Default test added with GREEN, not RED**
- The third Task 1 test names `AnalyticsCeilingRateLimit`, which would not compile in RED. It was added in the GREEN commit.
