# Phase 12.1 Plan 01: Path-only beacon and no speed reader Summary

**Every public page view is now counted at once with only its path (no cookie wait, no referrer), and the web-vitals speed reader is deleted and uninstalled.**

## Performance

- **Duration:** about 45 min (including a one-time `npm ci` for the worktree)
- **Tasks:** 2 (Task 1 tracer, Task 2 auto), both TDD
- **Files changed:** 16 (3 deleted, 1 created)

## Accomplishments

- `createBeaconMachine(send)` now has one member, `view(path)`. It ignores a repeat of the last path, sends `{ path }` and drops a failed send. The consent store, referrer reader, `visibilitychange` listener, held body and keepalive branch are gone. `usePageViewBeacon(pathname)` keeps the admin and dev skip and the lazy service import.
- `PageViewBody` holds `path` only and `pageView` takes no options. `VitalsBody` and `vitals` are gone.
- `useSpeedReport`, its test and `speedReport.ts` are deleted and `PublicLayout` no longer calls the reader.
- `web-vitals` 6.2.3 is uninstalled. The `web/package-lock.json` diff is 8 deletions: the top-level dependency line and the `node_modules/web-vitals` block, nothing else. `web/package.json` loses one line.
- `docs/dependencies.json`: the `web-vitals` package entry is removed and a 2026-11-18 owner approvals row records D-59. The 2026-11-15 row stays as history. `docs/dependencies.md` marks the Phase 12 web-vitals section removed (history kept) and drops web-vitals from the browser package list; only the updated timestamp changed. `web/THIRD-PARTY-NOTICES.txt` regenerated (only the web-vitals Apache block went, 207 lines).
- New gate `web/src/test/no-consent.node.test.ts` (three tests: no speed reader file, no web-vitals import, no web-vitals package in manifest or lockfile).
