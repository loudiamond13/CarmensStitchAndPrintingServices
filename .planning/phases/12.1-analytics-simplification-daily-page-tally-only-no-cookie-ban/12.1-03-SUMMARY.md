# Phase 12.1 Plan 03: The monthly cleanup stops rolling up visits and still ages out every analytics table Summary

**The analytics cleanup job no longer rolls visits into device and source totals, purges old raw rows by date alone, and reports its daily line as "Old daily page counts removed".**

## Performance

- **Duration:** about 15 min
- **Tasks:** 2 (both TDD)
- **Files modified:** 3

## Accomplishments

- Removed the roll-up rule, `RollUpAsync`, `RollDayAsync`, the cursor read and write, `CursorFormat`, `RolledUpLabel` and the `IMaintenanceCursors` constructor parameter from `AnalyticsRetentionJob`. The job has four rules now: raw visits, cookie choices, daily counts, address salts.
- `PurgeRawVisitsAsync` uses `AnalyticsRetention.RawCut(today)` directly (vital samples, then page views, then visits), so old rows go even when no cursor row exists (Pitfall 1, threat T-12.1-06).
- Daily line wording follows D-77: label "Old daily page counts removed", failure text "The old daily page counts could not be removed."
- Job name `analytics-retention` and order 15 are unchanged, so the GitHub Actions maintenance call needs no change. The old cursor row is left alone.
- No migration, no entity change, no inline SQL (EF `ExecuteDeleteAsync` only), no trigger, no package change.
