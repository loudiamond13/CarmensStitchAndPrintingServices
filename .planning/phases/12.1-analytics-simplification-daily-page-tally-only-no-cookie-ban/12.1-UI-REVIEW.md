## Top 3 Priority Fixes

1. **Privacy Policy still says the map loads "only after you tap Show Map"** (`web/src/modules/public/legalPrivacy.ts:71`, and the matching line near 114 named in UAT test 1). Since D-65 a returning browser loads the map by itself, so the page contradicts the behavior. Fix: use the owner's wording from UAT test 1(a), for example "after your first tap, this browser loads the map by itself until you clear the saved setting." The "Who else handles it" Google line (about line 112) says the same thing and needs the same change.
2. **"These two settings are not cookies" does not match the list** (`legalPrivacy.ts:185`). UAT says three saved keys exist. Drop the count ("These settings are not cookies"), then re-check the list is complete. Wrong counts in a legal page are a trust and legal risk.
3. **Page is still DRAFT and the owner's yes (D-73) is pending** (`legalPages.ts:30`, `approved: false`). Visitors would see a DRAFT notice and the page stays out of the sitemap. Settle UAT tests 1 and 2, then flip `approved` in the four places listed in 12.1-VERIFICATION.md. Also fix the busy message "from this address" on the site-wide limit (UAT test 1(c)); I found no matching string in `web/src`, so that fix is server side.

Minor fixes (not top 3):
4. `visitorKpiRowClasses` is a 3-column grid (2 on tablet) that holds one card (`visitorStats.recipe.ts`). The Page views card takes a third of the row on desktop. Use one column, or let the card span.
5. `visitorStatsListRowClasses` is a 2-column grid holding one list (`VisitorStatsPage.tsx`). The "Most viewed pages" card fills half the width and the other half is empty. Use a single column, or put the list beside the chart.
6. Pick one name per control: the `ranges` copy has "Last 30 days" and "This month", but the date picker must reach back 3 years (D-70) and the error copy says "from Nov 15, 2023". Confirm that floor is computed, not fixed (it is passed as a parameter, so likely fine).

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- Banner and consent copy is gone. Search of `web/src` (non-test files) for "cookie settings", "cookie bar", "/cookies", "vitals", "unique visitors", "circle-x" found nothing. The only cookie words left are the intended Privacy Policy section (`legalPrivacy.ts:142`, `:217`).
- Visitor Stats copy (`visitorStatsCopy.ts`) matches D-57, D-67 and D-70: "Page views", "Most viewed pages", hint "The top 5. Export CSV for every page." No unique visitors, no "Not available". No em or en dash found in any non-test `web/src` file (OR-4 clean).
- Empty state ("No page views in these dates") is plain and gives a next step.
- WARNING: `legalPrivacy.ts:71` is outdated against D-65 (see fix 1).
- WARNING: `legalPrivacy.ts:185` count is wrong (see fix 2).
- WARNING: the DRAFT notice is correct per D-71 but is a ship gate.
- MapCard note "The map loads from Google when you tap Show Map." stays by D-66. Acceptable, but it hides after the first tap, so a returning visitor gets no notice that Google is loading. D-66 allows this.

### Pillar 2: Visuals (3/4)
- Focal point is clear on Visitor Stats: head, toolbar, KPI card, chart, list.
- The chart is hand-rolled SVG and reused as ruled (D-68: no Day or Month switch; the card subline says "Per day" or "Per month").
- MapCard keeps the 16:10 box so the frame causes no layout shift, and the frame has a title (`MapCard.tsx`). The map pin SVG has `role="img"` with a label and the pin icon is `aria-hidden`.
- WARNING: single-item grids (fixes 4 and 5) leave the page looking like a leftover from a bigger layout.
- No orphan banner, consent modal or footer button components remain. The footer is now three Legal links (`SiteFooter.tsx` plus test).

### Pillar 3: Color (3/4)
- Bar fill uses the token `bg-chart-expense` for page views (`statBarFillClasses`). Using the "expense" chart color for a visitor count is a naming mismatch, though it is a token and not hardcoded. WARNING (low).
- Loading dimming uses color tokens only (`text-ink-subtle`, `bg-surface-2`), matching D-02 (no opacity on text).
- No hex or `rgb(` found in the files I read. The map drawing uses Blush tokens.

### Pillar 4: Typography (3/4)
- Page title, subline and card titles use shared recipes.
- `visitorStats.recipe.ts` sets `text-[14px]` and `text-[24px]` as arbitrary sizes in three places. They match spec values but bypass the scale. WARNING (low).

### Pillar 5: Spacing (3/4)
- Gaps use 4-point steps (`gap-2`, `gap-3`, `gap-4`, `gap-6`, `p-4`, `p-5`). Phone overrides exist for 320 px.
- Leftover grid shapes for one card (fixes 4 and 5).

### Pillar 6: Experience Design (3/4)
- States covered in `VisitorStatsPage.tsx`: loading region with `aria-busy`, skeletons, first-read ErrorState with retry, stale-refresh alert with Try Again, empty state, export pending and failure toasts, custom range validation with the server's words.
- Route guard keeps Admin out (Manager only), as D-23 requires.
- `mapChoice.ts` guards every storage call, so blocked storage only means the tap is not remembered. MapCard moves focus into the frame only after a real tap, not on auto-load. Good.
- WARNING: there is no on-page way to undo the saved map setting (D-65 allows this; the Privacy Policy must explain how to clear it). Confirm the "Saved map setting" entry says how, and fix the wording gaps above.
- Backend leftovers were out of scope, but `RetiredCookiesMiddleware.cs` is listed in VERIFICATION as covered, which matches D-63.
