## Detailed Findings

### Pillar 1: Copywriting (4/4)
- Map wording is now true to D-65 in both places (`legalPrivacy.ts:71`, `:108`). The saved-setting entry (`:202`, `:209`) explains the tap and Global Privacy Control in plain words.
- Search of non-test `web/src` for em and en dashes found none (OR-4 clean).
- Consent, banner and vitals copy is gone. The only cookie words are the intended Privacy Policy sections.

### Pillar 2: Visuals (3/4)
- Focal point is clear on Visitor Stats: head, toolbar, one KPI card, chart, list.
- WARNING (low): the one-column KPI row relies on phone-only overrides (`visitorStats.recipe.ts:24`) that I could not see rendered.
- Map frame keeps its 16:10 box, so no layout shift.

### Pillar 3: Color (4/4)
- Bar fill uses `bg-chart-views` (`visitorStats.recipe.ts:43`), defined in `ui/app.css:233` and `ui/base.css:44,94`.
- The only hex values are the token definitions in `ui/base.css`, which is the right place.

### Pillar 4: Typography (4/4)
- Named sizes only in the recipe. No `text-[` arbitrary sizes in `VisitorStatsPage.tsx` or `MapCard.tsx`.

### Pillar 5: Spacing (3/4)
- 4-point steps throughout; no arbitrary `p-[`, `gap-[` found in the audited page and card.
- WARNING (low): `grid-cols-[minmax(0,1fr)]` at `visitorStats.recipe.ts:24` is a bracket value (fix 3).

### Pillar 6: Experience Design (3/4)
- Loading with `aria-busy`, error with retry, stale refresh alert, empty state, export states and range validation all remain in `VisitorStatsPage.tsx`.
- Map storage failures are guarded in `mapChoice.ts`; focus moves only after a real tap.
- WARNING (low): focus order and touch target size (44 px) were checked in code only, not in a browser (fix 1).
