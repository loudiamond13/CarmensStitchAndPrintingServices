# Phase 12.1 Plan 07: Retired cookie expiry Summary

**A small middleware after the static files expires the old `__Secure-csps_vid` and `__Host-csps_consent` cookies, with their exact set-time attributes, on the first answer to any browser that still sends them.**

## Performance

- **Duration:** about 20 min
- **Tasks:** 2 (1 tracer, 1 auto), both TDD
- **Files modified:** 4 (2 created, 2 modified)

## Accomplishments

- `RetiredCookiesMiddleware` reads the request cookies once, and only when the browser sent a retired cookie does it register one `OnStarting` callback that calls `Response.Cookies.Delete` with the set-time options. Visitor id: path `/api/v1/analytics`, secure, samesite strict, httponly. Consent: path `/`, secure, samesite lax, not httponly. Neither has a domain.
- It is registered in `Program.cs` right after `UseStaticFiles` and before `UseRouting`, so hashed assets never carry a Set-Cookie, while the shell, the API and a 403 page view answer do.
- The sign-in, two-step and staff marker cookies are never touched.
- Seven integration tests and one e2e case (run in all five browser projects) prove it.
