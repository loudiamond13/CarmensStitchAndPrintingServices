# Phase 12.1 Plan 11: A page view only adds to the day's page count, and the visit stores and helpers are gone

**The one anonymous analytics write route now only increments the daily page count, whatever cookies the browser sends, and about 2,400 lines of visit, salt, consent record, visitor key and consent cookie code and tests are deleted with two reflection gates that keep them gone.**

## Performance

- **Duration:** about 75 min (10 min of it the full Server project run)
- **Tasks:** 3 (1 tracer, 2 auto), all TDD
- **Files changed:** 35 (1 created, 13 modified, 21 deleted; the DeviceClass.cs to DeviceKind.cs move shows as a delete plus an add)

## Accomplishments

- `CollectPageViewHandler` lost `RecordVisitAsync`, `NewVisit` and its visit store parameter. `CollectContext` is `(UserAgent, IsStaff)` and `PageViewRequest` is `(Path)`. The controller reads only the User-Agent and the staff check, with the GPC constants and the links options parameter gone.
- The server cannot write a consent or visitor id cookie any more: `SetConsent`, `SetVisitor`, `ExpireVisitor` and `IsVisitorId` are deleted from `AnalyticsCookies`. The two name constants and `CookiePath` stay for `RetiredCookiesMiddleware`, and the staff marker members are untouched.
- The three ports (`IAnalyticsVisits`, `IAnalyticsSalts`, `IConsentRecords`), four adapters, `VisitorKey`, `IdentifiedCollection`, `SqlErrors.ForeignKeyViolation`, `ConsentCookie`, `DeviceClass`, `OsFamily`, `AnalyticsRetention.SessionMinutes` and `ConsentLifetimeMonths`, the consent cookie fixture and their tests are gone. Tables, entities, enums and configurations stay.
- `AnalyticsSurfaceTests` now has three cases: the old removed-route types, the visitor identity types, and the consent cookie and device helpers.
- OpenAPI snapshot and `web/src/types/api.generated.ts` were regenerated in the same commit as the request change (`referrerHost` is gone from `PageViewRequest`).

**1. [Rule 3 - Blocking] IdentifiedCollection.cs deleted in Task 1, not Task 2**
- **Found during:** Task 1 build.
- **Issue:** `IdentifiedCollection` reads `CollectContext.Gpc`, `VisitorToken` and `ConsentCookie`, which Task 1 removes from the record, so the build failed (CS1061). Its only caller was the handler's visit half, also removed in Task 1.
- **Fix:** `git rm` the file in the Task 1 commit. The `HasNoVisitorIdentityType` list still names it, so it stays gated.
- **Commit:** `fb6964b4`.

**2. [Rule 2 - Missing critical] Added DeviceKindTests.cs**
- **Found during:** Task 3.
- **Issue:** The plan deletes `DeviceClassTests.cs`, but it held the only test that pins the stored numbers of the `DeviceKind` enum (1 to 4). The kept tables still hold those numbers (D-56), so losing the pin would let a reorder go unnoticed.
- **Fix:** A 1-test `DeviceKindTests.cs` with that case.
- **Commit:** `0a87897b`.

**3. Visit-half cases in PageViewCollectTests removed**
- The plan says "reshape" the file. The 17 cases (theory rows counted) for the visit, the GPC signal, the 30-minute session, the source name and the address hash tested behavior this plan removes, so they were deleted with their helpers (`ConsentValue`, `ConsentedCookieAsync`, `PostWithCookieAsync`, `WithRemoteIp`). The old-cookie case builds its Cookie header by hand, so `ConsentCookie` is no longer used anywhere in tests.
