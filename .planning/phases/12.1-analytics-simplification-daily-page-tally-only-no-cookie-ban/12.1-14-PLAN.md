# Plan 12.1-14: Visitor Stats reads only the daily page counts and answers page views, the top 5 pages and the trend

*Created: 2026-11-18T18:28:27-06:00 · Updated: 2026-11-18T18:28:27-06:00*

> MVP note: the ROADMAP Goal line for Phase 12.1 is not in user-story form. No story was invented.
> Spec-less probe fallback skipped: the phase has no requirement IDs to probe (visible skip, recorded here). Traceability keys are the owner rulings (D-IDs).
> Revision (checker scope warning): the server slice of the old plan 12.1-10. The web slice is plan 12.1-08, which already shaped the browser's `VisitorStats` and the page; this plan changes the server answer, the parser's input, the speed helpers, the Testing seed and the browser journeys. It runs after plan 12.1-11 because both regenerate the API types.

<objective>
The server half of D-57, D-67, D-68 and D-70: the Visitor Stats answer and reader shrink to total page views, the top 5 pages with shares, and a per day or per month trend, all from `DailyPageCounts`; the cut date, unique visitors, visits, sources, devices and page speed leave the answer, and the Domain helpers only they used go. The Testing seed writes page counts only, and the e2e journeys check the page on seeded data. The CSV changes in plan 12.1-15.

Requirement this plan reduces: ANL-08 (the dashboard is page views, top pages and the trend; the range stays in the URL, WEB-10). The rewording is done by plan 12.1-17.

Purpose: the server computes exactly the few numbers that are kept (Core Value), and nothing reads the unused tables.
Output: the reshaped server answer and reader, regenerated types, the parser on the new answer, the page-count-only Testing seed and e2e journeys.
</objective>
