# Phase 12.1 Plan 15: Export CSV gives one row per day per page, with the page's name

**The export is now `Date,Page,Page views`, one line per day and page that had views with the page's plain name, built from the daily page counts only; one shared fixture keeps the server and web page names equal, and the cookies page key is gone from the code.**

## Performance

- **Duration:** about 85 min (the whole Server project run took most of the wait)
- **Tasks:** 2 (Task 1 tracer, Task 2 auto), both TDD
- **Commits:** 4 (2 RED, 2 GREEN)

## Accomplishments

- `VisitorStatsCsv` writes the three-column file; the writer refuses a page text that does not start with a letter or holds a comma, quote, CR or LF (CWE-1236) and a negative count.
- `PageNames` (Application) holds the eight names in route order and `NameFor`, which falls back to the key, plus `OrderOf` for the sort.
- `IVisitorStatsReader.ReadDailyPagesAsync` reads `DailyPageCounts` with EF LINQ, views above 0 only. `ReadDailyAsync`, `DailyCount` and the visit-based figures behind the old CSV are deleted. No entity, configuration or migration changed.
- `ExportVisitorStatsHandler` drops the cut and the zero fill, names each key, and orders by date, then page order, then unknown keys by key.
- The OpenAPI snapshot and `api.generated.ts` were regenerated (only the endpoint description changed).
- `PageKeys.Cookies`, the cookies entry in the Testing seed's known pages and the cookies entry in `VISITOR_STATS_COPY.pages` are deleted. The seed now refuses `cookies` as an unknown page.
- The web export saves the file under the server's own name and accepts the header-only file.

## Deviations from Plan

**1. [Rule 1 - Bug] The web export would have broken on the new file**
- **Found during:** Task 1 (reading plan 14's open items)
- **Issue:** `visitorStatsService.exportCsv` checked the old four-column header and took the file name from the first and last day row. With the new file the header check refuses every export, and a header-only file (a range with no views, which the plan requires) has no day to name the file from. The plan's file list does not include the web service.
- **Fix:** the service reads the file name from the server's `Content-Disposition` through a short-lived response interceptor, accepts only the exact `visitor-stats-{from}-to-{to}.csv` shape, checks the new header and each row's shape, and accepts the header-only file. The saved name is therefore always the server's name, also for a preset range.
- **Files modified:** `web/src/modules/admin/services/visitorStatsService.ts`, its test, `VisitorStatsPage.test.tsx` (the fake export now sends the header), `httpClient.test.ts` and `downloadCsv.test.ts` (sample text only).
