## Executor rules (owner, binding)

- Claude never merges, pushes to main, deploys or starts the live audit. Merges go only through `tools/scripts/Merge-PullRequest.ps1` on the owner's word (D-08 of Phase 3). Claude may read run results and alerts with `gh` and may dispatch `zap.yml` (the CI scan of CI's own container) only on the owner's instruction.
- Commits on the pull request branch happen only before the merge. Anything recorded after the merge goes on a follow-up branch the owner names and reaches main through the same merge process.
- Decisions are the owner's: a High or Medium ZAP alert, a Lighthouse shortfall the owner's PC run confirms, or a failed certificate check stops and goes to the owner. In away mode, park each in the backlog with the run id and the finding.
- Not done means not complete: while Task 2 waits for the owner (merge, deploy, live audit), or is parked in away mode, write no 14-27-SUMMARY.md. A parked or partial run never stands in for the release, so plans 14-28 and 14-29 cannot start on it.
- Never read stdin; leave no background shell. No secret, token, host name or account id is written into any file or the SUMMARY (run ids and scores only).
- Commits: `gitleaks protect --staged --no-banner`. Stage by path. Messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
