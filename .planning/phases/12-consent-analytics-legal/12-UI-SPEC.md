# Phase 12: UI Design Contract (Consent, Analytics and Legal)

*Created: 2026-11-15T21:07:00-06:00 · Updated: 2026-11-15T21:30:00-06:00*

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Owner conventions apply to everything below** (`.claude/CLAUDE.md` Conventions): admin parts import from `@/components`; public parts import from each component's own module file, never an area barrel (PERF-01); module code lives in `web/src/modules/public/` and `web/src/modules/admin/` (`pages/`, `components/`, `hooks/`, `services/`, plus module-root copy and schema files); no em dash or en dash in any client string, `aria-label`, `title`, `<title>` or meta text (OR-4); a missing value renders `EmptyValue`, never a dash; every form has a zod schema that mirrors its API validator with the server's own messages (OR-3); API calls live in per-module services and only `core/api/http` touches `fetch` (OR-5); the owner layout tree (OR-6); no `style` attribute or inline script anywhere (strict CSP; React `style` only for the P2 custom-property rows). **Every count, share, rating and date bucket on the stats page comes from the server.** The client formats only.

**What this file is.** The phase-scoped contract for the **cookie consent bar** (CB1), the **Cookie Settings window** with "Clear my cookies & data" (CS1, CS2), the **consent-aware map card** (M1), the **footer legal row** (FT), the **four legal pages** (L1 template, L2 to L5), and the Manager-only **Visitor Stats page** (V1). This file only adds what Phase 12 needs. Every new screen is a spec gap (C-17) and each file carries `// SPEC-GAP: <name>`.

### Design choices made under Claude's discretion (CONTEXT) or as SPEC-GAP defaults, for the owner's UI review

- Legal routes `/privacy`, `/cookies`, `/terms`, `/accessibility`; footer order Privacy, Cookie, Terms, Accessibility, then Cookie Settings, in a row of its own in both footers.
- The DRAFT box sits above the breadcrumbs; the version and date line always sits under the title, so it stays when the box comes off. Drafts are version 0.1; the first approved text is 1.0.
- While a legal page is DRAFT it carries `noindex` and stays out of `sitemap.xml`, so search engines don't list unapproved text; both change with the approval.
- In the bar, the order is Cookie Settings, Reject All, Accept All; on phones Reject All and Accept All share the first row and Cookie Settings takes the row under them.
- Accept All and Reject All are both outline buttons, so neither choice looks stronger.
- The "Necessary" row has an "Always on" badge instead of a locked checkbox.
- A failed send of a cookie choice is retried on the next page view without an error message to the visitor; the choice applies at once in the browser.
- Top pages are always one of the site's own pages or "Page not found"; any other address is never stored, so odd or spam addresses can't fill the list.
- Unique visitors and visits count only visitors who allowed visitor stats; page views count everyone (with consent and the anonymous counts). The hints say so.
- The trend chart shows page views as bars and unique visitors as a line; it is per day up to 62 days and per month for longer ranges; the CSV is always per day.
- Page speed shows the 75th percentile (Google's own method) with the sample count.
- A CSV cell that is not available (over 13 months) is left empty, not 0, so totals in a spreadsheet stay honest.
- The Visitor Stats menu item sits after Site Content.
