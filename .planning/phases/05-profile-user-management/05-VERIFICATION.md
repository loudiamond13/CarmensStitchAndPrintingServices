### CR-01 confirmation (the one blocker)

- `SignOutOthersDialog.tsx` builds `useSubmission<undefined, undefined>` and its `onSuccess` never resets it.
- `useSubmission.ts:204-210`: `serialize(undefined)` is the fixed `NO_DATA`; after a success `lastRef` holds `{serialized: NO_DATA, success}`, and the next `submit()` takes `same && last.success !== undefined` and returns `Promise.resolve(last.success)` without calling `send`. The file header (lines 17-18) documents this as intended behaviour for double-clicks.
- Mounting: `AdminLayout.tsx:226` renders `<SignOutOthersDialog open={signOutOthersOpen} .../>` permanently; `SessionsPage.tsx:147` does the same. `git log -S"signOutOthersOpen &&"` shows the earlier conditional render from Phase 4 (566e86c) was replaced in Phase 5 plan 05-08 (1af77d9), so the hook state used to be discarded on each close and now is not. This is a Phase 5 regression of a control the user relies on after losing a device.
- `SignOutOthersDialog.test.tsx` has no second-confirm case (the review's reading holds: only "opens again without the failure line").
- Effect: first use works; every later use closes nothing, sends nothing, toasts nothing. Not covered by any Phase 5 requirement ID, but AUTH-06 ("sign out of all devices from their profile") is marked complete and is now broken on its second use.
