## Layout Contract

### L1 Full-bleed, sticky admin shell (D-01..D-05)

```
html, body, #root                                  no fixed height; nothing clips overflow
<div page root>                                    @container/pg, bg-bg, min-h-dvh  (public, auth and admin alike, D-01)
  <SkipLink/>
  <div .s-admin>                                   flex row, min-h-dvh
    <div data-ui="s-admin-side">                   the column itself is bg-nav-bg, full height of the row (no strip, D-01)
      <Sidebar>                                    position: sticky; top: 0; height: 100dvh; flex column (D-02)
        top: Logo + collapse toggle                fixed
        <nav aria-label="Admin">                   flex-1, min-h-0, overflow-y: auto, overscroll-contain (D-03)
        footer: user chip + Logout                 pinned at the bottom, never scrolled away (D-03)
    <div data-ui="s-admin-main">                   flex column, min-w-0
      <Topbar/>                                    sticky top-0, z 20 (D-02, D-04 phones)
      <main id="main" .s-body>                     the document scrolls; only this area moves
      <nav .s-tabbar>                              phones only, sticky bottom (unchanged)
  <MobileNavDrawer/> <ToastProvider/>              unchanged (D-04)
```

- **D-01 full bleed:** every page root (`pageRootClasses`, `authPageRootClasses`, the admin shell) is at least the dynamic viewport tall (`min-h-dvh`), so a short page shows no band of another colour below the shell at any width. Fix it once in the shared recipes, not per page.
- **D-02 sticky:** on tablet (72px rail) and desktop (248px or collapsed 72px), the sidebar stays in view at any scroll depth, and the topbar stays pinned. The document keeps the native scroll (so the skip link, `main` focus, browser find and the phone address bar behave normally). The build mechanism (sticky vs a fixed-height grid with an inner scroll area) is the planner's choice (CONTEXT discretion), but **no ancestor of the sidebar or topbar may get `overflow: hidden`**, which would break `position: sticky`.
- **D-03 short screens:** when the viewport is shorter than the logo, all nav items and the footer together (a small laptop, or browser zoom), the nav list scrolls inside the pinned sidebar; the logo stays at the top and the user chip and Logout stay at the bottom. The nav list is a focusable named region only if it actually scrolls (axe `scrollable-region-focusable`).
- **D-04 phones:** the slide-out drawer is unchanged; the topbar with the menu button is pinned.
- **D-05 no sideways scroll:** nothing in the shell may make the document wider than the viewport from 320 to 1920px. Wide content (tables, showcase frames) scrolls inside its own frame. Do not hide overflow on `html` or `body` to mask a wide child; fix the child.
- **Focus order is unchanged:** skip link, sidebar, topbar, `main`, tab bar. The skip link still lands on `main`.
- **Theme:** the profile Appearance tab and the topbar toggle change the same state (`localStorage['csps-theme']`, P2 D-13). The shell exposes the current theme and its setter to pages (outlet context or a small context); both controls always agree.

**URL params (WEB-10, allow-list parsers):** `role` ∈ {`admin`, `manager`}; `status` ∈ {`active`, `inactive`, `locked`}; `q` trimmed, capped at 100; `page` ≥ 1; `size` ∈ {10, 20, 50, 100}, default 20; `tab` ∈ {`details`, `security`, `appearance`}, default `details`; `range` ∈ {`last-7-days` (default), `last-30-days`, `this-month`, `last-month`, `all`, `custom`}; `from`, `to` via `parseAsBusinessDate`, read only when `range=custom`; `actor` and `target` are user ids (GUID shape, never an email, AUDIT-02) or the literal `system` for `actor`; `action` is one of the action keys in § Copywriting → Audit action labels.
