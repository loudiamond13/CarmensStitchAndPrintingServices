# Phase quick-261114-t04 Plan 01: Fix Phase 11 UI review warnings N-01 and N-02 Summary

The Contact bar height and the footer tagline width are named theme tokens (`--spacing-contact-bar` 77px, `--spacing-tagline` 320px), the footer and the Contact scroll padding read the bar token, the breadcrumb label lives in `PUBLIC_COPY.crumbs.label`, and `public-look.node.test.ts` gates all of it. Nothing looks different.

## What changed

- **N-02, footer (a5a6cb5e):** both footer variants share one `footerShellClasses` class. Its phone bottom padding is `max(var(--space-24), calc(var(--spacing-contact-bar) + env(safe-area-inset-bottom)))`: 96px today (the safe area is 0, owner ruling D-P11-BL-61), and never less than the bar plus the safe area.
- **N-02, scroll padding and tagline (1c0bdba6):** the Contact page's phone scroll padding reads `var(--spacing-contact-bar)`. The tagline uses `max-w-tagline`.
- **N-01 (83594c4c):** `PageHead` reads the nav's `aria-label` from `PUBLIC_COPY.crumbs.label` (`'Breadcrumb'`, same spoken name).
- **Review (9eb417e1):** `11-UI-REVIEW.md` has an Outcomes table with N-01 and N-02 as Fixed, and the Top Priority items 1 and 3 point to it. Only `updated:` changed in the frontmatter.

## Gates added (public-look.node.test.ts)

- A: `--spacing-contact-bar` equals 1 + 4 x `pt-N` + 4 x `h-N` + the `pb-[calc(Npx+...)]` px, read from the bar recipes.
- B: no bare px padding or margin in the public module.
- C: one shared footer clearance class; it compiles to the max() expression, with the token at 77px and `--space-24` at 96px.
- D: no hand-typed 77px in an arbitrary value in the public module or `PublicLayout.tsx`.
- E: `--spacing-tagline` is 320px, no px max width in the footer, `max-w-tagline` compiles to `var(--spacing-tagline)`.
- F: no string-literal `aria-label` in public TSX.
