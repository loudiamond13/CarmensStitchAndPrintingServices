- **How the idempotent script treats a non-transactional step (EF Core 10):** each migration gets its own `BEGIN TRANSACTION;` and `COMMIT;` (pinned by `MigrationScriptTests.IdempotentScriptWrapsEachMigrationInItsOwnTransaction`, which counts both against the number of migrations). A `migrationBuilder.Sql(..., suppressTransaction: true)` command is written outside the transaction, wrapped in the migration-history guard `IF NOT EXISTS (SELECT * FROM [__EFMigrationsHistory] WHERE [MigrationId] = N'...') BEGIN ... END;` and followed by `GO`; the history row insert then follows in its own `BEGIN TRANSACTION; ... COMMIT;` batch. So in SSMS an error in the ALTER batch does not stop the next batch, and the history row can be written while the setting stays off. The inner value guard makes re-running that one batch safe. The Task 1 script test proves the real layout; Task 3 documents what it shows.

- **Pooled connections and ROLLBACK IMMEDIATE:** the ALTER ends every other session on the database being migrated, and only that database (never another `CSPS_Test_`, `CSPS_Dev` or any `BetsLLC_*` database). A test that keeps an idle pooled connection to a test database, migrates it past the new migration on another connection, and then reuses the pool can get a transport-level error. So the new tests read the setting from `master` by name. If an existing test hits this in the full run, the fix is in that test: `SqlConnection.ClearPool(new SqlConnection(<that database's connection string>))` right after its migrate step (`CspsDatabase.DisposeAsync` line 246 already clears pools before a drop). Never drop ROLLBACK IMMEDIATE: without it the ALTER waits forever behind idle pooled connections.
