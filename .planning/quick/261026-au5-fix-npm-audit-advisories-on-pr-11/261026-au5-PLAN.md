## Facts the planner confirmed (do not re-derive)

- `web/.npmrc` sets `min-release-age=14`. A CLI `--before=<date>` overrides it for that one command (npm 11.19 config: cli beats project). `min-release-age-exclude` would also exempt a package from `--before`, so do NOT add exclusion lines for undici or fast-uri: a plain `npm update undici` without a cutoff would pick the unapproved 8.12.3. `npm ci` installs from the lockfile and does not apply the release-age filter, so web/.npmrc needs no change.
- `tests/Csps.ArchitectureTests/PackagePins.cs` reads `overrides` as pins, and a package listed twice at the same version (a dependency that is also an override, like axe-core) is one pin. So `"zod": "4.6.7"` in both dependencies and overrides is one pin, web:zod 4.6.7, and needs no test change (D-65). npm allows an override of a direct dependency only when both use the exact same spec, so both must read "4.6.7"; a different spec gives EOVERRIDE.
- chromium-bidi 17.0.2 is written against zod 3: its `parseObject` (out/Default/gen/src/protocol-parser/protocol-parser.js) reads `parseResult.error.errors`, which zod 4 does not have. A planner preview on zod 4.6.5 showed: module load OK, BidiMapper import OK, a valid `BrowsingContext.parseNavigateParams` call returns the input, but an INVALID command throws `TypeError: Cannot read properties of undefined (reading 'map')` instead of chromium-bidi's InvalidArgumentException. The orchestrator note that chromium-bidi already calls zod 4 APIs (z.config, z.pipe) was not confirmed: neither appears in its output. puppeteer-core loads chromium-bidi only through a dynamic import when WebDriver BiDi is requested (lib/puppeteer/node/BrowserLauncher.js); Lighthouse uses CDP and never loads it. The owner accepted this risk (D-65); record it in the SUMMARY and docs/dependencies.md.
- Known upstream issues, not new with these versions: zod 4.6 bare `z.any()`/`z.unknown()` object-field regression (planner grep: no use in web/src outside tests); vitest jsdom FormData file bytes dropped (web/src only passes FormData through core/api/http/httpClient.ts; nothing uploads files yet).
- `docs/dependencies.json` is checked against the pins by `DependencyRegistryTests`; `coolDown` must be `aged` (adopted at least 14 days after published, by date) or `accepted: <reason>`. Approvals are free text and not validated.
- `web/THIRD-PARTY-NOTICES.txt` lists zod@4.6.5 and fast-uri@3.1.8 today (both ship to the browser), so `notices:check` fails until it is regenerated.
