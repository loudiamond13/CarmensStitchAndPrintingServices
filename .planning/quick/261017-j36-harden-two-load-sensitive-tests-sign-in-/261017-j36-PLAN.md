<objective>
Harden two tests that pass alone but fail under full-suite load, without weakening what they prove.

1. `SignInTimingTests.EveryBranchTakesAtLeastTheFloorAndTheMediansAgree` failed in the 2026-10-17 full solution run: success median 863 ms against an overall median of 518 ms (unknown 518, wrong 524, deactivated 511, min 501, max 3454). Alone, every branch is floor-bound (last isolated run: medians 504 to 510 ms, max 552 ms).
2. `eslint-config.node.test.ts` case "resolves no rule at warn level for src/components/x.tsx" timed out at 5000 ms (7796 ms) in a full `vitest run`, and passes alone (15/15).

**Planner analysis (cause, from the code; Task 1 confirms it with numbers):** `SignInHandler.HandleAsync` waits `ResponseFloor.WaitAsync(started, 500 ms)` after the branch's work, so a response takes max(work, floor). The floor hides branch differences only while every branch's work stays under 500 ms. The success branch does the most work: on top of the one hash that every branch does, `StartChallengeAsync` runs a second transaction. It looks up and resets the failed count, invalidates open challenges, renders the code email (with a business-calendar lookup), makes three Data Protection `Protect` calls in `OutboxEmailSender.EnqueueAsync`, inserts the challenge, outbox and audit rows, and commits, inside `ConflictRetry`. In `dotnet test --solution`, Csps.Server.IntegrationTests (34 database classes, run in parallel in one process) and Csps.Infrastructure.IntegrationTests (20 database classes, another process) all create, migrate and use `CSPS_Test_*` databases on the single `(localdb)\MSSQLLocalDB` engine. Meanwhile Csps.ArchitectureTests runs a self-contained `dotnet publish` and a Release build. Every database round trip and continuation then queues, and the branch with the most of them (success) runs past the floor, while the 401 branches still fit under it. The first measured success call also pays one-time costs the single unknown-email warm-up never touches.

**Fix direction (no weakening):** the 04-12 must-have says "the median of each branch is within 20% of the others", success included, so the fix keeps the floor, the 8 rounds, the 0.2 tolerance and all four branches. It removes the load instead: the class runs in a non-parallel xunit collection, and every branch is warmed once before sampling. The ESLint test gets one shared ESLint instance with memoized config resolution, plus a realistic per-test budget that follows the existing `FULL_PAGE` precedent in `web/src/dev/ComponentShowcase.test.tsx`.

TDD note: this is a test-only change with no production behavior to drive, so no new RED unit test. The RED evidence is the recorded 2026-10-17 failures, reproduced in Task 1 step 3 where load allows. GREEN is two consecutive clean full runs (Task 3). Tracer-first does not apply: these are two independent test-file fixes with no layers to slice.

Purpose: full runs (local and the owner's merge gate) stop failing on load noise, so a red timing test again means a real CWE-204 regression.
Output: two hardened test files, plus a SUMMARY with the cause analysis, probe numbers and four full-run results.
</objective>
