<objective>
Close code-review finding WR-04 from Phase 1, test-first. `DevSeedTargetGuard` checks only the database name. Its MSSQLLocalDB block is a substring check that a named-pipe alias bypasses, and it has no server allow-list, so `tools/Csps.DevSeed --reset` (which reaches `EnsureDeletedAsync`) would drop a database named CSPS_Dev or CSPS_E2E on any server, including the SmarterASP.NET host. Replace the substring check with a data-source allow-list checked before the database name. Keep the AttachDBFilename refusal and the name check exactly as they are.

Owner decision (2026-10-07, UAT/secure-phase): fix WR-04 now, test-first, before Phase 1 closes. WR-02 (IpPrefix 6to4/NAT64) stays deferred. Do not touch `src/Csps.Domain/Auditing/IpPrefix.cs` or its tests. Its only change is the disposition record in Task 3.

Planner decisions (discretion, record them in the SUMMARY):
- **Allow-list (a stricter equivalent of the review's suggestion).** After trimming, a data source is allowed only if it is (a) exactly `(localdb)\CSPS`, compared OrdinalIgnoreCase (the instance named by `DevSeedOptions.DefaultConnectionString` and `SqlServerInstance.LocalDbMasterConnectionString`), or (b) exactly `<host>,<port>`, where host is `127.0.0.1` or `localhost` (OrdinalIgnoreCase) and port is a plain ASCII decimal 1–65535 with no sign or whitespace. Form (b) is what Testcontainers' `MsSqlContainer.GetConnectionString()` produces for `SqlServerInstance` when `CSPS_TEST_SQL=container` (`Server=127.0.0.1,<mapped port>`, or `localhost` when the Docker endpoint is tcp://localhost). It also covers the existing `localhost,1433` test case.
- **What the allow-list refuses, beyond the review's sample.** The review's sample allowed `.` and port-less `localhost`/`127.0.0.1`. These are refused, because they reach whatever default SQL Server instance is installed on the machine, not the container. Named instances (`host\instance`), every protocol prefix (`np:`, `tcp:`, `lpc:`, `admin:`), `(local)`, `::1`, other loopback addresses and every other host are refused too. Only the canonical prefix-free forms the repo already uses are accepted.
- **The guard stays pure.** It never reads `CSPS_TEST_SQL` or any other environment variable. The loopback rule is safe without that, because LocalDB has no TCP listener (so a loopback TCP address cannot reach MSSQLLocalDB), and the name check still limits writes to CSPS_Dev and CSPS_E2E, a prefix this project owns.
- **Failover Partner.** `Failover Partner` names a second server that SqlClient may connect to, so an allow-list on Data Source alone is bypassable. Any non-empty FailoverPartner is refused (Task 2).
- **CLI checks use unreachable targets.** End-to-end CLI refusals use `sql1234.site4now.invalid` (RFC 2606 `.invalid`, which never resolves) and a fake pipe `LOCALDB#00000000`, so even a broken guard cannot reach a real server. The realistic `sql1234.site4now.net` string appears only in pure unit tests, which never open a connection. Never run the CLI against `(localdb)\MSSQLLocalDB`, any `BetsLLC_*` database or any real remote host, not even to prove a refusal.

Purpose: the dev seed's "touch only CSPS_Dev or CSPS_E2E on our own servers" promise (FND-04, T-01-13, CLAUDE.md shared-machine rules) becomes true, so `--reset` can never drop a hosted or shared-instance database.
Output: the hardened guard with new tests, accurate docs, and an updated Phase 1 review disposition.
</objective>
