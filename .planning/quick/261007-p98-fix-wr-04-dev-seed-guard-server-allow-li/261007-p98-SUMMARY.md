# Quick 261007-p98: Dev-seed guard server allow-list (WR-04) Summary

The dev-seed guard now accepts only the `(localdb)\CSPS` instance or a loopback container written as `127.0.0.1,<port>` or `localhost,<port>`, and it refuses any Failover Partner. A `--reset` against a hosted, shared-instance or named-pipe target therefore exits 2 before anything connects. Both changes were made test-first, with RED evidence validated by the checker.

## What changed

- **`DevSeedTargetGuard.Check`** runs its checks in this order: empty, parse, AttachDBFilename, **Failover Partner**, **server allow-list**, missing catalog, database name. The old `MSSQLLocalDB` substring check is gone (`SharedLocalDbInstance` no longer exists). `IsAllowedServer` trims the value and accepts only two forms:
  - `(localdb)\CSPS`, compared OrdinalIgnoreCase.
  - Exactly `host,port`, where host is `127.0.0.1` or `localhost` and port parses with `NumberStyles.None` / InvariantCulture to 1–65535.
- **Refusal reasons are fixed text.** Neither the server reason nor the Failover Partner reason ever repeats the data source, the partner, the user or the password. The server reason still contains "MSSQLLocalDB", so `RefusesTheSharedMssqlLocalDbInstance` passes unchanged.
- **Doc comments.** `DevSeedTargetCheck.Allowed` now names the allowed servers. The header comment in `tools/Csps.DevSeed/Program.cs` was updated, and its logic is unchanged.
- **docs/development.md:** step 5 states the server rule, the Failover Partner refusal and exit code 2. A timestamp line was added under the title.
- **01-REVIEW-DISPOSITION.md:** WR-04 is `fixed` (commits ed02c70, 9245949), WR-02 is `deferred` with the owner's reason, and `open: 16`. The YAML and the table agree.

## Planner decisions (recorded as directed)

- **The allow-list is stricter than the review's sample.** `.`, `(local)`, port-less `localhost`/`127.0.0.1`, `::1`, other loopback addresses, named instances (`host\instance`) and every protocol prefix (`np:`, `tcp:`, `lpc:`, `admin:`) are refused. Only the canonical prefix-free forms the repo already uses are accepted.
- **The guard stays pure.** It never reads `CSPS_TEST_SQL` or any other environment variable. The loopback rule is still safe: LocalDB has no TCP listener, and the name check limits writes to CSPS_Dev or CSPS_E2E.
- **Failover Partner:** any non-empty value is refused, so no second server can sit behind an allowed one.
- **The CLI checks used only unreachable targets** (`sql1234.site4now.invalid` and the fake pipe `LOCALDB#00000000`). The realistic `sql1234.site4now.net` string appears only in pure unit tests.
