# Quick 261026-m16: a list search writes q and the page reset in one URL update

A typed list search now reaches the URL as one replace that holds `q` and drops `page`, whatever order the timers fire in. The list hook times the 300 ms wait itself instead of handing it to nuqs.

## Owner rulings

- **D-68 (owner, 2026-10-26):** fix the split in a small PR, not by re-running CI. The hook does the 300 ms wait with a timer in a ref and writes `{ q, page: null }` in one nuqs update with `history: 'replace'` and no rate-limit option.
- **D-69 (owner, 2026-10-26), approved both planner design choices:**
  1. **Waiting view.** While the search waits, the list hook shows the typed search and page 1 at once (a waiting view spread over the nuqs values). Only the URL write waits 300 ms. The view equals what nuqs shows after the write, so the values and the list query key do not change at the write.
  2. **A waiting search joins the next write.** If `setFilter`, `setFilters`, `setPageSize`, `setPage` or `clampPage` runs while a search waits, its own patch and history mode stay as they were, and the waiting search is written in the same single update. `reset()` and unmount drop the waiting search.
