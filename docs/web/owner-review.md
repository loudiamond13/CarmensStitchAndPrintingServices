## 2. How to read them (for the owner)

- **The Dashboard and Orders pages are still placeholders.** Their real content is built in later phases. For those, compare the frame around the page: the side menu, the top bar, the phone tab bar, the colours, the fonts and the spacing.
- **The public home page is a placeholder too.** Compare its header and footer.
- **Wording changes for you to confirm** (before and after): right now this is your ruling D-41 R2-06, the PRD money words. "Subtotal" is the amount before discount and "Total" the amount after discount, so the order totals panel and the order card say "Subtotal" where the approved design said "Total", and the profit note reads "Profit = Subtotal − Discount − Expenses. Internal only.". The demo Orders table's "Total" column now shows the amount after discount. Only the words change. A fully discounted order with no payment still reads "Fully Paid", and the panel has no row for the Total after discount, as in the approved design. Decide: **approve the new wording, or say what to change** (for example, ask for a "Total" row after the discount).
- **The Phase 5 screens are real.** Users, My Profile and the Audit Log are the finished pages, photographed by a Manager who signed in the way a person does (email, password, the emailed code). The people in the pictures (Bea Navarro, Ana Reyes and the rest) are made for the run, with addresses under `csps.test`, in the test database `CSPS_E2E`; no mail is sent. Read "Still open for you" first: it is the only list of decisions and checks left. Say "approved" or describe what to change.
- **The Phase 6 screens are real too.** Company Expenses, Deleted Expenses and Settings are the finished pages. Read the Phase 6 rulings page first. For OQ-1 to OQ-15 the build uses the option marked "built now"; say "approved", or name the option you want. Then read the table "Words on the Phase 6 screens" next to the pictures: every sentence is there, and any you change becomes a fix. The people, categories and expenses in the pictures are made for the run in the test database `CSPS_E2E` (fake names, addresses under `csps.test`), so the month cards at the top of Company Expenses add up every expense in that database, earlier test runs included: their figures are not the shop’s. A-06-01 is ruled by you and built (D-49, plan 06-20). The SQL item is ruled (D-50); the page shows its follow-up plan. Nothing is approved for you: say so yourself.
- **The SPEC-GAP parts** (page numbers, sign-in code boxes, money boxes, tick boxes, the skip link, list states, loading placeholders, pictures, error boxes, the phone menu and the account menu) have no drawing in the design. Check that each looks like it belongs.
- **The look check table** should show "did not match: 0". The differences table lists every change from the approved design that you decided, with its decision number (for example D-27 for the Logout button).
- Write down anything that looks wrong, in your own words. Every difference you name becomes a fix. A change that would alter the approved look comes back to you as a before/after picture first (D-08).

## 3. How to make them (for developers)

Do the shared-machine preflight first (the screenshot script also runs it):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Work\dev-tools\preflight.ps1 -Ports 5180,5115,7028,5199
```

If TheBETSLLC's test processes are listed, wait. Never stop another project's process.

1. **Optional, for a fresh look-check summary:** `npm --prefix web run parity` (about 30 minutes, see [parity.md](parity.md)). The parity run writes `web/test-results/parity-results.json`; the screenshot report reads the latest one and says which filters it was run with. With no file, the report says so in plain words.
2. **Screenshots:** `npm --prefix web run review` (about 15 minutes). It:
   1. refuses unless `artifacts/owner-review` is git-ignored (`git check-ignore`);
   2. takes the shared run lock `web/.locks/e2e.lock` (E2E, Lighthouse and this run all start the host on 5199) and refuses a busy port 5199;
   3. runs the shared-machine wait (`web/scripts/shared-machine.mjs`): it runs the preflight report and waits, up to 15 minutes, while one of this project's ports is in use by another program or TheBETSLLC's dev/test processes are listed, then exits 1. It never stops anything. Without the preflight script (CI) it says so and goes on; then the guarded CSPS_E2E seed (the host's `/health` checks the database);
   4. rebuilds the e2e bundle `web/.e2e-dist` whenever any build input (`web/src`, `web/public`, the HTML entries, `vite.config.ts`, `.env.e2e`, the lockfile, the build plugins) is newer than it, not only when it is missing (L-29);
   5. starts the real host on `https://localhost:5199` for this run only, exactly as the E2E host does (the Testing environment, so the Testing-only staff fixture and the in-memory mail sink are there for the signed-in pictures), and stops only that host when the pictures are done;
   6. writes `artifacts/owner-review/shots/` (57 pages: Company Expenses, Users, My Profile, the Audit Log, Deleted Expenses and Settings signed in as a Manager), `artifacts/owner-review/spec-gap/` (54 SPEC-GAP pictures), `artifacts/owner-review/auth-review/` (150 pictures of the Phase 4 sign-in screens, devices page, dialogs, menu and toasts, at 390, 820 and 1440 px: Blush for the cards, both themes for the rest), `artifacts/owner-review/phase5-review/` (131 pictures of the Phase 5 slide-overs, dialogs and states: each case at 390, 820 and 1440 px, Blush and Espresso, the confirm-email page in Blush only, the short shell at 1280 x 600; the run signs a seeded Manager in through the staff fixture and the code in the mail sink, as `web/e2e/auth.ts` does), `artifacts/owner-review/phase6-review/` (102 pictures of the Phase 6 states: 17 cases at 390, 820 and 1440 px in Blush and Espresso; three are signed in as an Admin, the rest as a Manager; the run first makes its own people, three categories, expenses and a deleted payer in `CSPS_E2E`, all marked with the run’s tag so a search finds only them, and changes one answer on the page, fetched from the server and then edited, for the empty month, empty list and empty Deleted Expenses pictures), `artifacts/owner-review/before-after/` (6 pictures: a before and an after for each of the 3 wording cases in `BEFORE_AFTER_CASES`, Blush at 1440 px) and `index.html`. The after picture is the case frame as the app shows it; for the before picture the script writes the approved wording back into that frame's exact texts (the swaps go into the page as JSON) and photographs it again, and the run stops with the case's name if a swap matches no text, so an outdated case can never give two equal pictures. Each SPEC-GAP picture is its case frame on `/dev/components`, except the phone menu (the whole phone screen, because it covers the page) and the skip link (reached with the keyboard, because it shows only with keyboard focus, and photographed at the top left of the screen where it then appears). It never writes into `src/`, `web/src` or the server's `wwwroot`.
3. **Side by side:** `node web/scripts/design-side-by-side.mjs` (about 30 seconds, after step 2, because it reuses the step 2 screenshots of our pages). It:
   1. refuses in CI (any `CI` value), when `.planning/design` is not git-ignored, when any file under it is tracked by git, and when its own output folder is not git-ignored;
   2. opens the two design exports **in place** (never copied or moved) in Playwright Chromium with every network request blocked, picks each matching screen by its exact title, checks its width, sets its theme (the export's light/dark prop, `data-theme`) and photographs it;
   3. writes the pictures and `index.html` only under `artifacts/owner-review/side-by-side/`.

The pairings are in `PAIRINGS` (web/scripts/design-side-by-side.mjs). Our side of Company Expenses, Users and My Profile is the signed-in picture from step 2, and the report says so. The public design has no tablet screen, so the report says "The design has no screen at this width" there. A design screen can be shorter than its frame; the space below it is painted in the screen's own background colour, so it is empty space, not part of the design.

## 4. Rules

- **Never** `git add -f` anything under `artifacts/` or `.planning/design/`, and never move or copy the design files.
- The side-by-side never runs in CI: the design files are not in git (D-24, threat T-02-77).
- No package was added for these reports: they use the Playwright already installed.
- The tests are `web/scripts/owner-review.test.ts` and `web/scripts/design-side-by-side.test.ts` (the guards, the page list, the widths, the rebuild rule, the output paths and the report pages).
